Kubernetes (K8s) est un orchestrateur de conteneurs : tu déclares l'état voulu (3 réplicas de cette application), et des contrôleurs font converger l'état réel vers l'état voulu en boucle, en permanence. C'est le même esprit que Terraform, mais en continu.

Les composants

etcdControl planeBase clé-valeur distribuée : tout l'état du cluster. À sauvegarder ; nombre impair de membres
kube-schedulerControl planeChoisit le nœud d'un Pod non placé (ressources, affinités, taints)

Ce qui se passe quand tu appliques un fichier

  1. kubectl apply -f app.yaml envoie l'objet à l'API (authentification, autorisation RBAC, admission)
  2. L'objet est écrit dans etcd
  3. Le contrôleur Deployment crée un ReplicaSet, qui crée des Pods
  4. Le scheduler affecte chaque Pod à un nœud
  5. Le kubelet du nœud demande au runtime de lancer les conteneurs (images tirées du registre)
  6. Le CNI donne une IP au Pod ; les Services et le DNS rendent l'application joignable

Sondes (probes) et ressources

Les 3 sondes

  • readiness : le Pod reçoit-il du trafic ? (retiré des Services s'il échoue)
  • liveness : faut-il redémarrer le conteneur ?
  • startup : pour les démarrages longs (suspend les deux autres)

Requests et limits

  • requests : ce que le scheduler réserve pour placer le Pod
  • limits : plafond ; dépasser la mémoire = OOMKilled ; dépasser le CPU = bridé (throttling)
  • Classes de QoS : Guaranteed, Burstable, BestEffort (évincé en premier)

Cycle de vie

  • initContainers : tâches préalables, séquentielles
  • Sidecars (journalisation, proxy)
  • terminationGracePeriodSeconds + preStop pour un arrêt propre
containers: - name: app image: monapp:1.4.2 resources: requests: { cpu: 250m, memory: 256Mi } limits: { memory: 512Mi } readinessProbe: httpGet: { path: /ready, port: 8080 } periodSeconds: 5 livenessProbe: httpGet: { path: /healthz, port: 8080 } initialDelaySeconds: 15
Piège classique : une liveness trop agressive redémarre en boucle une application lente au démarrage. Utiliser une startupProbe, et ne pas faire dépendre la liveness d'une base de données externe.

Exposer du HTTP : Ingress ou Gateway API

  • Ingress : règles HTTP(S) (hôtes, chemins, TLS) appliquées par un contrôleur d'ingress (il faut en installer un)
  • Gateway API : successeur plus expressif (GatewayClass, Gateway, HTTPRoute), séparation des rôles infra / applications ; à privilégier pour les nouveaux projets
  • ingress-nginx est en fin de vie depuis mars 2026 (plus de correctifs) : privilégier Traefik, un contrôleur compatible Gateway API (Cilium, Envoy Gateway, NGINX Gateway Fabric…) selon ta plateforme
apiVersion: networking.k8s.io/v1 kind: Ingress metadata: { name: web, namespace: monapp } spec: ingressClassName: traefik tls: [{ hosts: [app.lab.local], secretName: app-tls }] rules: - host: app.lab.local http: paths: - path: / pathType: Prefix backend: { service: { name: web, port: { number: 80 } } }

NetworkPolicy et CNI

  • Par défaut, tout est ouvert entre Pods. Une NetworkPolicy restreint (entrée / sortie) ; elle n'a d'effet que si le CNI la supporte (Calico, Cilium, Canal : oui ; Flannel seul : non)
  • Bonne pratique : une politique « tout refuser » par namespace, puis des autorisations ciblées (podSelector, namespaceSelector)
  • CNI courants : Calico (politiques, BGP), Cilium (eBPF, observabilité), Flannel (simple), Canal (Flannel + Calico)
  • Bare metal / VM sans cloud : MetalLB ou kube-vip pour les Services LoadBalancer

Haute disponibilité du control plane

HPA : ajuster le nombre de réplicas

Le Horizontal Pod Autoscaler mesure l'utilisation (CPU, mémoire ou métrique personnalisée) et modifie le nombre de réplicas d'un Deployment. Il a besoin du metrics-server.

# Version rapide kubectl autoscale deployment web --min=2 --max=10 --cpu-percent=70 kubectl get hpa -w # Version déclarative (autoscaling/v2) apiVersion: autoscaling/v2 kind: HorizontalPodAutoscaler metadata: name: web spec: scaleTargetRef: apiVersion: apps/v1 kind: Deployment name: web minReplicas: 2 maxReplicas: 10 metrics: - type: Resource resource: name: cpu target: type: Utilization averageUtilization: 70 behavior: scaleDown: stabilizationWindowSeconds: 300
  • Formule : réplicas voulus = ceil( réplicas actuels × mesure / cible ).
  • Stabilisation : par défaut la descente attend 5 minutes, pour éviter les va-et-vient.
  • Tester : lancer un Pod qui boucle des requêtes sur le Service et regarder kubectl get hpa -w.
  • Piège : un Pod sans requests CPU donne un HPA en <unknown>.

Une sauvegarde de volume à chaud peut être incohérente. Les hooks exécutent une commande avant et après la sauvegarde (gel du système de fichiers, vidage de la base) via des annotations sur le Pod :

19Gestion des secretsSécurité
SecretsSealed SecretsESOSOPSVault
Un Secret Kubernetes est seulement encodé en base64, pas chiffré : quiconque peut le lire via l'API ou accéder à etcd voit le contenu. Protéger les secrets, c'est jouer sur quatre leviers : chiffrement au repos, contrôle d'accès, stockage hors cluster et gestion dans Git.

Chiffrer les secrets dans etcd

  • Kubernetes chiffre les Secrets au repos avec une EncryptionConfiguration (fournisseurs aescbc, secretbox ou un KMS externe).
  • RKE2 sait l'activer d'une ligne : secrets-encryption: true dans config.yaml, état avec rke2 secrets-encrypt status.
  • Après activation, réécrire les secrets existants pour les chiffrer : kubectl get secrets -A -o json | kubectl replace -f -.
  • Vérification : une lecture brute dans etcd doit montrer le préfixe du fournisseur (par exemple k8s:enc:aescbc) et non le texte clair.

Réflexes de sécurité

  • RBAC : limiter get, list et watch sur secrets ; list révèle déjà les valeurs. Contrôle avec kubectl auth can-i get secrets --as alice.

22Argo CD en laboGitOps pratique
Argo CDGitOpsApplicationFleet
Argo CD est un outil GitOps : il surveille un dépôt Git et applique son contenu au cluster, puis signale et corrige les écarts. Rancher offre un équivalent intégré, Fleet (voir fiche RKE2 et Rancher).

Installer Argo CD en labo

kubectl create namespace argocd kubectl apply -n argocd --server-side -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml kubectl -n argocd get pods # Mot de passe initial de l'utilisateur admin kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d # Accéder à l'interface sur https://localhost:8080 kubectl -n argocd port-forward svc/argocd-server 8080:443
Pour un usage réel, installe plutôt une version précise (manifeste ou chart Helm) et change le mot de passe administrateur, puis supprime le secret initial.

Une première application

Un dépôt Git contient un dossier apps/web avec les manifestes (ou un chart Helm). On déclare une Application :

apiVersion: argoproj.io/v1alpha1 kind: Application metadata: name: web namespace: argocd spec: project: default source: repoURL: https://github.com/mon-org/mon-depot.git targetRevision: main path: apps/web destination: server: https://kubernetes.default.svc namespace: web syncPolicy: automated: prune: true selfHeal: true syncOptions: - CreateNamespace=true

Ce que l'on observe

StatutSignification
SyncedLe cluster correspond à Git
OutOfSyncGit et cluster diffèrent (modification manuelle ou nouveau commit)
HealthyLes ressources fonctionnent (Pods prêts, etc.)
DegradedUne ressource est en échec
  • automated : applique tout seul chaque commit ; sans, la synchronisation est manuelle (bouton Sync).
  • prune : supprime du cluster ce qui a disparu de Git.
  • selfHeal : annule les modifications faites à la main dans le cluster.
  • Retour arrière : on fait un git revert, pas un rollback dans l'interface.
  • Argo CD interroge Git environ toutes les 3 minutes ; un webhook accélère la détection.

Quelle différence entre K8s, K3s et RKE2 ?

K8s est l'abréviation de Kubernetes ; K3s est une distribution légère (labo, edge) ; RKE2 est une distribution durcie (datacenter, conformité). Les deux sont du Kubernetes certifié.

K9s est-il une distribution Kubernetes ?

Non : c'est une interface en terminal pour piloter un cluster existant, comme un kubectl plus visuel.

À quoi sert K6 ?

C'est un outil de tests de charge (Grafana k6) qui simule des utilisateurs ; il n'est pas lié à Kubernetes, même s'il peut s'y exécuter.

Que change-t-on en passant de K3s à RKE2 ?

L'installation, les réglages par défaut et les composants fournis (etcd, CIS, SELinux) ; les objets Kubernetes que l'on utilise restent les mêmes.

Quand choisir kind ou minikube plutôt que K3s ?

Pour un cluster jetable sur son poste de développement ; K3s convient à un vrai serveur léger (labo, edge).

Quelle est la différence entre un Pod et un Deployment ?

Un Pod est l'unité qui exécute les conteneurs, éphémère ; un Deployment maintient un nombre voulu de Pods identiques et gère les mises à jour progressives et les retours arrière.

Quel composant stocke l'état du cluster ?

etcd : base clé-valeur distribuée, accessible seulement via l'API ; à sauvegarder.

Que fait le scheduler ?

Il choisit le nœud d'un Pod non placé selon les ressources demandées, affinités, taints et contraintes.

Qu'est-ce que le modèle déclaratif ?

On décrit l'état voulu ; des contrôleurs font converger l'état réel vers lui en boucle.

Quelles sont les trois sondes et leur rôle ?

readiness (reçoit du trafic ?), liveness (faut-il redémarrer ?), startup (démarrage long : suspend les deux autres).

Quelle différence entre requests et limits ?

Les requests sont réservées pour le placement ; les limits sont un plafond. Dépasser la mémoire = OOMKilled, dépasser le CPU = bridage.

Quand utiliser un StatefulSet plutôt qu'un Deployment ?

Pour des applications avec état : identité stable, stockage par réplica, démarrage ordonné, Service headless.

Les Secrets Kubernetes sont-ils chiffrés ?

Non par défaut : ils sont seulement encodés en base64. Il faut RBAC strict, chiffrement d'etcd au repos ou un gestionnaire externe.

À quoi sert un Service ?

À donner une adresse et un nom DNS stables devant un ensemble de Pods sélectionnés par labels.

Que vaut le type de Service par défaut et que fait NodePort ?

ClusterIP (interne). NodePort ouvre un port 30000-32767 sur chaque nœud.

Quelle différence entre Ingress et Gateway API ?

Ingress : règles HTTP simples appliquées par un contrôleur. Gateway API : successeur plus expressif avec séparation des rôles (GatewayClass, Gateway, HTTPRoute).

Pourquoi éviter ingress-nginx pour un nouveau projet ?

Il est en fin de vie depuis mars 2026 : plus de correctifs. Préférer Traefik ou un contrôleur compatible Gateway API.

Une NetworkPolicy suffit-elle à restreindre le trafic ?

Seulement si le CNI la supporte (Calico, Cilium, Canal) ; avec Flannel seul elle n'a aucun effet.

Que signifie PV, PVC et StorageClass ?

PV : volume du cluster ; PVC : demande d'une application ; StorageClass : modèle de provisionnement dynamique.

Quelle différence entre RWO et RWX ?

RWO : lecture-écriture par un seul nœud. RWX : par plusieurs nœuds (NFS, CephFS…).

Que fait kubectl drain et à quoi sert un PDB ?

drain évacue un nœud proprement après cordon ; le PodDisruptionBudget garantit un minimum de Pods disponibles pendant l'évacuation.

Quelle différence entre Role et ClusterRole ?

Role : droits dans un namespace. ClusterRole : droits cluster-wide ou modèle réutilisable ; on les attribue par RoleBinding / ClusterRoleBinding.

Comment vérifier un droit RBAC ?

kubectl auth can-i VERBE RESSOURCE -n NS --as UTILISATEUR.

Quels sont les profils de Pod Security ?

privileged, baseline, restricted, appliqués par label de namespace.

Quelle commande installer un logiciel avec Helm en fixant sa version ?

helm install NOM DÉPÔT/CHART --version X -n NS --create-namespace -f values.yaml (ou helm upgrade --install).

Qu'est-ce que le GitOps ?

L'état voulu du cluster est dans Git et un outil (Argo CD, Flux) synchronise le cluster, détecte la dérive et permet le retour arrière par Git.

Un Pod est Pending : où regarder ?

kubectl describe pod : section Events (ressources insuffisantes, taints, PVC non lié, affinité impossible).

Un Service renvoie « connection refused » alors que les Pods tournent : que vérifier ?

kubectl get endpoints : vide = sélecteur du Service différent des labels ; sinon readiness ou port.

Pourquoi sauvegarder etcd et que ne contient pas cette sauvegarde ?

Il contient l'état du cluster (objets). Il ne contient pas les données des volumes persistants.

Combien de nœuds control plane pour la haute disponibilité ?

3 (nombre impair) : quorum de 2, tolère 1 panne ; 5 tolèrent 2 pannes.

Comment mettre à jour un cluster en sécurité ?

Sauvegarder etcd, lire les notes, une version mineure à la fois, control plane puis workers avec cordon/drain/uncordon.

Qu'est-ce qu'un Operator ?

Un CRD plus un contrôleur qui automatise l'exploitation d'une application (déploiement, sauvegarde, bascule).

À quoi sert cert-manager ?

À émettre et renouveler automatiquement des certificats (Let's Encrypt, CA interne).

Comment les certifications CKA/CKAD/CKS sont-elles évaluées ?

Par des examens pratiques en ligne de commande sur de vrais clusters, pas par des QCM.

Pourquoi définir des requests sur les Pods quand on utilise un HPA ?

Le HPA calcule un pourcentage d'utilisation par rapport aux requests ; sans requests CPU, la métrique est indéterminée (<unknown>) et l'autoscaling ne fonctionne pas.

Quelle formule le HPA utilise-t-il pour calculer le nombre de réplicas ?

réplicas voulus = ceil( réplicas actuels × mesure actuelle / cible ), avec un délai de stabilisation à la descente (5 minutes par défaut) pour éviter les oscillations.

Quelle différence entre limit CPU et limit mémoire quand le conteneur la dépasse ?

Au-delà de la limite CPU, le conteneur est ralenti (throttling) ; au-delà de la limite mémoire, il est tué (OOMKilled, code 137).

À quoi sert un PodDisruptionBudget ?

À garantir un minimum de Pods disponibles pendant les interruptions volontaires (drain d'un nœud, mise à jour) : le drain attend plutôt que de passer sous ce minimum.

Quelle différence entre readinessProbe et livenessProbe ?

La readiness retire le Pod des Services sans le redémarrer ; la liveness redémarre le conteneur. Une startupProbe laisse le temps à un démarrage long.

Pourquoi faire à la fois un snapshot etcd et des sauvegardes Velero ?

etcd permet de reconstruire le cluster, mais pas de restaurer une application seule ni ses volumes ; Velero sauvegarde les applications et volumes et sert aussi à migrer vers un autre cluster.

Comment Velero sauvegarde-t-il les volumes ?

Par snapshots CSI (rapide, dépend du pilote de stockage) ou par sauvegarde de fichiers via un agent sur les nœuds (plus lent mais indépendant du stockage).

Un Secret Kubernetes est-il chiffré ?

Non, il est seulement encodé en base64. Il faut activer le chiffrement au repos dans etcd, restreindre le RBAC et éviter de stocker les secrets en clair dans Git.

Quelle différence entre Sealed Secrets et External Secrets Operator ?

Sealed Secrets permet de commiter un secret chiffré dans Git que seul le cluster déchiffre ; External Secrets Operator synchronise des secrets depuis un coffre externe (Vault, gestionnaire cloud).

Comment activer le chiffrement des secrets au repos sur RKE2 ?

Avec secrets-encryption: true dans config.yaml ; l'état se contrôle avec rke2 secrets-encrypt status.

Un Pod est en CrashLoopBackOff : quelle démarche suivre ?

Lire kubectl logs --previous et le code de sortie dans describe pod, puis chercher une erreur de démarrage, une variable manquante ou une sonde liveness trop stricte.

Un Service ne répond pas alors que les Pods tournent : que vérifier ?

Les endpoints du Service : le sélecteur doit correspondre aux étiquettes des Pods, les Pods doivent être Ready, et le port cible doit être le bon.

Quels sont les domaines de la CKA par ordre de poids ?

Dépannage (30 %), architecture et installation du cluster (25 %), services et réseau (20 %), workloads et ordonnancement (15 %), stockage (10 %) ; à vérifier sur le programme en vigueur.

Quelle est l'erreur la plus fréquente pendant l'examen CKA ?

Oublier de changer de contexte (kubectl config use-context) au début de chaque question et agir sur le mauvais cluster.

Que font les options automated, prune et selfHeal d'Argo CD ?

automated applique chaque commit, prune supprime du cluster ce qui a disparu de Git, selfHeal annule les modifications manuelles faites dans le cluster.

Comment revenir en arrière avec Argo CD ?

On revient en arrière dans Git avec un git revert, puis Argo CD synchronise le cluster sur ce nouvel état.
