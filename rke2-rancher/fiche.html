1Panorama : RKE2, Rancher et leurs rôlesFondations
RKE2Rancherk3sDownstream
RKE2 (Rancher Kubernetes Engine 2, « RKE Government ») est une distribution Kubernetes certifiée CNCF, durcie par défaut (profil CIS, conformité FIPS 140-2 possible) et empaquetée en un seul binaire avec containerd. Rancher est la plateforme de gestion multi-clusters (interface, authentification centralisée, RBAC global, catalogue d'applications, import / provisionnement de clusters). Ce sont deux produits distincts qui s'associent bien.
RKE2k3sRancher
NatureDistribution KubernetesDistribution légèrePlateforme de gestion
CibleDatacenter, secteur public, durcissementEdge, IoT, labo, petits clustersPiloter plusieurs clusters (tous types)
DatastoreetcdSQLite par défaut, etcd intégré possibleTourne sur un cluster Kubernetes
InstallationScript + service systemdScript + service systemdChart Helm sur un cluster

Architecture type d'un projet

  1. Cluster de management : RKE2 à 3 nœuds server qui héberge Rancher (Helm) : on n'y met pas d'applications métier
  2. Clusters downstream : clusters de production / test créés par Rancher (RKE2 sur VM, fournisseur cloud…) ou importés (clusters existants)
  3. Rancher déploie l'agent cattle-cluster-agent dans chaque cluster downstream pour communiquer avec lui
Compatibilité : chaque version de Rancher certifie une plage de versions de Kubernetes pour le cluster de management (à lire dans la matrice de support Rancher avant d'installer). Au moment de la rédaction de cette fiche (nov. 2026), Rancher 2.15.x certifiait Kubernetes 1.34 à 1.36 : donc RKE2 en 1.36 pour le cluster qui héberge Rancher. À re-vérifier à chaque installation.

5Installer un cluster RKE2 (1 puis 3 serveurs)Installation
ServerAgentconfig.yamlToken

Premier nœud server

mkdir -p /etc/rancher/rke2 cat > /etc/rancher/rke2/config.yaml <<'EOF' token: MON-SECRET-PARTAGE # facultatif : sinon généré dans node-token tls-san: - rke2.lab.local # nom / IP virtuelle de l'API - 10.0.0.10 write-kubeconfig-mode: "0640" EOF curl -sfL https://get.rke2.io | INSTALL_RKE2_CHANNEL=v1.36 sh - # ou INSTALL_RKE2_VERSION=... systemctl enable --now rke2-server.service journalctl -u rke2-server -f # suivre le démarrage

Accéder au cluster

export KUBECONFIG=/etc/rancher/rke2/rke2.yaml export PATH=$PATH:/var/lib/rancher/rke2/bin # kubectl, crictl, ctr kubectl get nodes -o wide cat /var/lib/rancher/rke2/server/node-token # jeton pour joindre d'autres nœuds

Joindre les serveurs 2 et 3 (HA)

cat > /etc/rancher/rke2/config.yaml <<'EOF' server: https://rke2.lab.local:9345 token: MON-SECRET-PARTAGE tls-san: - rke2.lab.local EOF curl -sfL https://get.rke2.io | INSTALL_RKE2_CHANNEL=v1.36 sh - systemctl enable --now rke2-server.service # un nœud à la fois, attendre Ready

Ajouter des workers

curl -sfL https://get.rke2.io | INSTALL_RKE2_TYPE="agent" sh - cat > /etc/rancher/rke2/config.yaml <<'EOF' server: https://rke2.lab.local:9345 token: MON-SECRET-PARTAGE EOF systemctl enable --now rke2-agent.service
  • Les serveurs rejoignent un par un ; tu dois avoir un nombre impair de serveurs (3 ou 5)
  • tls-san doit contenir tous les noms / IP par lesquels on joint l'API, sinon erreurs de certificat
  • Le premier démarrage télécharge les images : prévoir quelques minutes (ou voir la section air-gap)

8Sauvegarde et restauration etcdReprise
SnapshotS3cluster-resetRestauration
Un snapshot etcd contient l'état du cluster (objets Kubernetes), pas les données des volumes. Par défaut RKE2 prend un snapshot toutes les 12 heures et en garde 5, sur chaque serveur.
# Snapshot à la demande rke2 etcd-snapshot save --name avant-upgrade rke2 etcd-snapshot ls # Planification et copie S3 (config.yaml) etcd-snapshot-schedule-cron: "0 */6 * * *" etcd-snapshot-retention: 14 etcd-s3: true etcd-s3-endpoint: s3.lab.local etcd-s3-bucket: rke2-snapshots etcd-s3-access-key: ... etcd-s3-secret-key: ...

Restaurer (cluster à un seul serveur ou panne totale)

  1. Arrêter rke2-server sur tous les serveurs (rke2-killall.sh)
  2. Sur un seul serveur : rke2 server --cluster-reset --cluster-reset-restore-path=/chemin/snapshot (ou depuis S3 avec les options --etcd-s3…)
  3. Redémarrer ce serveur : systemctl start rke2-server
  4. Sur les autres serveurs : supprimer /var/lib/rancher/rke2/server/db puis redémarrer pour qu'ils rejoignent le cluster restauré
Procédure à répéter en labo avant d'en avoir besoin : l'ordre exact et les options varient selon la version, suis la page « Backup and Restore » de ta version. Restaure aussi les volumes avec l'outil de ton stockage (Longhorn snapshots / sauvegardes, Velero…).

Installation hors ligne

  1. Télécharger sur une machine connectée : rke2-images.linux-amd64.tar.zst (ou le .tar.gz), rke2.linux-amd64.tar.gz, sha256sum-amd64.txt et install.sh
  2. Copier les archives d'images dans /var/lib/rancher/rke2/agent/images/ sur chaque nœud
  3. Lancer l'installeur en mode tarball : INSTALL_RKE2_ARTIFACT_PATH=/chemin sh install.sh
  4. Démarrer le service ; les images sont chargées localement
# /etc/rancher/rke2/registries.yaml : miroir et authentification mirrors: docker.io: endpoint: - "https://registry.lab.local" configs: "registry.lab.local": auth: username: robot password: ... tls: ca_file: /etc/ssl/certs/registry-ca.pem

Durcissement CIS

  • profile: cis active les contrôles du référentiel CIS ; nécessite des réglages OS préalables (utilisateur etcd, paramètres sysctl : voir la page « CIS Hardening Guide » de ta version)
  • Active aussi la Pod Security par défaut et des NetworkPolicies de base : certaines applications devront recevoir leurs propres politiques
  • RKE2 fournit un rapport de conformité via kube-bench (aussi disponible dans Rancher : CIS Scan)
  • SELinux en mode enforcing supporté sur RHEL-like (selinux: true)

Auto-évaluation — clique pour voir la réponse

Dans l'analogie du restaurant, que représentent RKE2 et Rancher ?

RKE2 est un restaurant aux normes de sécurité renforcées ; Rancher est la direction du groupe qui supervise plusieurs restaurants sans cuisiner.

Quelle différence entre cluster de management et cluster downstream ?

Le cluster de management héberge Rancher ; les clusters downstream sont ceux que Rancher gère.

À quoi sert le cattle-cluster-agent ?

C'est l'agent déployé dans chaque cluster géré ; il établit la liaison avec Rancher (HTTPS 443).

Qu'est-ce que RKE2 ?

Une distribution Kubernetes certifiée CNCF, durcie par défaut (CIS, FIPS possible), en un binaire avec containerd et etcd.

Quelle différence entre RKE2 et Rancher ?

RKE2 est le moteur Kubernetes ; Rancher est la plateforme de gestion multi-clusters (interface, SSO, RBAC, catalogue) qui s'installe sur un cluster.

Quelle différence entre RKE2 et k3s ?

k3s est léger (edge, labo, SQLite par défaut) ; RKE2 est orienté datacenter et durcissement, avec etcd.

Combien de serveurs pour la haute disponibilité ?

3 (impair) : le quorum etcd tolère la perte d'un serveur ; 5 tolèrent 2 pannes.

À quoi servent les ports 9345 et 6443 ?

9345 : API de supervision RKE2 (enregistrement des nœuds) ; 6443 : API Kubernetes.

Où se trouve le kubeconfig d'un cluster RKE2 ?

/etc/rancher/rke2/rke2.yaml sur un serveur ; kubectl se trouve dans /var/lib/rancher/rke2/bin.

Comment un worker rejoint-il le cluster ?

Installer avec INSTALL_RKE2_TYPE=agent, renseigner server: https://…:9345 et token dans config.yaml, démarrer rke2-agent.

À quoi sert tls-san ?

Lister tous les noms et IP par lesquels on joint l'API, pour qu'ils figurent dans le certificat.

Où est stocké le jeton des nœuds ?

Dans /var/lib/rancher/rke2/server/node-token sur un serveur (ou défini dans config.yaml).

Quel CNI par défaut et quelles alternatives ?

Canal (Flannel + Calico). Alternatives : Calico, Cilium. À choisir avant la création du cluster.

Que devient l'ingress dans les versions récentes ?

ingress-nginx est en fin de vie depuis mars 2026 ; Traefik devient le contrôleur par défaut à partir de RKE2 1.36. À vérifier dans les notes de ta version.

Comment personnaliser un chart empaqueté ?

Avec un HelmChartConfig du même nom dans /var/lib/rancher/rke2/server/manifests/, champ valuesContent.

Quelle est la politique de snapshots par défaut ?

Un snapshot etcd toutes les 12 heures, 5 conservés, dans /var/lib/rancher/rke2/server/db/snapshots.

Comment prendre un snapshot à la demande ?

rke2 etcd-snapshot save --name NOM ; lister avec rke2 etcd-snapshot ls.

Comment restaurer etcd ?

Arrêter tous les serveurs, puis sur un seul : rke2 server --cluster-reset --cluster-reset-restore-path=…, redémarrer, et réinitialiser le dossier db des autres serveurs pour qu'ils rejoignent.

Un snapshot etcd sauvegarde-t-il les volumes ?

Non : seulement l'état du cluster. Les volumes se sauvegardent avec l'outil de stockage ou Velero.

Comment mettre à jour RKE2 ?

Snapshot, une version mineure à la fois, serveurs un par un puis workers, avec drain / installateur avec INSTALL_RKE2_VERSION / restart / uncordon, ou via system-upgrade-controller.

Comment installer RKE2 hors ligne ?

Copier les archives d'images dans /var/lib/rancher/rke2/agent/images/, installer par tarball (INSTALL_RKE2_ARTIFACT_PATH) et configurer registries.yaml pour un registre privé.

Que fait profile: cis ?

Active les contrôles du référentiel CIS (dont Pod Security et NetworkPolicies de base) ; demande des réglages préalables de l'OS.

Quelle version de RKE2 choisir pour héberger Rancher ?

Une version de Kubernetes certifiée par la version de Rancher visée (matrice de support). Fin 2026, Rancher 2.15.x certifiait Kubernetes 1.34 à 1.36.

Quels sont les prérequis de l'installation Helm de Rancher ?

Un cluster RKE2 sain, cert-manager, un nom DNS (hostname), le dépôt de charts Rancher et un mot de passe d'amorçage.

Quelles sont les options de certificat pour Rancher ?

Auto-signé géré par Rancher (défaut), Let's Encrypt, ou certificat fourni dans un Secret (CA privée avec tls-ca).

Comment ajouter un cluster existant à Rancher ?

L'importer : Rancher fournit une commande kubectl apply qui déploie l'agent cattle-cluster-agent dans le cluster cible.

À quoi sert Fleet ?

GitOps intégré à Rancher : des GitRepo déployés sur des groupes de clusters sélectionnés par labels.

Pourquoi ne pas déployer d'applications sur le cluster Rancher ?

Pour isoler la plateforme de gestion : stabilité, sécurité, mises à jour indépendantes.

Que sauvegarder pour reconstruire Rancher ?

L'etcd du cluster qui l'héberge et l'opérateur Rancher Backups vers S3, plus config.yaml et les values Helm dans Git.

Un nœud ne rejoint pas le cluster : que vérifier ?

Le jeton, le port 9345, le nom DNS de server:, l'horloge, puis le journal de rke2-agent.
