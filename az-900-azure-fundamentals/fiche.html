Concepts cloud fondamentaux

📘 Domaine 1 · 25–30%

Définition du cloud computing

Le cloud computing est la fourniture de services informatiques (serveurs, stockage, bases de données, réseau, logiciels, analytique, IA) via Internet, avec facturation à l'utilisation.

Haute disponibilité

  • SLA Azure : jusqu'à 99,99% de disponibilité
  • Redondance géographique
  • Zones de disponibilité
  • Paires de régions

Scalabilité

  • Verticale : + CPU/RAM à une VM existante
  • Horizontale : + instances identiques
  • Azure Scale Sets (auto-scaling)
  • Scale out ≠ Scale up

Fiabilité & Prédictibilité

  • Résilience : infrastructure redondante
  • Récupération automatique après incident
  • Prédictibilité des coûts (tarification connue)
  • Prédictibilité des perfs (autoscale)

Sécurité & Gouvernance

  • Microsoft Defender for Cloud
  • Azure Policy & Blueprints
  • Certifications conformité : ISO, SOC, RGPD…
  • Gestion centralisée des accès

Gérabilité

  • Portail Azure (interface web)
  • Azure CLI / PowerShell / ARM
  • Mise à l'échelle automatique
  • Déploiement via modèles

Modèles cloud

📘 Domaine 1 · 25–30%

☁️ Cloud public

  • Infrastructure appartenant au fournisseur (Microsoft)
  • Accessible via Internet
  • Pas de CapEx initial
  • Mutualisation des ressources
  • Mise à l'échelle élastique

🏢 Cloud privé

  • Infrastructure dédiée à une organisation
  • Hébergé sur site ou datacenter dédié
  • Contrôle et sécurité maximaux
  • CapEx élevé
  • Organisation maintient le matériel

🔀 Cloud hybride

  • Combinaison public + privé
  • Azure Arc pour gérer les deux
  • Flexibilité maximale
  • Compliance : données sensibles on-prem
  • Migration progressive vers le cloud

🏘️ Multi-cloud

  • Plusieurs fournisseurs cloud
  • Azure + AWS, GCP…
  • Évite le vendor lock-in
  • Azure Arc gère ressources multi-cloud

Modèle de consommation & Serverless

CapEx (Capital Expenditure)

  • Dépenses d'investissement initiales

Serverless computing

Azure Functions

  • Code exécuté à la demande
  • Facturation à l'exécution
  • Pas de gestion de serveur
  • Déclencheurs : HTTP, timer, queue…

Azure Logic Apps

  • Workflows d'automatisation
  • Connecteurs prêts à l'emploi
  • Intégration (low-code)
  • Déclencheurs & actions

Azure Container Apps

  • Conteneurs sans gestion de cluster
  • Scale-to-zero possible
  • KEDA pour l'autoscaling

Architecture Azure — Composants fondamentaux

🏗️ Domaine 2 · 35–40%

Hiérarchie des ressources Azure

Ordre de la hiérarchie (du plus grand au plus petit) Groupes d'administration → Abonnements → Groupes de ressources → Ressources
Groupe d'administrationConteneur pour plusieurs abonnements. Permet d'appliquer des stratégies et contrôles d'accès à grande échelle (Azure Policy, RBAC hérite vers le bas).
AbonnementUnité de facturation et de gestion. Chaque ressource Azure appartient à un abonnement. Limite d'utilisation par abonnement.
Groupe de ressourcesConteneur logique de ressources Azure. Toute ressource doit appartenir à un seul groupe. Cycle de vie partagé. Région de déploiement du groupe ≠ région des ressources.
RessourceInstance d'un service Azure (VM, base de données, réseau virtuel, etc.).

Régions, zones de disponibilité & paires de régions

Concept Description Usage
Région Zone géographique avec au moins un datacenter (ex : France Central, West Europe) Choisir la région la plus proche des utilisateurs
Zone de disponibilité Datacenters physiquement séparés dans une même région (min 3 par région). Alimentation, réseau, refroidissement indépendants. Haute disponibilité : SLA 99,99% avec VM zonales
Paire de régions Deux régions Azure appairées à ≥300 km. Ex : France Central ↔ France South Réplication géo-redondante, reprise après désastre
Régions souveraines Azure Government (US), Azure China 21Vianet Conformité gouvernementale / réglementaire stricte

Calcul & Réseau Azure

🏗️ Domaine 2 · 35–40%

Services de calcul

Service Type Usage typique
Azure Virtual Machines IaaS Migration lift-and-shift, contrôle total de l'OS
VM Scale Sets IaaS Groupes de VMs identiques avec autoscaling (jusqu'à 1000 VMs)
Availability Sets IaaS Groupes de VMs sur domaines de pannes/MAJ distincts. SLA 99,95%
Azure Virtual Desktop SaaS/PaaS Bureau Windows dans le cloud, accès multi-appareil
Azure App Service PaaS Héberger apps web, API REST, mobile backends
Azure Container Instances (ACI) PaaS Conteneurs sans gestion d'infrastructure, démarrage rapide
Azure Kubernetes Service (AKS) PaaS Orchestration de conteneurs managée (Kubernetes)
Azure Functions Serverless Exécution de code à la demande, facturation à l'exécution

Availability Sets vs Availability Zones

Availability Sets (ancienne approche)

  • VMs réparties sur domaines de pannes (fault domains) : matériel distinct
  • VMs réparties sur domaines de mise à jour (update domains)
  • SLA : 99,95% pour 2+ VMs
  • Pas de coût supplémentaire pour l'Availability Set
  • Reste dans un seul datacenter

Availability Zones (recommandée)

  • VMs dans des datacenters physiques distincts (≥3 zones)
  • Alimentation / réseau / refroidissement indépendants
  • SLA : 99,99% pour 2+ VMs zonales
  • Protection contre la défaillance d'un datacenter entier
  • Recommandée par Microsoft

Réseau Azure

Service réseau Rôle
Virtual Network (VNet) Réseau privé dans Azure. Isolation, segmentation, communication entre ressources
Sous-réseaux (Subnets) Segmentation d'un VNet. Isolation et contrôle du trafic avec NSG
VNet Peering Connexion privée entre VNets (même région ou cross-region). Réseau backbone Microsoft
Azure DNS Hébergement de zones DNS dans Azure. Haute disponibilité, intégration Azure
Azure VPN Gateway Connexion chiffrée (VPN) entre Azure et réseau on-premises via Internet
Azure ExpressRoute Connexion privée dédiée (fibre) entre on-premises et Azure. Bypass Internet. SLA > VPN
Point de terminaison public Ressource accessible depuis Internet avec adresse IP publique
Point de terminaison privé Interface réseau privée dans le VNet pour accéder à un service Azure en privé (sans Internet)
💡 VPN Gateway vs ExpressRoute VPN = connexion chiffrée via Internet (moins cher, moins fiable). ExpressRoute = fibre privée dédiée (coûteuse, SLA garanti, non chiffrée par défaut mais très sécurisée).

Identité, Accès & Sécurité

🏗️ Domaine 2 · 35–40%

Microsoft Entra ID (ex Azure Active Directory)

Entra IDService cloud d'identité et de gestion des accès. Gère authentification des utilisateurs, groupes, applications. Remplace Azure AD depuis 2023.
Entra Domain ServicesActive Directory Domain Services managé dans Azure. Permet de joindre des VMs Azure à un domaine sans déployer de contrôleurs de domaine.
TenantInstance dédiée d'Entra ID pour une organisation. Créé automatiquement à l'inscription Azure.

Méthodes d'authentification

Méthode Description
SSO (Single Sign-On) Une seule authentification pour accéder à toutes les applications. Réduit la fatigue des mots de passe.
MFA (Multi-Factor Auth.) Deux facteurs ou plus : quelque chose que vous savez (mot de passe) + quelque chose que vous avez (téléphone) ou êtes (biométrie)
Sans mot de passe Windows Hello, Microsoft Authenticator, clés FIDO2. Plus sécurisé que les mots de passe.
Identités externes B2B : inviter des partenaires externes. B2C : identités clients (réseaux sociaux, comptes propres).

Conditional Access (Accès conditionnel)

Moteur de stratégie Zero Trust : évalue des signaux (utilisateur, emplacement, appareil, app) pour prendre des décisions d'accès (si X alors Y). Exemples : exiger MFA depuis l'extérieur, bloquer les appareils non conformes.

Signal : utilisateur/groupe Signal : emplacement/IP Signal : appareil (conformité) Signal : application cible Signal : risque (Entra ID Protection)

Azure RBAC (Role-Based Access Control)

PrincipeAccorder uniquement les droits nécessaires (moindre privilège). Attribuer un rôle à une identité sur une portée (ressource, groupe de ressources, abonnement, groupe d'administration).
Rôles intégrésPropriétaire (lecture+écriture+gestion accès) | Contributeur (lecture+écriture, pas gestion accès) | Lecteur (lecture seule) | Admin accès utilisateurs
HéritageLes rôles s'appliquent de façon héritée vers le bas : un rôle sur l'abonnement s'applique à tous ses groupes de ressources et ressources.

Zero Trust & Défense en profondeur

Zero Trust — 3 principes

  • Vérifier explicitement : authentifier toujours, même sur le réseau interne
  • Moindre privilège : accès JIT (Just-in-Time), limité au strict nécessaire
  • Supposer une violation : segmenter, chiffrer, surveiller en permanence

Défense en profondeur — 7 couches

  • Sécurité physique
  • Identité & accès
  • Périmètre réseau
  • Réseau
  • Calcul (VMs)
  • Applications
  • Données

Microsoft Defender for Cloud

Outil de gestion de la posture de sécurité cloud (CSPM) et de protection des charges de travail (CWP). Évalue la configuration Azure selon les bonnes pratiques et fournit un Score de sécurité. Détecte et répond aux menaces sur VMs, bases de données, conteneurs, etc.

Score de sécurité Recommandations de sécurité Alertes de sécurité Azure + multi-cloud + on-prem

Gestion des coûts Azure

⚙️ Domaine 3 · 30–35%

Facteurs qui influencent les coûts

  • Type et taille des ressources (VM Standard vs Premium)
  • Région Azure (prix variables selon la région)
  • Bande passante sortante (ingress gratuit, egress payant)
  • Durée d'utilisation (à la seconde pour certains services)
  • Type d'abonnement (Pay-as-you-go, EA, CSP…)

Calculatrice de prix

  • Estimation avant déploiement
  • Configurer services, régions, durée
  • Exporter le devis PDF/Excel
  • azure.microsoft.com/pricing/calculator

Calculatrice TCO

  • Comparer coût on-premises vs Azure
  • Total Cost of Ownership sur 5 ans
  • Inclut : serveurs, stockage, réseau, IT

Microsoft Cost Management

  • Analyse des dépenses réelles
  • Budgets & alertes de dépassement
  • Recommandations d'optimisation
  • Rapports et tableaux de bord

Balises (Tags)

💡 Rôle des balises Les balises (paires clé-valeur : Environnement: Production, Centre de coûts: Finance) permettent d'organiser les ressources Azure et de filtrer les coûts par balise dans Azure Cost Management. Les balises ne sont pas héritées automatiquement par les ressources enfants.

Gouvernance & Conformité

⚙️ Domaine 3 · 30–35%
Outil Rôle
Microsoft Purview Gouvernance des données et conformité. Catalogue de données, classification de la sensibilité, gestion des risques. Vision unifiée des données Azure + Microsoft 365 + multi-cloud.
Azure Policy Définir et appliquer des règles sur les ressources (ex : toute VM doit être dans une région approuvée, toute ressource doit avoir une balise). Audit, déni, correction automatique.
Verrous de ressource (Locks) Protéger les ressources contre la modification ou suppression accidentelle. CanNotDelete : lecture et modification OK, suppression interdite. ReadOnly : lecture seule, aucune modification ni suppression.
Azure Blueprints (Déprécié — migrer vers Azure Deployment Environments + Template Specs) Anciennement : définir des environnements Azure conformes en un seul package (RBAC + Policies + ARM templates).
⚠️ Verrous vs RBAC Les verrous s'appliquent à TOUTES les personnes y compris les propriétaires (Owner). Même un Owner ne peut pas supprimer une ressource avec un verrou CanNotDelete sans retirer le verrou d'abord.

Surveillance & Monitoring

⚙️ Domaine 3 · 30–35%
Service Rôle
Azure Advisor Assistant de recommandations personnalisées dans 5 catégories : Fiabilité, Sécurité, Performance, Coûts, Excellence opérationnelle. Analyse votre configuration et propose des améliorations.
Azure Service Health Tableau de bord de la santé des services Azure. 3 niveaux : Azure Status (mondial), Service Health (votre abonnement, alertes personnalisées), Resource Health (ressource individuelle).
Azure Monitor Plateforme centralisée de collecte, analyse et action sur métriques et logs. Inclut Log Analytics, alertes, Application Insights.
Log Analytics Outil de requêtes sur les logs (langage KQL). Permet d'analyser des données de performance, événements, diagnostics.
Azure Monitor Alerts Alertes basées sur des métriques ou des requêtes de logs. Actions : e-mail, SMS, webhook, Azure Action Groups.
Application Insights Monitoring des applications (APM). Performances, exceptions, dépendances, flux utilisateurs. Intégré dans Azure Monitor.
💡 Mémo Service Health Azure Status = tout Azure mondial | Service Health = services Azure dans votre région/abonnement | Resource Health = une ressource spécifique. Configurer des alertes Service Health pour être notifié des incidents Azure qui vous affectent.

Pièges classiques & Nuances examen

⚠️ Points critiques à retenir
  • Les données restent TOUJOURS responsabilité du client, même en SaaS (Microsoft 365). Microsoft gère la plateforme mais pas vos données.
  • Availability Sets ≠ Availability Zones : les Availability Sets protègent contre les pannes matérielles dans un SEUL datacenter. Les Availability Zones protègent contre la perte d'un datacenter entier.
  • GRS ≠ RA-GRS : GRS réplique mais la région secondaire est inaccessible en lecture sans failover. RA-GRS permet de lire depuis la région secondaire en temps réel.
  • Les balises ne s'héritent pas automatiquement des groupes de ressources vers les ressources. Il faut les appliquer explicitement ou via Azure Policy.
  • Azure Policy ≠ RBAC : Policy contrôle ce qu'on peut FAIRE avec les ressources (propriétés). RBAC contrôle QUI peut accéder à quoi.
  • Un groupe de ressources est dans une seule région mais ses ressources peuvent être dans des régions différentes.
  • Verrous héritables : un verrou sur un groupe de ressources s'applique à toutes ses ressources, y compris pour les Owners.
  • ExpressRoute n'est pas chiffré par défaut — c'est une liaison privée, non chiffrée (sauf IPsec optionnel). Plus sécurisée que le VPN car elle n'utilise pas Internet.
  • ARM est la couche de gestion : tout appel API, portail, CLI, PowerShell passe par ARM. ARM authentifie et autorise avant d'agir sur les ressources.
  • Azure Arc n'est pas Azure : Arc étend la gestion Azure aux ressources HORS Azure (on-prem, autres clouds). Il ne migre pas les ressources, il les gère là où elles sont.
  • Serverless ≠ sans serveur : il y a des serveurs, mais vous ne les gérez pas. Vous payez à l'exécution, pas à la durée d'exécution continue.
  • Azure Advisor = recommandations proactives, pas de monitoring en temps réel. Pour les alertes en temps réel, c'est Azure Monitor.
