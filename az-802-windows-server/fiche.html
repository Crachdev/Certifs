Sites AD et réplication

  • Site Link : définit le coût et la fréquence de réplication inter-sites (KCC génère automatiquement la topologie)
  • Réplication intra-site : automatique, environ 15 secondes. Inter-site : selon le schedule du site link (défaut 180 min)
  • Connexion forcée : repadmin /syncall /AdeP · Statut : repadmin /showrepl · repadmin /replsummary
  • SYSVOL : répliqué via DFSR (depuis WS 2008R2). Migration NTFRS→DFSR : dfsrmig

Corbeille AD (AD Recycle Bin)

Activer
Enable-ADOptionalFeature 'Recycle Bin Feature' -Scope ForestOrConfigurationSet -Target domaine.local
Restaurer
Get-ADObject -Filter {isDeleted -eq $true} -IncludeDeletedObjects | Restore-ADObject
⚠️ Irréversible : une fois activée, impossible de désactiver sans recréer la forêt. Niveau fonctionnel minimum : WS 2008 R2.

Délégation de contrôle (OU Delegation)

  • Clic droit sur l'OU → Delegate Control → assistant guidé
  • Ou via dsacls "OU=Computers,DC=domain,DC=local" /G "DOMAIN\HelpDesk:RPWP;pwdLastSet"
  • Vérifier avec Active Directory Rights Management ou via ADSI Edit

Protected Users & Tiering

Groupe Protected Users

  • Pas de NTLM, Digest, CredSSP
  • Kerberos uniquement (AES)
  • TGT limité à 4h (non renouvelable)
  • Pas de délégation Kerberos non contrainte

AD Tier Model

  • Tier 0 : DCs, Schema Admins, PKI
  • Tier 1 : Serveurs d'application
  • Tier 2 : Postes de travail, utilisateurs
  • Jamais de credentials Tier 0 sur Tier 1/2

gMSA (Group Managed Service Accounts)

  1. Créer la clé racine KDS : Add-KdsRootKey -EffectiveImmediately
  2. Créer le gMSA : New-ADServiceAccount -Name svc-web -DNSHostName svc-web.domain.local -PrincipalsAllowedToRetrieveManagedPassword "WebServers"
  3. Installer sur les serveurs : Install-ADServiceAccount svc-web
  4. Configurer le service avec le compte DOMAIN\svc-web$ (pas de mot de passe manuel)

SQL Always On & WSFC

  • Nécessite Windows Server Failover Clustering (WSFC) activé
  • Primary Replica → synchronisation synchrone/asynchrone vers Secondary Replicas
  • Automatic Failover : réplica synchrone + witness quorum
  • Validation cluster : Test-Cluster -Node SRV01,SRV02
  • Quorum recommandé : Node and File Share Majority (2 nœuds + témoin)

Azure Azure AD / Entra ID & Hybrid

Azure AD Connect

Méthodes d'authentification

PHS (Password Hash Sync)
Hash de hash synchronisé dans Azure AD — le plus résilient
PTA (Pass-Through Auth)
Validation on-premises en temps réel via agents
Federation (AD FS)
SAML/WS-Fed — complexe, contrôle total

Seamless SSO

  • Crée le compte AZUREADSSOACC$ dans AD
  • Kerberos ticket vers Azure AD
  • Compatible PHS et PTA
  • Configurer via Group Policy (site intranet → kerberos)

Azure AD Password Protection

  • Bloque les mots de passe bannis (liste Microsoft + custom)
  • On-premises : installer DC Agent + Proxy Service
  • Modes : Audit (log uniquement) → Enforced (bloque)
  • Event IDs : 30001 Password accepted · 30002 Password rejected

Kerberos Constrained Delegation

KCD classique

  • Configuré sur le compte de service (ADUC → Delegation tab)
  • Trust this computer for delegation to specified services only
  • Requiert Domain Admin
  • Limité au même domaine

RBCD (Resource-Based)

  • Configuré sur la ressource (msDS-AllowedToActOnBehalfOfOtherIdentity)
  • Délégable par le propriétaire de la ressource
  • Cross-domain, plus flexible
  • Set-ADComputer -PrincipalsAllowedToDelegateToAccount

Conditional Access & PIM

Conditional Access

  • Signal → Décision → Application
  • Contrôles : MFA, device compliant, app approuvée
  • Named Locations : plages IP de confiance
  • Sign-in Risk (Entra ID Protection)

PIM (Privileged Identity Management)

  • Roles Eligible (doivent activer) vs Active permanent
  • Just-in-time access avec durée limitée
  • Approbation requise / justification
  • Access Reviews périodiques

LAPS v2

  • Intégré nativement WS 2022 / Win 11 22H2 (plus besoin de LAPS legacy)
  • Stockage dans AD (ms-LAPS-Password) ou Azure AD
  • Activation GPO : Computer > LAPS > Enable LAPS
  • Récupération : Get-LapsADPassword -Identity PC01 -AsPlainText
  • Rotation forcée : Reset-LapsPassword -ComputerName PC01

SEC Sécurité Windows

Credential Guard / WDAG / AppLocker / WDAC

Credential Guard

  • Isole LSASS dans une VM sécurisée (VSM/VBS)
  • Protège NTLM hashes, Kerberos TGTs
  • Prérequis : UEFI Secure Boot, VT-x/VT-d
  • GPO : Device Guard > Turn on Virtualization Based Security

WDAG (Application Guard)

  • Edge dans une VM Hyper-V isolée
  • Navigation non fiable sans risque pour l'hôte
  • Fichiers téléchargés isolés
  • GPO : Windows Defender AG > Turn on WDAG

AppLocker

  • Règles : Publisher, Path, Hash
  • S'applique à : Exe, DLL, Scripts, Packaged Apps
  • Configurable via GPO
  • Contournable par les admins locaux

WDAC

  • Policy XML compilée, appliquée au kernel
  • Résiste aux admins locaux
  • + HVCI = protection maximale
  • Modes : Audit → Enforced

MDE (Microsoft Defender for Endpoint)

  • Onboarding WS 2022 : script natif ou via Azure Arc + MDfC
  • Alertes : Microsoft 365 Defender portal (security.microsoft.com)
  • Live Response : exécution de commandes à distance
  • Attack Surface Reduction (ASR) rules : bloquer Office macros, credential theft, etc.
  • Isolation réseau : isoler une machine compromise depuis le portail

GPO Security Baselines (SCM)

  • Télécharger depuis Microsoft Security Compliance Toolkit
  • Importer : lgpo.exe /g .\GPO ou via Group Policy Management
  • Inclut les baselines pour WS 2019/2022, Edge, Office 365
  • Comparer avec Policy Analyzer inclus dans le toolkit

DHCP Security

  • DHCP Failover : Hot Standby (serveur de secours) ou Load Balance (50/50)
  • DHCP Snooping : sur les switches managés — bloquer les serveurs DHCP non autorisés
  • Dynamic ARP Inspection : couplé avec DHCP Snooping
  • Audit log DHCP : C:\Windows\System32\dhcp\ (DhcpSrvLog-*.log)

DNS Haute Disponibilité

  • Primary/Secondary zones : secondaire en lecture seule, transfert de zone IXFR/AXFR
  • AD-Integrated zones : répliquées via la réplication AD (recommandé) — tous les DCs sont authoritative
  • Conditional Forwarders : résolution cross-domaine ou vers Azure DNS
  • Azure DNS Private Zones : résolution on-premises vers Azure via DNS forwarders

RRAS VPN & SDN

RRAS VPN

  • S2S IKEv2 avec Azure VPN Gateway
  • Always On VPN (remplace DirectAccess)
  • Split tunneling : seul le trafic d'entreprise passe par VPN
  • Diagnostics : Get-VpnConnection

SDN (Software Defined Networking)

  • Network Controller : cerveau centralisé
  • SLB (Software Load Balancer)
  • RAS Gateway : connectivité hybride
  • Micro-segmentation via ACLs distribuées

BranchCache / Delivery Optimization

BranchCache

  • Mode Hosted Cache : serveur dédié en agence
  • Mode Distributed Cache : P2P entre postes
  • Compatible HTTP, HTTPS, SMB, BITS
  • Config GPO : Network > BranchCache

Delivery Optimization

  • P2P pour les mises à jour Windows/Office
  • Modes : LAN, WAN, Internet, Group
  • Limiter la bande passante via GPO/Intune
  • Logs : Get-DeliveryOptimizationLog

IIS Performance & SSL

  • Compteurs clés : Web Service\Current Connections, ASP.NET\Requests/sec, W3SVC_W3WP\Requests/sec
  • Application Pools : recycling (mémoire, durée), worker process isolation
  • SSL/TLS : SNI (Server Name Indication) — un certificat par hostname sur même IP/port
  • TLS 1.3 : activé par défaut WS 2022 ; désactiver TLS 1.0/1.1 via SCHANNEL registry ou GPO
  • HTTP/2 : activé par défaut WS 2019+ — améliore les performances multi-requêtes

STORE Stockage

Storage Spaces Direct (S2D)

  • HCI : stockage local des nœuds agrégé en pool partagé (SDS)
  • Tiers : Cache (NVMe/SSD) + Capacity (HDD/SSD)
  • CSV (Cluster Shared Volumes) pour la haute disponibilité des VMs
  • Mirror (2/3 voies) ou Erasure Coding pour la résilience
  • Santé : Get-StoragePool | Get-StorageJob · Get-VirtualDisk | Select HealthStatus

Storage Replica

Modes de réplication

  • Synchrone : RPO=0, nécessite acquittement destination
  • Asynchrone : RPO > 0 (intervalles), meilleure perf sur WAN

Commandes clés

  • New-SRPartnership : créer la réplication
  • Get-SRGroup : statut des groupes
  • Test-SRTopology : valider avant déploiement

Storage Migration Service

  1. Inventorier les partages source (SMS Orchestrator)
  2. Transférer les données vers le serveur destination
  3. Cutover : transférer l'identité réseau (nom, IP) vers la destination
  4. L'ancien serveur change de nom/IP automatiquement
Idéal pour migrer depuis WS 2003/2008 vers WS 2019/2022 sans reconfigurer les clients

Quorum Failover Cluster

Modes de quorum

  • Node Majority : nombre impair de nœuds
  • Node + Disk Witness : disque partagé dédié
  • Node + File Share Witness : partage SMB (souvent recommandé)
  • Node + Cloud Witness : Azure Blob Storage (WS 2016+)

Validation & diagnostics

  • Test-Cluster -Node SRV01,SRV02
  • Get-ClusterNode : statut des nœuds
  • Get-ClusterResource : ressources du cluster
  • Event ID 1135 : nœud retiré du cluster

AVD (Azure Virtual Desktop)

  • Host Pools : Pooled (multi-session, WS 2019/2022) ou Personal (Win 10/11)
  • FSLogix : conteneurs de profils utilisateurs (VHD/VHDX sur Azure Files/NetApp)
  • Resize automatique avec Azure Virtual Desktop scaling plans
  • Intégration MFA via Conditional Access
  • Monitoring : Azure Monitor Workbooks for AVD

Server Core & Nano Server

Server Core

  • Interface graphique minimale (CLI/PowerShell)
  • Surface d'attaque réduite (~70% moins de patches)
  • Gestion via RSAT ou WAC
  • Peut installer des rôles AD DS, Hyper-V, File Server

Windows Admin Center (WAC)

  • Interface web pour gérer les serveurs Core
  • Extension Azure : Azure Network Adapter, Arc, Backup
  • Port 443 (HTTPS), déployé en Gateway ou Local
  • SSO avec Azure AD possible

AZURE Azure Hybride

Azure Arc

  • Arc-enabled Servers : gérer les serveurs on-prem comme des ressources Azure
  • Capacités : Azure Policy (Guest Config), Defender for Cloud, Azure Monitor, Extensions VM
  • Installation : script généré depuis Azure Portal, agent azcmagent
  • azcmagent check : vérifier la connectivité · azcmagent show : statut agent
  • Prérequis réseau : HTTPS sortant vers *.his.arc.azure.com, *.guestconfiguration.azure.com

Azure Update Manager

On-premises (WSUS)

  • Groupes d'ordinateurs, approbation manuelle/auto
  • Event ID 19 : update installé
  • Event ID 20 : échec installation
  • Nettoyage : WSUS Cleanup Wizard mensuel

Azure Update Manager

  • Gère Arc-enabled + VMs Azure
  • Maintenance Windows configurables
  • Patch orchestration : Customer Managed Schedule
  • Rapports de conformité intégrés

Azure Bastion & RDP Security

  • Azure Bastion : RDP/SSH via HTTPS (port 443) depuis le portail Azure — aucun port RDP exposé
  • Pas de VM Jump Box requise, pas de NSG pour RDP
  • On-premises : RD Gateway pour sécuriser l'accès RDP (HTTPS tunnel)
  • RDP hardening : Network Level Authentication (NLA) obligatoire, TLS 1.2+
  • Restricted Admin Mode : évite la transmission des credentials sur le réseau

MON Supervision & Diagnostic

Performance Monitor & Data Collector Sets

  • Créer un DCS (Data Collector Set) pour collecter automatiquement les compteurs sur la durée
  • Compteurs CPU : \Processor(_Total)\% Processor Time
  • Mémoire : \Memory\Available MBytes · \Memory\Pages/sec
  • Disque : \PhysicalDisk\Avg Disk Queue Length · \PhysicalDisk\Avg Disk sec/Transfer
  • Réseau : \Network Interface\Bytes Total/sec
  • OOM : Event ID 2004 dans System · poolmon.exe pour les fuites de pool

Supervision AD

  • repadmin /showrepl : afficher la réplication · repadmin /replsummary : résumé
  • dcdiag /test:replications /v : diagnostic complet
  • nltest /dsgetdc:domaine.local : trouver un DC disponible
  • Azure AD Connect Health : surveille la synchronisation, alertes dans Azure Portal

Azure Monitor & Log Analytics

  • Agent Azure Monitor (AMA) : remplace MMA/OMS (déprécié)
  • Data Collection Rules (DCR) : définir quels logs et compteurs collecter
  • KQL : SecurityEvent | where EventID == 4625 | summarize count() by Account
  • Alertes : métriques (seuil), logs (requête KQL), activité (Azure Activity Log)
  • Workbooks : tableaux de bord interactifs (AVD, VMs, Security)

PKI AD CS & Certificats

Hiérarchie PKI recommandée

Root CA (Offline)

  • Durée : 20 ans
  • Hors réseau (physiquement)
  • Auto-signé

Sub CA (Enterprise)

  • Durée : 10 ans
  • En ligne, sur réseau
  • Émet les certificats feuilles

Certificats feuilles

  • Durée : 1-2 ans
  • Utilisateurs, serveurs, code signing
  • CRL/OCSP vérifiable

Commandes AD CS essentielles

  • Publier Root CA dans AD : certutil -dspublish -f RootCA.crt RootCA
  • Déployer via GPO : Computer → Policies → Windows Settings → Security → Public Key → Trusted Root CAs
  • Révoquer un certificat : certutil -revoke <SerialNumber>
  • Publier CRL : certutil -crl
  • Vérifier la chaîne : certutil -verify -urlfetch certificat.crt

PS PowerShell DSC

Concepts clés DSC

Architecture

  • Configuration : script .ps1 déclarant l'état souhaité
  • MOF : fichier compilé (.mof) envoyé aux nœuds
  • LCM (Local Config Manager) : applique la configuration
  • Modes : Push (admin envoie) ou Pull (nœud récupère)

Commandes essentielles

  • Start-DscConfiguration -Path .\Config
  • Get-DscConfigurationStatus
  • Test-DscConfiguration : vérifier sans appliquer
  • Restore-DscConfiguration : revenir à l'état précédent
DSC vs GPO : DSC est idéal pour les configurations applicatives et les fichiers ; GPO reste supérieur pour la gestion des paramètres Windows et utilisateurs en domaine.
