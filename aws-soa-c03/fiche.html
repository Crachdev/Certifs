Monitoring · 22 %
📊 D1 — Monitoring, Logging & Remediation

CloudWatch — Les 4 piliers

Metrics

Métriques standard (EC2: CPUUtilization, NetworkIn, DiskReadOps…) + custom metrics via PutMetricData. Résolution : 1 min standard, 1 s (high resolution, coût +). Namespaces séparent les services.

Logs

Log Groups → Log Streams. Retention de 1 jour à 10 ans. Metric Filters créent des métriques depuis des patterns regex. CW Logs Insights : requêtes SQL-like. Export vers S3 ou Kinesis.

Alarms

États : OK / ALARM / INSUFFICIENT_DATA. Actions : SNS, Auto Scaling, EC2 (reboot/stop/terminate/recover). Composite Alarms = AND/OR d'alarmes simples (réduit les faux positifs).

Dashboards

Widgets cross-account et cross-région. Partageables via URL publique. Automatisables avec PutDashboard. Métriques, alarmes, logs, texte libre.

CloudWatch Agent — métriques système avancées

✅ L'agent CloudWatch est nécessaire pour les métriques non disponibles nativement sur EC2 : mémoire RAM utilisée, espace disque, swap, nombre de processus. Il envoie aussi des logs système (syslog, Windows Event Log). Installation via SSM Run Command recommandée.

CloudWatch Logs Insights — syntaxe clé

# Trouver les erreurs dans les logs Lambda
fields @timestamp, @message
| filter @message like /ERROR/
| sort @timestamp desc
| limit 50

# Latence p99 des requêtes API Gateway
fields @timestamp, @duration
| stats avg(@duration), pct(@duration, 99) by bin(5m)

# Erreurs 5xx groupées par path
fields httpMethod, path, status
| filter status >= 500
| stats count() by path
| sort count desc

CloudWatch Alarms — stratégies

Anomaly Detection

Machine learning sur l'historique de la métrique. Crée automatiquement une bande "normale". Utile pour les métriques avec saisonnalité (trafic web, charges par heure).

Composite Alarms

Combine plusieurs alarmes avec AND/OR. Ex: alerte seulement si CPU >80% ET mémoire >90%. Réduit les faux positifs = moins de bruit ops.

EC2 Recovery

Action d'alarme spéciale : recover redémarre l'instance sur nouvel hôte en conservant l'IP, les volumes EBS, le security group. Pour les pannes hardware silencieuses.

Missing Data

Traitement des données manquantes : notBreaching (défaut : OK), breaching (ALARM), ignore (garde état), missing (INSUFFICIENT_DATA).

AWS CloudTrail — Audit complet

Management Events

Toutes les opérations de contrôle (CreateBucket, RunInstances, PutPolicy…). Activés par défaut. Lecture et écriture séparables. 90 jours dans la console sans trail.

Data Events

Opérations sur les données (S3 GetObject/PutObject, Lambda Invoke). Désactivés par défaut car très volumineux. Activez par bucket/fonction cible.

Insights Events

Détecte les activités anormales : pic d'appels API, erreurs inhabituelles. ML sur l'historique. Coût supplémentaire. Utile pour la sécurité.

Log File Validation

Hash SHA-256 sur chaque fichier de log. Détecte la falsification. Obligatoire pour la compliance (PCI, SOX). Stocke dans S3 avec un fichier digest.

AWS X-Ray — distributed tracing

Traces & Segments

Trace = requête end-to-end. Segment = unité de travail (Lambda, EC2, service). Subsegments pour appels AWS SDK ou HTTP externes.

Sampling

Défaut : 5 % + 1 requête/s. Custom rules par service, URL, méthode. Réduit les coûts sans perdre la visibilité sur les anomalies.

Service Map

Carte visuelle des services, latences, taux d'erreur. Identifie les goulots d'étranglement dans les architectures microservices.

Intégrations

Lambda (auto avec layer), API Gateway, EC2 (daemon), ECS (sidecar). Active avec AWS_XRAY_DAEMON_ADDRESS.

Route 53 — politiques de routing

Simple

Un enregistrement → un ou plusieurs IPs (aléatoire). Pas de health check. Pour les environnements non critiques.

Failover

Primary actif, Secondary en standby. Health check sur Primary obligatoire. Basculement automatique si Primary fail. Actif-passif.

Latency

Route vers la région AWS avec la latence la plus faible pour l'utilisateur. Idéal pour les déploiements multi-région actifs.

Weighted

Distribue le trafic selon des poids (0-255). Ex: 90 % prod / 10 % canary. Poids 0 = aucun trafic (utile pour maintenance).

Geolocation

Route selon la localisation DNS de l'utilisateur (pays, continent). Conformité RGPD/réglementation locale. Toujours définir un "Default".

Geoproximity

Route vers la ressource géographiquement la plus proche avec bias ajustable. Nécessite Traffic Flow (payant).

AWS Backup — sauvegarde centralisée

Backup Plan

Règles de sauvegarde : fréquence, fenêtre, rétention, transition vers Backup Vault (cold storage). Supporte EC2, EBS, RDS, DynamoDB, EFS, S3, Storage Gateway.

Backup Vault

Coffre-fort chiffré pour stocker les recovery points. Vault Lock (WORM) = backups immuables même pour le root. Cross-account et cross-region copy.

vs Snapshots natifs

AWS Backup = gouvernance centralisée multi-services. Snapshots natifs EBS/RDS = flexibles mais non centralisés. Utiliser AWS Backup pour compliance et audit.

DynamoDB PITR

Point-In-Time Recovery : restauration à la seconde près sur les 35 derniers jours. Activé par table. Ne remplace pas les sauvegardes on-demand pour l'archivage long terme.

RDS — Haute disponibilité

Multi-AZ

Réplica synchrone dans une autre AZ. Failover auto en 60-120 s. Pour la haute disponibilité, pas pour la performance lecture. Même endpoint.

Read Replicas

Réplica asynchrone. Charge lectures (jusqu'à 5 replicas). Peut être promu en principal. Cross-région possible. Endpoint différent.

Aurora

MySQL/PostgreSQL compatible. 6 copies de données sur 3 AZs automatiquement. Failover <30 s. Aurora Global : RPO <1 s, RTO <1 min cross-région.

ElastiCache

Redis : persistence, pub/sub, structures complexes, cluster mode. Memcached : simple cache objet, multi-thread, pas de persistence. Redis pour tout nouveau projet.

S3 — Résilience et réplication

Versioning

Protège contre la suppression accidentelle. Delete marker = soft delete. MFA Delete = protection supplémentaire. Payant : toutes les versions stockées.

CRR / SRR

Cross-Region Replication : DR, réduction de latence. Same-Region Replication : conformité, copies de test. Versioning obligatoire source ET destination.

Classes de stockage

Standard > Standard-IA > One Zone-IA > Glacier Instant > Glacier Flexible > Glacier Deep Archive. Intelligent-Tiering gère les transitions automatiquement.

Object Lock

WORM (Write Once Read Many). Compliance mode : personne (y compris root) ne peut supprimer avant expiration. Governance mode : seul root peut outrepasser.

Deployment · 22 %
🚀 D3 — Deployment, Provisioning & Automation

AWS Systems Manager (SSM) — vue d'ensemble

Run Command

Exécute des commandes sur des fleets d'instances via tags sans SSH. Document AWS-RunShellScript. Sortie dans S3/CloudWatch Logs. Idempotent et auditable.

Session Manager

Accès shell sécurisé aux EC2 sans port 22, sans bastion. Log des sessions dans S3/CloudWatch. Basé sur IAM. Obligatoire pour la compliance Zero Trust.

Patch Manager

Patch Baseline : règles d'approbation (auto/manuel, sévérité). Maintenance Window : planifie l'exécution. Scan sans patch = audit. Patch + reboot = maintenance.

Automation

Runbooks SSM pour workflows complexes multi-étapes. Peut appeler Lambda, API AWS, scripts. Remédiation automatique déclenchée par Config/EventBridge.

Inventory

Collecte les métadonnées des instances (apps installées, configs réseau, registre Windows). Stocké dans S3 + interrogeable via Athena.

State Manager

Maintient les instances dans l'état défini (ex: antivirus toujours installé, config nginx). Association appliquée périodiquement ou en continu.

CloudFormation — fonctionnalités avancées

Change Sets

Prévisualise les modifications avant de les appliquer. Indique si une ressource sera remplacée (destructif) ou mise à jour en place. Toujours utiliser avant une update en production.

Drift Detection

Détecte les ressources modifiées manuellement hors CloudFormation. Utile pour la gouvernance. Ne remédie pas automatiquement : il faut re-déployer ou importer.

StackSets

Déploie des stacks dans plusieurs comptes/régions depuis un compte admin. Nécessite des rôles cross-account. Idéal pour les configurations multi-comptes AWS Organizations.

cfn-init & cfn-signal

cfn-init configure l'instance depuis metadata CFN. cfn-signal notifie CFN que le bootstrap est terminé. Obligatoire avec CreationPolicy pour éviter les timeouts prématurés.

Custom Resources

Lambda invoquée par CFN pour des ressources non natives (ex: vider un bucket S3 avant suppression, appeler une API externe lors du deploy).

Nested Stacks

Modularise les templates en sous-stacks réutilisables. Les outputs d'un stack enfant peuvent être utilisés par le parent. Idéal pour VPC, IAM, DB communs.

EC2 Image Builder & AMIs

Image Builder Pipeline

Crée des AMIs "golden" automatiquement. Étapes : Source AMI → Composants (install/configure) → Test → Distribution. Planifiable. Intègre SSM et Inspector pour la sécurité.

AMI Sharing

AMI partageables entre comptes AWS sans copier. AMI chiffrées : la clé KMS doit être partagée aussi. Copier l'AMI dans la région cible avant de lancer des instances.

ECS & Fargate

ECS EC2 : contrôle total des instances. Fargate : serverless, AWS gère l'infra. Task Definitions = configuration container. Services = running tasks avec ALB intégration.

ECR Lifecycle

Politiques de cycle de vie ECR : supprime automatiquement les images non taguées ou plus vieilles que N jours. Réduit les coûts de stockage. expire sur countNumber ou sinceImagePushed.

Security · 16 %
🔒 D4 — Security & Compliance

IAM — évaluation des permissions

Ordre d'évaluation : 1. Deny explicite (toujours gagne) → 2. SCP (Organizations) → 3. Resource policy → 4. Permission boundary → 5. IAM policy → 6. Session policy → Deny implicite par défaut.

Permission Boundaries

Plafond de permissions pour un rôle/user. Intersection avec les politiques IAM = permissions effectives. Permet la délégation sécurisée : un dev peut créer des rôles sans dépasser ses propres droits.

SCPs (Organizations)

Plafond pour tous les comptes de l'org. Bloquent même root. Approche "allow list" (autoriser explicitement) ou "deny list" (bloquer spécifiquement). Ne remplacent pas IAM.

IAM Identity Center

SSO centralisé pour tous les comptes AWS Organizations. Permission Sets = groupes de permissions appliqués à un compte. Intègre Active Directory, Okta, Azure AD via SAML 2.0.

IAM Access Analyzer

Détecte les ressources accessibles depuis l'extérieur de la zone de confiance (bucket S3 public, rôle assumable par un autre compte). Génère des findings actionnables.

AWS KMS — chiffrement

Types de clés

AWS-managed : gratuite, rotation auto 1 an, pas de contrôle. Customer-managed (CMK) : $1/mois, contrôle total, rotation configurable. Importée : votre propre matériel de clé.

Envelope Encryption

KMS chiffre la Data Key (DEK). La DEK chiffre les données. Réduit les appels KMS et les coûts. Pattern standard pour S3, EBS, RDS, Secrets Manager.

Key Policy

Obligatoire sur chaque CMK. Sans policy explicite, personne ne peut utiliser la clé. Toujours accorder l'accès au compte root (récupération d'urgence). IAM + Key Policy pour les services.

CloudHSM

HSM dédié (votre propre hardware). FIPS 140-2 Level 3. Vous gérez les clés entièrement. Pour les exigences de conformité strictes (finance, gouvernement). Plus cher que KMS.

AWS Config — conformité continue

Managed Rules

Règles prédéfinies par AWS : s3-bucket-public-read-prohibited, encrypted-volumes, iam-password-policy... Plus de 200 règles disponibles. Évaluation déclenchée par changement ou périodique.

Custom Rules

Lambda function qui évalue la conformité selon votre logique métier. Ex: vérifier que toutes les EC2 ont le tag "CostCenter" défini.

Remédiation auto

Associer un SSM Automation Runbook à une règle Config. Ex: règle s3-bucket-public-read-prohibited → Runbook AWS-DisableS3BucketPublicReadWrite.

Conformance Packs

Collection de règles Config + remédiations packagées. Templates disponibles : CIS, PCI-DSS, HIPAA, NIST. Déployable via CloudFormation StackSets multi-comptes.

ACM — Certificates Manager

✅ ACM fournit des certificats TLS gratuits pour ALB, CloudFront, API Gateway, Elastic Beanstalk. Renouvellement automatique. Important : les certificats ACM ne peuvent pas être exportés — ils sont liés aux services AWS. Pour un certificat sur EC2 direct ou une app on-premise, utiliser un CA privé ACM (payant) ou importer depuis Let's Encrypt.

Networking · 18 %
🌐 D5 — Networking & Content Delivery

VPC — fondamentaux

Subnets publics vs privés

Public = route table a une route vers l'IGW. Privé = pas de route directe vers Internet. Les instances EC2 dans un subnet public ont besoin d'une IP publique/Elastic IP.

NAT Gateway vs NAT Instance

NAT Gateway : AWS-managed, haute dispo par AZ, jusqu'à 100 Gbps, payant. NAT Instance : EC2 que vous gérez, moins cher pour faible trafic, single-AZ (SPOF).

Security Groups vs NACLs

SG : stateful (réponse auto), appliqué à l'interface réseau, only allow. NACL : stateless (règles IN et OUT séparées), appliqué au subnet, allow ET deny.

VPC Flow Logs

Capture le trafic réseau (IP src/dst, port, protocole, action ACCEPT/REJECT). Vers CloudWatch Logs, S3 ou Kinesis. Utile pour le troubleshooting et la conformité.

VPC Endpoints

Connectivité hybride et multi-VPC

VPC Peering

Connexion directe entre deux VPCs (même compte ou cross-account, cross-région). Non transitif : A↔B et B↔C ne permettent pas A↔C. Pas de CIDR overlap.

Transit Gateway (TGW)

Hub centralisé pour connecter des VPCs, VPNs, Direct Connect. Transitif. Route Tables par attachment. Idéal pour architectures hub-and-spoke avec beaucoup de VPCs.

Site-to-Site VPN

IPSec chiffré sur Internet public. Customer Gateway (votre routeur) + Virtual Private Gateway (AWS). Redondant : 2 tunnels par défaut. Bande passante limitée.

Direct Connect

Connexion physique dédiée (1G, 10G, 100G). Latence prévisible, bande passante garantie. Pas de chiffrement natif → associer avec VPN pour la sécurité. Délai de déploiement : semaines.

PrivateLink

Expose un service (votre NLB) à d'autres VPCs via un Interface Endpoint. Unidirectionnel, sécurisé, pas de peering nécessaire. Pattern SaaS multi-tenant.

Route 53 Resolver

Inbound Endpoints : permettent aux serveurs on-premise de résoudre les noms AWS. Outbound Endpoints : permettent aux instances AWS de résoudre les noms on-premise (AD, DNS interne).

CloudFront — distribution de contenu

Origins & Behaviors

Origins : S3, ALB, EC2, Custom HTTP. Behaviors : règles de cache par path pattern. Cache Control Headers ou TTL CloudFront. Invalidation manuelle = coût $0.005/path.

Signed URLs / Cookies

Signed URL : accès à un seul fichier, avec expiration. Signed Cookie : accès à plusieurs fichiers, moins de changements côté client. Toujours utiliser pour le contenu premium/privé.

OAC (Origin Access Control)

Remplace OAI. Permet à CloudFront d'accéder à S3 privé sans rendre le bucket public. Supporte KMS, SSE-S3, POST/PUT. Toujours utiliser OAC pour S3 + CloudFront.

WAF + CloudFront

AWS WAF sur CloudFront = protection globale (tous les PoP). Rate-based rules (DDoS L7), IP sets, managed rule groups (OWASP Top 10, bot protection). Logs vers Kinesis Firehose.

⚠️ Pièges & astuces
Pièges courants à l'examen SOA-C03

Mémoire RAM ≠ CloudWatch natif

CloudWatch ne collecte PAS la mémoire RAM par défaut. Il faut installer l'agent CloudWatch. Question piège classique : "pourquoi je ne vois pas l'utilisation mémoire ?"

Multi-AZ ≠ Read Replica

Multi-AZ = haute dispo, failover synchrone, même endpoint. Read Replica = scalabilité lecture, réplication asynchrone, endpoint différent. L'exam teste souvent cette distinction.

Security Group = stateful

Une réponse à une connexion entrante autorisée EST automatiquement autorisée en sortie. Les NACLs sont stateless : vous devez créer des règles IN et OUT séparément.

VPC Peering non transitif

A↔B et B↔C ne permettent PAS A↔C. Pour la transitivité, utiliser Transit Gateway. Le VPC Peering fonctionne cross-région et cross-compte.

Gateway Endpoint gratuit

S3 et DynamoDB via Gateway Endpoint = gratuit. Tous les autres services (SSM, EC2 API, Secrets Manager) nécessitent un Interface Endpoint (payant). Dans la plupart des architectures coût-optimisées, on combine les deux.

Secrets Manager vs Parameter Store

Secrets Manager = rotation automatique + coût ($0.40/mois). Parameter Store Standard = gratuit, pas de rotation. SecureString = chiffré KMS mais pas de rotation auto. Pour les DB passwords : Secrets Manager.

CloudTrail délai ~15 minutes

CloudTrail n'est PAS temps réel. Pour des réactions immédiates à des événements de sécurité, utiliser EventBridge (quasi temps réel). CloudTrail pour l'audit historique.

SCP bloque root

Les Service Control Policies d'AWS Organizations bloquent MÊME le compte root du compte membre. C'est la seule façon de restreindre root sur un sous-compte.

cfn-signal est obligatoire

Sans cfn-signal dans le UserData, CloudFormation considère l'instance prête dès sa création (avant que l'app soit démarrée). Utiliser CreationPolicy + cfn-signal pour attendre le bootstrap réel.

ACM non exportable

Les certificats ACM ne peuvent pas être exportés ou utilisés directement sur EC2/on-premise. Utiliser ACM Private CA ou importer un certificat Let's Encrypt pour ces cas.

NAT Gateway par AZ

Pour la haute disponibilité, créer un NAT Gateway par AZ et configurer les routes de chaque subnet privé vers son propre NAT. Un seul NAT Gateway = SPOF.

ALB vs NLB — IP statique

L'ALB n'a pas d'IP fixe (noms DNS). Pour une IP statique/Elastic IP, utiliser NLB. Cas concret : whitelisting IP firewall client = NLB obligatoire.
