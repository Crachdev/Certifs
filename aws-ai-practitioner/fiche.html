L'examen AIF-C01

Profil viséNon-technique : décideurs, chefs de projet, professionnels métiers qui souhaitent comprendre les capacités IA/ML d'AWS et l'IA générative. Valable 3 ans.

Format

  • 65 questions (dont 15 non notées)
  • 90 minutes
  • Score passage : 700/1000
  • QCM simple et multiple, classement, correspondance

Accès

  • Pearson VUE (en centre ou en ligne)
  • $100 USD
  • Recommandé : 6 mois exp. AWS + connaissance IA/ML basique

Ressources officielles

  • aws.amazon.com/certification/certified-ai-practitioner
  • AWS Skill Builder (cours gratuits)
  • AWS Well-Architected Framework - ML Lens

Tâches hors scope (ne pas étudier)

⚠️ Hors examen AIF-C01 — Ces sujets ne seront pas évalués : codage de modèles IA/ML, ingénierie des données et des features, réglage des hyperparamètres, création de pipelines IA/ML, analyses mathématiques et statistiques avancées.

Fondamentaux IA et ML

🧠 Domain 1 · 20%

Types d'apprentissage ML

ParadigmeDescriptionExemples
SuperviséDonnées labelisées. Apprend la correspondance entrée → sortie.Classification (spam/pas spam), régression (prédiction de prix)
Non superviséDonnées sans labels. Trouve des patterns cachés.Clustering (segmentation clients), réduction de dimension
Par renforcementAgent qui apprend par essai/erreur avec récompenses.Jeux, robotique, optimisation
Semi-superviséMélange : quelques données labelisées + beaucoup non labelisées.Reconnaissance vocale, NLP
Auto-superviséCrée ses propres labels à partir des données. Base des LLMs.Transformer, GPT, BERT

Concepts ML fondamentaux

FeatureVariable d'entrée du modèle. Feature engineering = transformer les données brutes en features utiles.
OverfittingModèle trop adapté aux données d'entraînement, mauvaise généralisation. Solution : régularisation, plus de données, dropout.
UnderfittingModèle trop simple, ne capture pas les patterns. Solution : modèle plus complexe, plus de features.
Biais / VarianceBiais élevé = underfitting. Variance élevée = overfitting. Trouver le bon équilibre (bias-variance tradeoff).
Train / Validation / TestSplit classique : 70% train, 15% validation (tuning), 15% test (évaluation finale).
MLOpsDevOps pour le ML : expérimentation, processus reproductibles, mise à l'échelle, surveillance des modèles, réentraînement. Gestion de la dette technique.
IA agentiqueSystèmes d'IA qui planifient et agissent de manière autonome. Multi-agents, orchestration de flux de travail, gestion de la mémoire, utilisation d'outils. MCP (Model Context Protocol) = protocole pour connecter les agents à des systèmes externes.

Types d'inférence

Temps réelRéponse immédiate, faible latence. Ex : chatbot, recommandation live.
Par lots (batch)Traitement différé de grandes quantités. Ex : analyse nocturne de logs.
AsynchroneL'appelant n'attend pas la réponse. Ex : génération de rapport en arrière-plan.
ServerlessInférence sans gestion d'instances, facturation à l'appel. Ex : Bedrock API.

Types de données ML

Structurées (tables SQL) Semi-structurées (JSON, XML) Non structurées (images, audio, texte) Séries temporelles (IoT, métriques)

03

Fondamentaux de l'IA Générative

✨ Domain 2 · 24%

Concepts clés

Foundation Model (FM)Grand modèle pré-entraîné sur des données massives. Peut être adapté à de nombreuses tâches. Ex : Claude, Llama, Titan.
LLM (Large Language Model)FM spécialisé dans le texte. Génère du texte cohérent basé sur des milliards de paramètres.
TokenUnité de traitement du texte (~0.75 mots). La longueur du contexte = fenêtre de tokens (context window). 1K tokens ≈ 750 mots.
EmbeddingsReprésentation vectorielle (numérique) du texte. Permet de mesurer la similarité sémantique. Base des moteurs de recherche IA.
TemperatureContrôle la créativité/variabilité des sorties. 0 = déterministe (reproductible), 1 = créatif/aléatoire.
HallucinationLe modèle génère des informations fausses mais confiantes. Risque clé des LLMs. Atténué par RAG, grounding.
MultimodalModèle traitant plusieurs types de données : texte, images, audio, vidéo. Ex : Amazon Nova.

Amazon Bedrock

💡 Service clé AIF-C01 Amazon Bedrock = API unifiée pour accéder à des FMs via AWS sans gérer d'infrastructure. Modèles disponibles : Anthropic Claude, Meta Llama, Mistral, Amazon Titan, Stability AI, Cohere. Fonctionnalités : Knowledge Bases (RAG), Agents, Guardrails, Model Evaluation, Prompt Flows.

Cycle de vie d'un FM

ÉtapesSélection des données → Sélection du modèle → Pré-entraînement → Peaufinage (fine-tuning) → Évaluation → Déploiement → Feedbacks → Réentraînement.
Tarification par tokenCoût calculé en tokens (input + output). Plus la fenêtre de contexte est grande, plus c'est coûteux. Mise en cache des invites (prompt caching) réduit les coûts sur les prompts répétitifs.

Amazon SageMaker JumpStart

Hub de modèles pré-entraînés déployables en 1 clic. FMs open-source : Llama, Mistral. Différent de Bedrock : JumpStart déploie dans votre compte (contrôle total), Bedrock est serverless (API managée).

Prompt Engineering

TechniqueDescription
Zero-shotInstruction directe sans exemples. Simple, peut manquer de précision.
Few-shot1–5 exemples dans le prompt. Guide le format et le style de réponse.
Chain-of-thought (CoT)Demander au modèle de "penser étape par étape". Améliore le raisonnement.
System promptInstructions permanentes données au modèle (persona, règles, format).
Prompt templateStructure réutilisable avec des variables. Utilisé dans Bedrock Prompt Flows.
Invites négativesIndiquer ce que le modèle NE doit PAS faire ou inclure. Réduit les sorties indésirables.

Risques du prompt engineering

RisqueDescription
InjectionInput malveillant pour contourner les instructions du système.
EmpoisonnementContaminer les données d'entraînement/contexte pour manipuler les sorties.
DétournementFaire exécuter des actions non prévues par le concepteur.
Débridage (jailbreak)Contourner les garde-fous de sécurité du modèle.
ExpositionFuite d'informations sensibles contenues dans le prompt système.
💡 Bedrock Prompt Management — Service pour versionner, gérer et optimiser les invites. Permet de tester, comparer et déployer des versions de prompts en production.

Applications des Foundation Models

🔧 Domain 3 · 28%

Critères de sélection d'un FM

Critères techniquesCoût, latence, modalité (texte/image/audio), taille du contexte (input/output), capacités multilingues, complexité du modèle.
Critères businessConformité réglementaire, personnalisation possible, mise en cache des invites (prompt caching), disponibilité régionale.
Approches de personnalisationDu moins au plus coûteux : RAG (données externes) → Apprentissage en contexte (few-shot) → Fine-tuning → Pré-entraînement continu → Distillation (compresser un grand modèle vers un plus petit).

RAG — Retrieval Augmented Generation

DéfinitionAugmenter le LLM avec des données externes récupérées en temps réel. Évite l'hallucination et le knowledge cutoff.
ArchitectureDocuments → Chunks → Embeddings → Vector Store → Requête → Recherche sémantique → Contexte → LLM → Réponse.
Amazon Bedrock Knowledge BasesService RAG managé. Sources : S3, Confluence, SharePoint, Salesforce. Vector store : OpenSearch, Aurora, Pinecone, Redis.
Vector DatabaseBDD spécialisée pour stocker et rechercher des embeddings. Recherche par similarité cosinus. Ex : OpenSearch, Pinecone.

Fine-tuning des modèles

TechniqueDescriptionQuand utiliser
Fine-tuning completRéentraîner tous les paramètres du modèle sur des données spécifiques.Domaine très spécifique, données suffisantes (1K+)
PEFT / LoRAAdapter seulement une petite fraction des paramètres. Efficace.Ressources limitées, résultats proches du full fine-tuning
RLHFReinforcement Learning from Human Feedback. Aligne le modèle sur les préférences humaines.Amélioration comportement, sécurité, utilité
Continued pre-trainingContinuer l'entraînement sur des données de domaine non-labelisées.Intégrer vocabulaire/concepts d'un domaine (médical, juridique)

Évaluation des modèles génératifs

ROUGE

  • Recall-Oriented Understudy for Gisting Evaluation
  • Compare résumés générés vs référence
  • ROUGE-N : chevauchement n-grammes

BLEU

  • Bilingual Evaluation Understudy
  • Score de traduction automatique
  • Chevauchement avec traduction de référence

BERTScore

  • Compare les embeddings BERT
  • Sémantique, pas juste mots-clés
  • Plus précis que ROUGE/BLEU

LLM-juge

  • Un LLM évalue les sorties d'un autre LLM
  • Évaluation humaine à l'échelle
  • Utilisé dans Bedrock Model Evaluation

Agents IA (Amazon Bedrock Agents)

AgentLLM + outils (APIs, bases de données, code) + mémoire. Capable d'agir sur l'environnement pour accomplir des tâches complexes.
Action GroupsAPIs définies que l'agent peut appeler (Lambda fonctions). Le modèle décide quand appeler quel outil.
ReAct patternReasoning + Acting. L'agent alterne réflexion et action jusqu'à résoudre la tâche.

Types de biais en ML

Biais de donnéesDonnées d'entraînement non représentatives ou historiquement biaisées. Entraîne des prédictions discriminatoires.
Biais algorithmiqueLe modèle amplifie les patterns biaisés présents dans les données.
Data driftLes données de production diffèrent des données d'entraînement. Dégrade les performances au fil du temps.
Concept driftLa relation entre features et labels change (ex : comportements clients post-COVID).

Bedrock Guardrails

Filtres de contenu pour les applications Bedrock : blocage de contenu nuisible, toxique, discriminatoire. Filtrage de contenu sensible (PII). Hallucination detection. Grounding check : vérifier que les réponses sont fondées sur les sources fournies.

Risques propriété intellectuelle

⚠️ Risques légauxLes FMs peuvent mémoriser et reproduire des données d'entraînement protégées par copyright. Utiliser des données d'entraînement licenciées. AWS indemnisation copyright disponible pour certains services Bedrock.

Qualité des données d'entraînement

Caractéristiques clésInclusivité, diversité, représentativité, équilibre des classes. Des données biaisées produisent des modèles biaisés.
DurabilitéPréférer des modèles plus petits et efficaces quand c'est possible. L'entraînement de grands modèles a un impact environnemental (consommation énergétique).
Design centré humainMécanismes de feedback utilisateurs, transparence des décisions IA, possibilité de contestation. L'humain doit pouvoir comprendre et corriger les décisions du modèle.

Pièges classiques

  • Bedrock ≠ SageMaker : Bedrock = API serverless pour FMs pre-built (pas de gestion infra). SageMaker = entraîner et déployer VOS propres modèles (plus de contrôle, plus complexe).
  • SageMaker JumpStart ≠ Bedrock : JumpStart déploie le modèle dans votre infrastructure (coût EC2). Bedrock est serverless (pay-per-token, pas de gestion d'instances).
  • RAG ≠ Fine-tuning : RAG enrichit les prompts avec des données externes (temps réel). Fine-tuning modifie les poids du modèle (entraînement). RAG est plus flexible et moins coûteux pour des données changeantes.
  • Precision vs Recall : Precision = parmi ce qu'on prédit positif, combien est vrai. Recall = parmi tous les vrais positifs, combien on en trouve. F1 = équilibre entre les deux.
  • Temperature 0 ≠ meilleure qualité : Temperature 0 = déterministe (reproductible). Pas forcément meilleur pour tout. Résumés et faits = faible température. Créativité = haute température.
  • Tokens ≠ mots : 1 token ≈ 4 caractères ou 0.75 mots. "ChatGPT" = 1 token, mais "tokenization" peut être 2-3 tokens. Coût et limite de contexte calculés en tokens.
  • Data drift ≠ Concept drift : Data drift = distribution des données change. Concept drift = relation features-labels change. Les deux dégradent les modèles en production.
  • Prompt Injection ≠ SQL Injection : Prompt Injection = manipulation d'un LLM via son input pour ignorer ses instructions. Spécifique aux LLMs.
  • ROUGE pour résumés, BLEU pour traductions : ROUGE mesure le chevauchement pour les résumés. BLEU mesure la qualité de traduction. Les deux sont basés sur les n-grammes.

💡 Kiro & Strands Agents — Nouveaux services 2025/2026Kiro et Strands Agents sont des ajouts récents à l'écosystème AWS IA, reflétant la tendance agentic AI. L'examen AIF-C01 mis à jour les inclut comme services in-scope. Retenir : Kiro = IDE IA, Strands = framework agents open-source Python.

Coûts et gouvernance financière IA

AWS BudgetsDéfinir des seuils d'alerte pour les dépenses Bedrock, SageMaker, EC2 (GPU). Alertes automatiques par email/SNS quand les coûts dépassent les budgets. Essentiel pour contrôler les dépenses IA génératives (facturation par token).
AWS Cost ExplorerAnalyser et visualiser les coûts IA. Identifier quels modèles Bedrock ou endpoints SageMaker sont les plus coûteux. Prévoir les dépenses futures. Rightsizing : dimensionner correctement les ressources ML.

Sécurité complémentaire

AWS Secrets ManagerStocker et rotation automatique des clés API pour les services IA tiers (OpenAI, Anthropic, etc.) ou les tokens d'accès aux datasets. Ne jamais hardcoder des credentials dans le code ML.
Amazon CloudFrontCDN pour distribuer globalement les applications IA à faible latence. Mettre en cache les réponses statiques. Protéger les endpoints d'API d'inférence (AWS WAF intégré).
