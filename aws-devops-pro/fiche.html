SDLC Automation · 22 %
SDLC Automation — CI/CD

Les 4 services Code*

CodeCommit

Git managé AWS. Triggers sur push : Lambda, SNS. Intégration IAM pour les permissions par branche/repo.

CodeBuild

Build serverless. Lit le buildspec.yml. Phases : install → pre_build → build → post_build. Supporte Docker, ECR push, rapports de tests.

CodeDeploy

Déploiement sur EC2, Lambda, ECS. Strategies : AllAtOnce, HalfAtATime, OneAtATime, Canary, Linear. Rollback auto sur alarme.

CodePipeline

Orchestrateur CI/CD. Stages : Source → Build → Test → Deploy. Supporte approbations manuelles, intégrations GitHub, Jenkins, CodeBuild, CodeDeploy.

buildspec.yml — structure

version: 0.2
phases:
  install:
    runtime-versions:
      nodejs: 18
    commands:
      - npm ci
  pre_build:
    commands:
      - # Login ECR, tests unitaires
      - aws ecr get-login-password | docker login --username AWS ...
  build:
    commands:
      - docker build -t my-app:$CODEBUILD_RESOLVED_SOURCE_VERSION .
      - docker push $ECR_URI:$CODEBUILD_RESOLVED_SOURCE_VERSION
  post_build:
    commands:
      - # Générer imagedefinitions.json pour ECS deploy
      - printf '[{"name":"app","imageUri":"%s"}]' $ECR_URI > imagedefinitions.json
artifacts:
  files:
    - imagedefinitions.json

Configuration & IaC · 17 %
Configuration & Infrastructure as Code

CloudFormation — fonctionnalités avancées

StackSets

Déploie des stacks dans plusieurs comptes/régions depuis un compte admin. Nécessite des rôles cross-account dédiés.

ChangeSets

Prévisualise les modifications avant de les appliquer. Permet de valider l'impact (remplacement ou update en place).

Drift Detection

Détecte les ressources modifiées manuellement hors CloudFormation. Utile pour la gouvernance et la compliance.

Custom Resources

Lambda invoquée par CloudFormation pour des ressources non natives (ex: vider un bucket S3 avant suppression).

cfn-init & cfn-signal

cfn-init configure l'instance depuis les metadata CFN. cfn-signal notifie CFN que le bootstrap est terminé (obligatoire avec CreationPolicy).

Nested Stacks

Modularise les templates en sous-stacks réutilisables. Idéal pour les modules VPC, IAM, DB communs entre projets.

CloudFormation CLI — dépannage

# Voir les events (trouver les erreurs de création)
aws cloudformation describe-stack-events \
  --stack-name my-app-prod \
  --query 'StackEvents[?ResourceStatus==`CREATE_FAILED`]'

# Ressources d'un stack
aws cloudformation list-stack-resources \
  --stack-name my-app-prod

# Drift detection
aws cloudformation detect-stack-drift --stack-name my-app-prod

SSM — Systems Manager

Parameter Store

Stockage de configs et secrets. Standard (gratuit) vs Advanced. SecureString avec KMS. Hiérarchie /app/env/param.

Secrets Manager

Rotation automatique (Lambda), coût $0.40/secret/mois. Idéal pour les credentials DB, API keys avec expiration.

Session Manager

Accès shell sécurisé aux EC2 sans SSH, sans port 22, sans bastion. Log des sessions dans S3/CloudWatch.

Run Command

Exécute des commandes sur des fleets d'instances via tags. Document AWS-RunShellScript. Sans SSH.

Patch Manager

Automatise les patchs OS sur EC2. Patch Baseline définit les règles. Maintenance Window planifie l'exécution.

Automation

Runbooks SSM pour des workflows complexes multi-étapes. Remédiation automatique déclenché par Config/EventBridge.

Security & Compliance · 17 %
Security & Compliance

IAM avancé

Permissions Boundaries

Plafond des permissions qu'un rôle/user peut avoir. Ne remplace pas IAM : les deux s'appliquent (intersection). Délégation sécurisée.

SCP (Organizations)

Service Control Policies : définissent le maximum de permissions pour tout compte de l'org. Même le root est limité.

IAM Roles Anywhere

Permet aux workloads on-premise d'assumer des rôles IAM via certificats X.509. Pas besoin de clés d'accès statiques.

ABAC

Attribute-Based Access Control : contrôle d'accès basé sur des tags (ex: accès aux ressources avec le même tag dept:finance).

AWS Config — conformité continue

# Config rule : S3 bucket public read interdit
aws configservice put-config-rule \
  --config-rule '{
    "ConfigRuleName": "s3-bucket-public-read-prohibited",
    "Source": {
      "Owner": "AWS",
      "SourceIdentifier": "S3_BUCKET_PUBLIC_READ_PROHIBITED"
    }
  }'

# Remédiation auto via SSM Automation
aws configservice put-remediation-configurations \
  --remediation-configurations '[{
    "ConfigRuleName": "s3-bucket-public-read-prohibited",
    "TargetType": "SSM_DOCUMENT",
    "TargetId": "AWS-DisableS3BucketPublicReadWrite",
    "Automatic": true
  }]'

Chiffrement

KMS CMK

Customer Managed Key : contrôle total (rotation, policy, audit). Key policy + IAM pour l'accès. CloudTrail log tous les usages.

Envelope Encryption

KMS chiffre la Data Key, la Data Key chiffre les données. Réduit les appels KMS et les coûts. Pattern standard pour S3, EBS, RDS.

ACM

AWS Certificate Manager : TLS gratuit pour ALB, CloudFront, API GW. Renouvellement automatique. Pas d'export pour ALB (sécurité).

Secrets Manager

Rotation automatique des secrets via Lambda. Supporte RDS, Redshift, DocumentDB nativement. Versionning et audit CloudTrail.

Monitoring & Logging · 15 %
Monitoring & Logging

CloudWatch — 4 piliers

Metrics

Métriques standard (CPU, NetworkIn…) + custom metrics via PutMetricData. Résolution 1s (high resolution) ou 1 min. Namespaces.

Logs

Log Groups → Log Streams. Metric Filters créent des métriques depuis des patterns de logs. Insights pour requêtes. Retention configurable.

Alarms

États : OK / ALARM / INSUFFICIENT_DATA. Actions : SNS, Auto Scaling, EC2. Composite Alarms (AND/OR) pour réduire le bruit.

Dashboards

Widgets cross-account et cross-region. Métriques, alarmes, logs. Partageable via URL publique. Automatisable avec PutDashboard.

CloudWatch Logs — CLI

# Lire les derniers logs d'un groupe
aws logs tail /aws/lambda/my-function --follow

# Requête CloudWatch Insights
aws logs start-query \
  --log-group-name /app/production \
  --start-time $(date -d '1 hour ago' +%s) \
  --end-time $(date +%s) \
  --query-string 'fields @timestamp, @message | filter @message like /ERROR/ | sort @timestamp desc | limit 20'

# Exporter des logs vers S3 (analytique)
aws logs create-export-task \
  --log-group-name /app/production \
  --from 1699900000000 \
  --to 1699986400000 \
  --destination my-logs-bucket

AWS X-Ray — Distributed Tracing

Traces & Segments

Une trace = requête end-to-end. Segments = une unité de travail (Lambda, EC2, service). Subsegments pour les appels AWS SDK ou HTTP.

Service Map

Carte visuelle des services et leurs latences/erreurs. Identifie les goulots d'étranglement et les cascades d'erreurs dans les architectures microservices.

Sampling

Pour réduire les coûts : rule par défaut = 5 % des requêtes + 1/s. Sampling rules custom par service, path, méthode HTTP.

Groups & Insights

Filtres de traces pour alerter sur des anomalies (latence anormale, taux d'erreur élevé). Intègre CloudWatch pour les alarmes.

CloudTrail — Audit des actions API

✅ CloudTrail enregistre toutes les API calls (console + CLI + SDK). Trail multi-région obligatoire pour la compliance. Log File Validation (hash SHA-256) garantit l'intégrité. Envoie vers S3 (long terme) + CloudWatch Logs (temps réel) + EventBridge (réaction).
⚠️ CloudTrail a un délai de ~15 minutes. Pour une réponse en temps réel aux événements de sécurité, utiliser EventBridge (quasi temps réel) plutôt que CloudTrail directement.

Resilient Cloud Solutions · 15 %
Resilient Cloud Solutions

Auto Scaling Groups (ASG)

Target Tracking

Maintient une métrique cible (ex: 50 % CPU). AWS gère automatiquement scale-out et scale-in. La politique la plus simple et recommandée.

Step Scaling

Actions par paliers selon l'ampleur de l'alarme. Ex: +2 instances si CPU 60-80 %, +4 si CPU >80 %. Plus fine que simple scaling.

Scheduled Scaling

Montée en charge prévisible (black friday, horaires bureau). Définit min/max/desired à un moment précis ou en cron.

Predictive Scaling

Machine learning analyse l'historique et anticipe. Combine avec reactive scaling. Réduit la latence de démarrage grâce à l'anticipation.

RDS — Haute disponibilité

Multi-AZ

Réplica synchrone dans une autre AZ. Failover automatique en 60-120s. Pour la haute disponibilité, pas pour la performance lecture.

Read Replicas

Réplica asynchrone pour décharger les lectures. Peut être promu en instance principale. Cross-region possible. Pour la scalabilité lecture.

Aurora Global Database

Réplication cross-région en moins d'1 seconde. RPO <1s, RTO <1min. Idéal pour les applications mondiales et la DR active.

RDS Proxy

Pool de connexions entre Lambda/ECS et RDS. Réduit les connexions directes (problème classique Lambda). Failover transparent.

Incident & Event Response · 14 %
Incident & Event Response

EventBridge — le hub d'événements AWS

Event Bus

Default (services AWS), Custom (apps), Partner (SaaS). Les règles filtrent les événements et routent vers des targets (Lambda, SQS, Step Functions, SNS…).

Event Rules

Pattern matching sur les attributs d'un event JSON. Ex: EC2 state-change → {"source":["aws.ec2"],"detail-type":["EC2 Instance State-change Notification"]}.

Scheduled Rules

Cron ou rate expression pour déclencher des workflows périodiques. Remplace CloudWatch Events (même service, nouveau nom).

Pipes

Connexion point-à-point source → enrichissement → target. Source : SQS, DynamoDB Streams, Kinesis. Filtre et enrichit sans code Lambda intermédiaire.

Pattern : remédiation automatique avec Config + SSM

# Flow : Config détecte une non-conformité
#        → EventBridge reçoit l'event Config
#        → déclenche SSM Automation Runbook
#        → remédie automatiquement

# EventBridge Rule :
{
  "source": ["aws.config"],
  "detail-type": ["Config Rules Compliance Change"],
  "detail": {
    "configRuleName": ["s3-bucket-public-read-prohibited"],
    "newEvaluationResult": {
      "complianceType": ["NON_COMPLIANT"]
    }
  }
}
# Target : SSM Automation avec AWS-DisableS3BucketPublicReadWrite

Step Functions — orchestration

Standard Workflows

Jusqu'à 1 an d'exécution. Exactement une fois. Idéal pour les workflows métier longs (commandes, approbations humaines). Visible dans la console.

Express Workflows

Jusqu'à 5 minutes. Au moins une fois. Haute performance (100k/s). Pour IoT, traitement de données en masse. Moins cher.

Parallel & Map

Parallel : exécute plusieurs branches en parallèle. Map : itère sur un tableau (traitement batch). Les deux attendent la complétion avant de continuer.

Wait for Callback

Workflow pause et envoie un token. Reprend quand un service externe appelle SendTaskSuccess. Pattern pour les approbations humaines ou APIs externes.

# Créer une alarme CPU

  --alarm-name HighCPU \
  --metric-name CPUUtilization \
  --namespace AWS/EC2 \
  --dimensions Name=AutoScalingGroupName,Value=my-asg \
  --statistic Average \
  --period 60 \
  --threshold 80 \
  --comparison-operator GreaterThanOrEqualToThreshold \
  --evaluation-periods 2 \
  --alarm-actions arn:aws:sns:us-east-1:123:alerts

# Mettre une alarme en état ALARM (test)
aws cloudwatch set-alarm-state \
  --alarm-name HighCPU \
  --state-value ALARM \
  --state-reason "Test"

⚠️ Pièges & astuces
Pièges courants à l'examen DOP-C02

CodeDeploy ≠ CodePipeline

CodeDeploy = outil de déploiement (EC2/Lambda/ECS). CodePipeline = orchestrateur CI/CD qui peut appeler CodeDeploy. Ne pas les confondre dans les scénarios.

Multi-AZ ≠ Read Replica

Multi-AZ = haute disponibilité (failover auto, réplica synchrone). Read Replica = scalabilité lecture (réplica asynchrone). L'exam teste souvent cette distinction.

CloudTrail délai 15 min

CloudTrail ne convient pas pour des alertes de sécurité immédiates. Utiliser EventBridge (quasi temps réel) + GuardDuty pour détecter et réagir instantanément.

Parameter Store vs Secrets Manager

Secrets Manager = rotation automatique + coût ($0.40/secret/mois). Parameter Store Standard = gratuit, pas de rotation auto. SecureString = KMS mais pas de rotation.

SCP ne remplace pas IAM

Les SCP (Organizations) définissent le plafond des permissions. IAM doit toujours accorder explicitement les droits. Les deux s'appliquent (intersection).

Blue/Green sur Lambda

Pour Lambda, utiliser les alias et la traffic shifting (Canary/Linear) via CodeDeploy. Les CloudWatch Alarms déclenchent le rollback automatique si erreurs.

cfn-signal obligatoire

Sans cfn-signal dans le UserData, CloudFormation considère l'instance prête dès sa création (pas après bootstrap). Utiliser CreationPolicy + cfn-signal pour attendre réellement.

EventBridge ≠ SNS pour l'automation

Pour réagir aux événements AWS (Config, GuardDuty, CodePipeline), EventBridge est le bon choix. SNS est mieux pour les notifications humaines (email, SMS).

RDS Proxy pour Lambda

Lambda peut créer des milliers de connexions RDS simultanées lors du scale. RDS Proxy pool les connexions. Toujours proposer RDS Proxy quand Lambda + RDS.

StackSets nécessite confiance

StackSets cross-account nécessite un rôle AWSCloudFormationStackSetAdministrationRole dans le compte admin et AWSCloudFormationStackSetExecutionRole dans les cibles.
