SDLC Automation · 22 %

SDLC Automation — CI/CD

CodeCommit, CodeBuild, CodeDeploy, CodePipeline — le cœur du DevOps AWS

Les 4 services Code*

CodeCommit

Dépôt Git managé AWS. Intègre IAM pour les accès, SNS/EventBridge pour les triggers. Supporte les hooks Git. Alternative à GitHub/GitLab dans l'écosystème AWS.

CodeBuild

Build serveur managé (pas d'infra à gérer). Exécute buildspec.yml. Charge les artefacts dans S3. Supporte Docker nativement. Facturation à la minute.

CodeDeploy

Déploiement automatisé sur EC2, Lambda, ECS. Strategies : AllAtOnce, HalfAtATime, OneAtATime, Canary, Linear.

CodePipeline

Orchestrateur CI/CD : enchaîne Source → Build → Test → Deploy. Intègre CodeCommit, GitHub, S3 (source), CodeBuild (build), CodeDeploy/ECS/Beanstalk (deploy).

buildspec.yml — structure

# buildspec.yml — fichier à la racine du dépôt
version: 0.2

phases:
  install:
    runtime-versions:
      nodejs: 18
    commands:
      - npm install

  pre_build:
    commands:
      - # Login ECR
      - aws ecr get-login-password | docker login --username AWS --password-stdin $ECR_URI

  build:
    commands:
      - npm test
      - docker build -t $IMAGE_TAG .
      - docker push $IMAGE_TAG

  post_build:
    commands:
      - printf '[{"name":"app","imageUri":"%s"}]' $IMAGE_TAG > imagedefinitions.json

artifacts:
  files:
    - imagedefinitions.json
    - appspec.yml

CodePipeline — intégrations clés

Source Actions

CodeCommit, GitHub (via CodeStar Connections), S3, ECR. Chaque push déclenche le pipeline via EventBridge.

Approval manuelle

Action d'approbation humaine entre stages. Envoie une notification SNS. Le pipeline attend jusqu'à l'approbation ou le timeout (7 jours).

Cross-account deploy

Pipeline dans compte A, déploiement dans compte B. Nécessite un rôle IAM cross-account et une clé KMS partagée pour les artefacts S3.

Notifications

CodeStar Notifications → SNS/Slack/Teams pour les événements pipeline (succès, échec, approbation en attente).

✅ Elastic Beanstalk comme cible de déploiement : supporte les mêmes stratégies (AllAtOnce, Rolling, Rolling with additional batch, Immutable, Traffic splitting). Immutable = meilleur pour la production, sans downtime et rollback rapide.
Config & IaC · 17 %

Configuration Management & Infrastructure as Code

CloudFormation, CDK, Systems Manager, OpsWorks, Elastic Beanstalk

CloudFormation — concepts avancés

StackSets

Déploie un stack CloudFormation dans plusieurs comptes et régions simultanément depuis un compte administrateur. Idéal pour les organisations AWS.

Change Sets

Aperçu des modifications avant application. Montre les ressources créées, modifiées, supprimées. Obligatoire en prod pour éviter les suppressions accidentelles.

Drift Detection

Détecte les ressources modifiées manuellement hors CloudFormation. Permet de resynchroniser l'état réel avec le template.

Custom Resources

Lambda ou SNS invoqués par CloudFormation pour des ressources non natives. Utile pour configurer des services tiers ou des logiques custom lors du déploiement.

cfn-init / cfn-signal

Bootstrap d'instances EC2 : cfn-init applique la config depuis les métadonnées, cfn-signal notifie CloudFormation que l'instance est prête (CreationPolicy).

Nested Stacks

Stacks imbriqués pour découper en modules réutilisables (réseau, IAM, app). Le parent référence l'enfant via AWS::CloudFormation::Stack.

CloudFormation — exemple avec rollback

# Créer un stack avec rollback sur erreur
aws cloudformation create-stack \
  --stack-name my-app-prod \
  --template-body file://template.yaml \
  --parameters ParameterKey=Env,ParameterValue=prod \
  --on-failure ROLLBACK \
  --capabilities CAPABILITY_IAM

# Mettre à jour avec un Change Set
aws cloudformation create-change-set \
  --stack-name my-app-prod \
  --template-body file://template-v2.yaml \
  --change-set-name update-v2

aws cloudformation execute-change-set \
  --change-set-name update-v2 \
  --stack-name my-app-prod

AWS Systems Manager (SSM)

Parameter Store

Stockage de configuration et secrets. Hiérarchie /app/prod/db-password. Intégration native CloudFormation, Lambda, CodeBuild. Tier standard gratuit.

Secrets Manager

Rotation automatique des secrets (RDS, Redshift, custom). Intègre Lambda pour la rotation. Plus cher que Parameter Store mais rotation native.

Session Manager

Shell sur instances EC2 sans SSH, sans clé, sans port 22 ouvert. Audit via CloudTrail. Idéal pour les environnements sécurisés (pas de bastion).

Run Command

Exécute des commandes sur des flottes d'instances (par tags, groupes). Remplace Ansible/Chef pour les tâches ponctuelles. Résultats dans S3 ou CloudWatch Logs.

Patch Manager

Applique les patches OS selon une Patch Baseline. Planifié via Maintenance Windows. Rapports de compliance dans SSM Compliance.

Automation

Runbooks SSM pour automatiser les opérations (créer AMI, remediation…). Peut être déclenché par EventBridge, AWS Config, ou manuellement.

Security & Compliance · 17 %

Security & Compliance

IAM avancé, AWS Config, Security Hub, GuardDuty, chiffrement

IAM avancé

Permissions Boundaries

Plafond de permissions d'une entité IAM. Même si une policy accorde plus, la boundary limite. Délégation sécurisée à des développeurs pour créer des rôles.

Service Control Policies (SCP)

Politiques Organizations : limitent ce que les comptes membres peuvent faire, même pour l'admin. Whitelist ou blacklist de services/actions.

IAM Roles Anywhere

Permet aux workloads on-premise d'assumer des rôles IAM via des certificats X.509. Élimine les long-lived access keys pour les serveurs hors AWS.

ABAC — Attribute-Based

Contrôle d'accès basé sur des tags (ex: Project=Alpha). Plus scalable que RBAC traditionnel quand les équipes et ressources grandissent.

Chiffrement & Secrets

KMS CMK

Customer Managed Keys : rotation annuelle automatique optionnelle. Utilisé pour chiffrer S3, EBS, RDS, Secrets Manager. Audit via CloudTrail.

Envelope Encryption

KMS chiffre une Data Encryption Key (DEK), la DEK chiffre les données. KMS ne voit jamais les données en clair. Pattern standard AWS.

ACM — Certificate Manager

Certificats TLS gratuits pour ALB, CloudFront, API Gateway. Renouvellement automatique. Les certificats ne peuvent pas être exportés (sauf Private CA).

Secrets Manager

Rotation automatique toutes les N jours via Lambda. Intègre nativement RDS, Redshift, DocumentDB. Référencer depuis ECS Task Definition ou Lambda env vars.

Monitoring & Logging · 15 %

Monitoring & Logging

CloudWatch, X-Ray, CloudTrail — observabilité complète

CloudWatch — les 4 piliers

Metrics

Métriques standard (CPUUtilization, RequestCount…) et custom. Résolution standard 1min, haute résolution 1s. Rétention jusqu'à 15 mois.

Logs

Log Groups → Log Streams. Metric Filters extraient des métriques des logs. Subscription Filters envoient vers Lambda, Kinesis, OpenSearch en temps réel.

Alarms

Déclenche actions : Auto Scaling, SNS, EC2 (stop/reboot/recover). États : OK, ALARM, INSUFFICIENT_DATA. Composite Alarms combinent plusieurs alarmes.

Dashboards

Visualisations cross-account et cross-region. Partageables. Widgets : graphiques, chiffres, textes. Supporte les expressions mathématiques sur métriques.

CloudWatch Logs — flux de données

# Envoyer des logs custom depuis une app
aws logs put-log-events \
  --log-group-name /app/production \
  --log-stream-name instance-i-1234567890abcdef0 \
  --log-events timestamp=1699900000000,message="Deploy OK"

# Créer un Metric Filter (compter les erreurs 500)
aws logs put-metric-filter \
  --log-group-name /app/production \
  --filter-name Http500Errors \
  --filter-pattern "[..., statusCode=5*]" \
  --metric-transformations \
    metricName=Http500Count,metricNamespace=AppMetrics,metricValue=1

# Exporter des logs vers S3 (analytique)
aws logs create-export-task \
  --log-group-name /app/production \
  --from 1699900000000 \
  --to 1699986400000 \
  --destination my-logs-bucket

AWS X-Ray — Distributed Tracing

Traces & Segments

Une trace = requête end-to-end. Segments = une unité de travail (Lambda, EC2, service). Subsegments pour les appels AWS SDK ou HTTP.

Service Map

Carte visuelle des services et leurs latences/erreurs. Identifie les goulots d'étranglement et les cascades d'erreurs dans les architectures microservices.

Sampling

Pour réduire les coûts : rule par défaut = 5% des requêtes + 1/s. Sampling rules custom par service, path, méthode HTTP.

Groups & Insights

Filtres de traces pour alerter sur des anomalies (latence anormale, taux d'erreur élevé). Intègre CloudWatch pour les alarmes.

CloudTrail — Audit des actions API

✅ CloudTrail enregistre toutes les API calls (console + CLI + SDK). Trail multi-région obligatoire pour la compliance. Log File Validation (hash SHA-256) garantit l'intégrité. Envoie vers S3 (long terme) + CloudWatch Logs (temps réel) + EventBridge (réaction).
⚠️ CloudTrail a un délai de ~15 minutes. Pour une réponse en temps réel aux événements de sécurité, utiliser EventBridge (quasi temps réel) plutôt que CloudTrail directement.
Resilient Cloud Solutions · 15 %

Resilient Cloud Solutions

Auto Scaling, multi-AZ, DR, RDS/ECS/Lambda haute disponibilité

Auto Scaling Groups (ASG)

Target Tracking

Maintient une métrique cible (ex: 50% CPU). AWS gère automatiquement scale-out et scale-in. La politique la plus simple et recommandée.

Step Scaling

Actions par paliers selon l'ampleur de l'alarme. Ex: +2 instances si CPU 60-80%, +4 si CPU >80%. Plus fine que simple scaling.

Scheduled Scaling

Montée en charge prévisible (black friday, horaires bureau). Définit min/max/desired à un moment précis ou en cron.

Predictive Scaling

Machine learning analyse l'historique et anticipe. Combine avec reactive scaling. Réduit la latence de démarrage grâce à l'anticipation.

RDS — Haute disponibilité

Multi-AZ

Réplica synchrone dans une autre AZ. Failover automatique en 60-120s. Pour la haute disponibilité, pas pour la performance lecture.

Read Replicas

Réplica asynchrone pour décharger les lectures. Peut être promu en instance principale. Cross-region possible. Pour la scalabilité lecture.

Aurora Global Database

Réplication cross-région en moins d'1 seconde. RPO <1s, RTO <1min. Idéal pour les applications mondiales et la DR active.

RDS Proxy

Pool de connexions entre Lambda/ECS et RDS. Réduit les connexions directes (problème classique Lambda). Failover transparent.

Incident & Event Response · 14 %

Incident & Event Response

EventBridge, SNS, SQS, Lambda, Step Functions — automatiser la réponse

EventBridge — le hub d'événements AWS

Event Bus

Default (services AWS), Custom (apps), Partner (SaaS). Les règles filtrent les événements et routent vers des targets (Lambda, SQS, Step Functions, SNS…).

Event Rules

Pattern matching sur les attributs d'un event JSON. Ex: EC2 state-change → {"source":["aws.ec2"],"detail-type":["EC2 Instance State-change Notification"]}.

Scheduled Rules

Cron ou rate expression pour déclencher des workflows périodiques. Remplace CloudWatch Events (même service, nouveau nom).

Pipes

Connexion point-à-point source → enrichissement → target. Source : SQS, DynamoDB Streams, Kinesis. Filtre et enrichit sans code Lambda intermédiaire.

Pattern : remédiation automatique avec Config + SSM

# Flow : Config détecte une non-conformité
#        → EventBridge reçoit l'event Config
#        → déclenche SSM Automation Runbook
#        → remédie automatiquement

# Exemple : S3 bucket public read → remédiation auto
# EventBridge Rule :
{
  "source": ["aws.config"],
  "detail-type": ["Config Rules Compliance Change"],
  "detail": {
    "configRuleName": ["s3-bucket-public-read-prohibited"],
    "newEvaluationResult": {
      "complianceType": ["NON_COMPLIANT"]
    }
  }
}
# Target : SSM Automation avec AWS-DisableS3BucketPublicReadWrite

Step Functions — orchestration

Standard Workflows

Jusqu'à 1 an d'exécution. Exactement une fois. Idéal pour les workflows métier longs (commandes, approbations humaines). Visible dans la console.

Express Workflows

Jusqu'à 5 minutes. Au moins une fois. Haute performance (100k/s). Pour IoT, traitement de données en masse. Moins cher.

Parallel & Map

Parallel : exécute plusieurs branches en parallèle. Map : itère sur un tableau (traitement batch). Les deux attendent la complétion avant de continuer.

Wait for Callback

Workflow pause et envoie un token. Reprend quand un service externe appelle SendTaskSuccess. Pattern pour les approbations humaines ou APIs externes.

CloudWatch — alarmes et métriques

# Créer une alarme CPU
aws cloudwatch put-metric-alarm \
  --alarm-name HighCPU \
  --metric-name CPUUtilization \
  --namespace AWS/EC2 \
  --dimensions Name=AutoScalingGroupName,Value=my-asg \

  --period 60 \
  --threshold 80 \
  --comparison-operator GreaterThanOrEqualToThreshold \
  --evaluation-periods 2 \

⚠️ Pièges & astuces

Pièges courants à l'examen DOP-C02

Les erreurs classiques qui font perdre des points

CodeDeploy ≠ CodePipeline

CodeDeploy = outil de déploiement (EC2/Lambda/ECS). CodePipeline = orchestrateur CI/CD qui peut appeler CodeDeploy. Ne pas les confondre dans les scénarios.

Multi-AZ ≠ Read Replica

Multi-AZ = haute disponibilité (failover auto, réplica synchrone). Read Replica = scalabilité lecture (réplica asynchrone). L'exam teste souvent cette distinction.

CloudTrail délai 15 min

CloudTrail ne convient pas pour des alertes de sécurité immédiates. Utiliser EventBridge (quasi temps réel) + GuardDuty pour détecter et réagir instantanément.

Parameter Store vs Secrets Manager

Secrets Manager = rotation automatique + coût ($0.40/secret/mois). Parameter Store Standard = gratuit, pas de rotation auto. SecureString = KMS mais pas de rotation.

SCP ne remplace pas IAM

Les SCP (Organizations) définissent le plafond des permissions. IAM doit toujours accorder explicitement les droits. Les deux s'appliquent (intersection).

Blue/Green sur Lambda

Pour Lambda, utiliser les alias et la traffic shifting (Canary/Linear) via CodeDeploy. Les CloudWatch Alarms déclenchent le rollback automatique si erreurs.

cfn-signal obligatoire

Sans cfn-signal dans le UserData, CloudFormation considère l'instance prête dès sa création (pas après bootstrap). Utiliser CreationPolicy + cfn-signal pour attendre réellement.

EventBridge ≠ SNS pour l'automation

Pour réagir aux événements AWS (Config, GuardDuty, CodePipeline), EventBridge est le bon choix. SNS est mieux pour les notifications humaines (email, SMS).

RDS Proxy pour Lambda

Lambda peut créer des milliers de connexions RDS simultanées lors du scale. RDS Proxy pool les connexions. Toujours proposer RDS Proxy quand Lambda + RDS.

StackSets nécessite confiance

StackSets cross-account nécessite un rôle AWSCloudFormationStackSetAdministrationRole dans le compte admin et AWSCloudFormationStackSetExecutionRole dans les cibles.
