ALB — Règles de routage

  • Path-based : /api/* → Target Group A, /images/* → Target Group B
  • Host-based : api.example.com → TG A, app.example.com → TG B
  • Query string : ?version=2 → TG B
  • HTTP header : X-Custom-Header: value → TG C
  • IP source : CIDR whitelist → TG interne

NLB — Caractéristiques clés

  • IP statique par AZ (1 EIP assignable) → utile pour whitelisting firewall
  • Preserve client IP par défaut (ALB utilise X-Forwarded-For)
  • TLS Termination possible (SNI multi-certs)
  • Supporte AWS PrivateLink comme endpoint

Sticky Sessions (Session Affinity)

  • ALB : cookie AWSALB (durée configurable 1s–7j)
  • NLB : basé sur IP source + port
  • Problème : déséquilibre de charge si un cookie est long

Connection Draining / Deregistration Delay

  • Durée : 1–3 600 secondes (défaut 300s)
  • Permet aux connexions en cours de se terminer avant désenregistrement

RDS — Haute Disponibilité J3

RDS Multi-AZ

  • Réplication synchrone vers standby dans une autre AZ
  • Failover automatique : ~1–2 min (DNS bascule)
  • Standby = pas lisible (différence avec Read Replica)
    • Protège contrePanne AZ, maintenance OS/DB
RDS Multi-AZ standby N'EST PAS une Read Replica. Il n'accepte pas de trafic lecture. Pour lire, utiliser des Read Replicas séparées.

RDS Read Replicas

  • Réplication asynchrone (possible lag)
  • Jusqu'à 15 replicas (Aurora) ou 5 (RDS standard)
  • Peuvent être dans une autre région (Cross-Region RR)
  • Peuvent être promus en instance principale (manuelle)
  • Coût : transfert de données inter-région facturé

RDS Multi-AZ DB Cluster (nouveau)

  • 1 writer + 2 readers dans 3 AZ différentes
  • Readers acceptent du trafic lecture (différence avec Multi-AZ classique)
  • Failover ~35 secondes

RDS Proxy

  • Pool de connexions géré (réduit les connexions DB)
  • Failover plus rapide (connexions maintenues pendant failover)
  • Compatible avec IAM Authentication et Secrets Manager
  • Cas d'usage : Lambda → RDS (Lambda ouvre/ferme connexions = problème)
Lambda + RDS = toujours utiliser RDS Proxy. Sans proxy, Lambda peut saturer les connexions DB lors de pics.

Health Checks

  • Endpoint health checks : HTTP/HTTPS/TCP, intervalles 10 ou 30s
  • Calculated health checks : combine plusieurs checks (AND/OR)
  • CloudWatch Alarm health checks : pour ressources privées (VPC)
  • Seuil unhealthy : 3 checks consécutifs échoués (défaut)
Geolocation ≠ Latency. Geolocation = où est le CLIENT géographiquement. Latency = quelle région répond le plus vite. Un client en France peut avoir moins de latence vers us-east-1 qu'eu-west-3 (rare mais possible).

SQS — Concepts clés HA

ParamètreStandard QueueFIFO Queue
OrdreBest-effortGaranti
DéduplicationNonOui (5 min window)
ThroughputIllimité300 msg/s (3000 avec batching)
LivraisonAt-least-onceExactly-once
  • Visibility Timeout : durée pendant laquelle un message est invisible après lecture (défaut 30s, max 12h)
  • Dead Letter Queue (DLQ) : messages qui échouent N fois → DLQ pour analyse
  • Long Polling : WaitTimeSeconds 1–20s, réduit les requêtes vides et les coûts
  • Message retention : 1 min – 14 jours (défaut 4 jours)
Si un consumer crash pendant le traitement, le message redevient visible après le Visibility Timeout. Sans DLQ configuré, il peut boucler indéfiniment.

SNS — Fan-out pattern

  • SNS Topic → multiple SQS queues (fan-out) : garantit que tous les subscribers reçoivent
  • SNS FIFO → SQS FIFO : ordre garanti end-to-end
  • Message Filtering : chaque subscriber peut définir un filtre JSON

Patterns de résilience multi-région

Active-Active

  • Route 53 Latency ou Weighted
  • DynamoDB Global Tables
  • Aurora Global Database
  • S3 CRR bidirectionnel

Active-Passive (DR)

  • Route 53 Failover policy
  • RDS Cross-Region Read Replica
  • Aurora Global DB (promote)
  • S3 CRR unilatéral

DynamoDB Global Tables

  • Réplication multi-région active-active
  • Latence d'écriture <1s entre régions
  • Conflict resolution : last-writer-wins (timestamp)
  • Prérequis : DynamoDB Streams activé

Aurora Global Database

  • 1 région primaire (R/W) + jusqu'à 5 régions secondaires (read-only)
  • Réplication asynchrone <1s typiquement
  • RPO <1s, RTO <1 minute lors d'un failover inter-région
  • Promote secondaire en primaire : <1 min
Pour RTO <1 min inter-région avec une DB SQL → Aurora Global Database. Pour NoSQL → DynamoDB Global Tables.

Sécurité — Architectures sécurisées (D1 · 30%)

Gouvernance multi-comptes

AWS OrganizationsRegroupement hiérarchique de comptes AWS. Root → Organizational Units (OUs) → Comptes. Permet la facturation consolidée et l'application de politiques centralisées.
SCP (Service Control Policies)Politiques de permission max appliquées à une OU ou un compte. Elles ne donnent pas de droits — elles limitent ce que les IAM policies peuvent accorder. SCP doit autoriser ET IAM doit autoriser = accès accordé.
AWS Control TowerService pour provisionner un landing zone multi-comptes sécurisé. Crée automatiquement des OUs, des guardrails (préventifs = SCP, détectifs = Config Rules), et un compte de logs centralisé. Idéal pour démarrer une organisation AWS.
AWS STS (AssumeRole)Génère des credentials temporaires. Cross-account : rôle dans le compte cible → AssumeRole depuis le compte source. Durée 15 min à 12 h. Utilisé pour l'accès inter-comptes, les applications EC2, et la fédération d'identité.

Authentification & Fédération d'identité

Amazon Cognito — User PoolsAnnuaire d'utilisateurs géré (inscription, connexion, MFA, JWT tokens). Utilisé pour authentifier les utilisateurs d'applications web/mobile. Remplace la gestion custom des comptes utilisateurs.
Amazon Cognito — Identity PoolsÉchange un token (Cognito, Google, Facebook, SAML…) contre des credentials AWS temporaires (via STS). Donne aux users d'appli un accès direct à S3, DynamoDB, etc. sans proxy backend.
IAM Identity Center (ex-SSO)SSO centralisé pour tous les comptes AWS de l'organisation et les applis SAML 2.0. Se connecte à Active Directory ou à un IdP externe. Remplace la gestion de rôles cross-account manuels.
Cognito User Pools = authentification des UTILISATEURS. Cognito Identity Pools = autorisation d'accès aux RESSOURCES AWS. Les deux peuvent être chaînés.

Sécurité des workloads & applications

Amazon GuardDutyDétection de menaces basée sur le ML. Analyse CloudTrail, VPC Flow Logs, DNS logs. Identifie : instances compromises, appels API suspects, communications C2, cryptomining. Activation en 1 clic, sans agent.
Amazon MacieDécouverte et protection des données sensibles (PII, credentials) dans S3. Utilise le ML pour classer automatiquement le contenu. Génère des findings pour les buckets non sécurisés ou contenant des données sensibles exposées.
AWS Shield StandardProtection DDoS automatique et gratuite sur tous les services AWS (couches 3 et 4).
AWS Shield AdvancedProtection DDoS avancée (couche 7 aussi), avec réponse 24/7 par l'équipe SRT, remboursement des coûts de scaling liés à une attaque, et WAF inclus. ~3 000 $/mois.
AWS WAFFirewall applicatif (couche 7). Règles sur IP, géolocalisation, rate limiting, injection SQL, XSS. S'intègre avec CloudFront, ALB, API Gateway. Web ACL = ensemble de règles. Managed Rules = règles AWS ou Marketplace.
AWS Secrets ManagerStocke et fait tourner automatiquement les secrets (mots de passe RDS, clés API). Rotation built-in pour RDS/Aurora/Redshift. Référencer via ARN dans le code — jamais hardcoder.
ACM (AWS Certificate Manager)Gestion gratuite des certificats TLS/SSL pour ALB, CloudFront, API Gateway. Renouvellement automatique. Les certificats ACM ne peuvent pas être exportés (pour EC2 direct → importer son propre certificat).

Sécurité des données

AWS KMSChiffrement at-rest géré. Customer Master Keys (CMK) : AWS-managed (gratuit) ou Customer-managed (contrôle total, rotation manuelle ou annuelle). KMS est régional — les clés ne se répliquent pas automatiquement.
Chiffrement S3SSE-S3 (clés AWS, défaut), SSE-KMS (audit trail CloudTrail, quota API), SSE-C (clé client, AWS ne stocke pas la clé), CSE (chiffrement avant envoi). Bucket Key réduit les appels KMS et les coûts.
VPC EndpointsInterface Endpoint (PrivateLink) : accès privé à des services via ENI dans le VPC, facturation par heure + données. Gateway Endpoint : S3 et DynamoDB uniquement, gratuit, via table de routage. Préférer Gateway pour S3/DynamoDB.

Conteneurs & Serverless

Amazon ECS (Elastic Container Service)

Concepts clésTask Definition (image + ressources CPU/RAM) → Task (instance en cours) → Service (maintient N tasks en vie avec ALB). Cluster = regroupement logique.
Launch typesEC2 : tu gères les instances sous-jacentes (patch, capacité). Fargate : serverless, AWS gère l'infra, tu définis seulement CPU/RAM par task. Fargate est plus simple et recommandé pour SAA.
IAM pour ECSTask Role : permissions que le container a sur les ressources AWS (ex: S3, DynamoDB). Execution Role : permissions pour ECS de tirer l'image ECR et envoyer les logs CloudWatch.

Amazon EKS (Elastic Kubernetes Service)

Quand choisir EKSWorkloads Kubernetes existants à migrer, besoin d'un écosystème K8s (Helm, opérateurs), équipe avec expertise K8s. Plus complexe que ECS mais portable.
ModesEC2 managed nodes, Fargate (node management zéro), ou AWS Outposts pour EKS on-premises.

AWS Fargate

PrincipeMoteur serverless pour ECS et EKS. Zéro gestion de serveurs. Facturation à la seconde selon vCPU + RAM alloués. Chaque task a ses propres ressources réseau (ENI). Scaling via ECS Service Auto Scaling.
Cas d'usage SAAMicroservices, workers de traitement, APIs containerisées. Choisir Fargate si l'énoncé mentionne «sans gestion de serveurs» ou «serverless containers».

AWS Transfer Family

DéfinitionService managé de transfert de fichiers vers/depuis S3 ou EFS via protocoles SFTP, FTPS, FTP, AS2. Remplace les serveurs FTP maison. Authentification via IAM, Cognito, ou annuaire AD/LDAP.
Cas d'usage SAAPartenaires B2B qui envoient des fichiers via SFTP → stocker directement dans S3. Migration de workflows FTP existants sans changer le client.

AWS X-Ray

DéfinitionService de tracing distribué. Suit les requêtes à travers Lambda, EC2, ECS, API Gateway, SQS. Génère une Service Map visuelle et identifie les goulots d'étranglement et les erreurs.
ConceptsTrace = requête de bout en bout. Segment = contribution d'un service. Subsegment = appel externe (DB, HTTP). Sampling = X-Ray ne trace pas 100% des requêtes par défaut (réducteur de coûts).
Cas d'usage SAADiagnostiquer latences dans une architecture microservices. Identifier quel service cause des erreurs 500. L'énoncé mentionne «observabilité», «tracing», «bottleneck» → penser X-Ray.

Analytique & Data Ingestion (D3)

Amazon Athena

DéfinitionMoteur de requêtes SQL serverless sur S3. Pas d'infra à gérer, paiement par scan (5$/TB scanné). Supporte CSV, JSON, ORC, Parquet, Avro. Intégration native avec AWS Glue Data Catalog.
Optimisation coûtsConvertir en Parquet (format colonnaire) = 70-80% de réduction des coûts. Partitionner les données (ex: par date) = réduction du scan. Utiliser la compression (Snappy, GZIP).
Cas d'usage SAAAnalyser les logs S3 (CloudTrail, ALB), BI ad-hoc sur un data lake, remplacer un data warehouse pour des requêtes occasionnelles. Mot-clé : «interroger des données dans S3 sans infra».

AWS Glue

DéfinitionService ETL (Extract, Transform, Load) serverless. Découvre automatiquement les schémas (Glue Crawlers → Data Catalog). Exécute des jobs de transformation en Spark/Python.
Glue Data CatalogRéférentiel central de métadonnées (tables, schémas). Partagé avec Athena, Redshift Spectrum, EMR. C'est le «catalogue» de votre data lake.
Cas d'usage SAAPréparer des données brutes S3 pour Athena/Redshift. Convertir CSV → Parquet. Mots-clés : «ETL», «transformer», «cataloguer», «data lake».

Amazon EMR (Elastic MapReduce)

DéfinitionCluster managé pour Big Data : Hadoop, Spark, Hive, HBase, Presto. Traitement distribué de très gros volumes. Stockage sur S3 (via EMRFS) ou HDFS sur instances EC2.
Cas d'usage SAAMachine learning sur gros datasets, transformations Spark complexes, analyse de logs en temps réel. Choisir EMR si l'énoncé mentionne Spark/Hadoop/Hive ou «traitement de pétaoctets».

AWS Lake Formation

DéfinitionOrchestrateur pour construire, sécuriser et gérer un data lake sur S3. Automatise l'ingestion, le catalogage (via Glue), et la gestion des permissions d'accès aux données au niveau colonne/ligne.
Cas d'usage SAAGouvernance centralisée des accès à un data lake. Contrôle fin qui peut accéder à quelles colonnes dans Athena/Redshift. Mots-clés : «data lake», «gouvernance», «contrôle d'accès aux données».

AWS DataSync

DéfinitionService de transfert de données rapide et automatisé entre on-premises et AWS (S3, EFS, FSx). Installe un agent on-premises. Jusqu'à 10x plus rapide que les outils open source. Vérification d'intégrité automatique.
vs Storage GatewayDataSync = migration/transfert de données one-shot ou récurrent. Storage Gateway = extension permanente du stockage on-premises vers AWS (accès continu). DataSync pour migrer; Storage Gateway pour hybride permanent.

AWS Storage Gateway

File GatewayExpose S3 comme un partage NFS/SMB. Les fichiers récents en cache local, les archives dans S3. Idéal pour remplacer un NAS on-premises ou pour archiver vers S3.
Volume GatewayExpose des volumes iSCSI. Stored volumes : données primaires on-premises, snapshot dans S3. Cached volumes : données primaires dans S3, fréquemment accédées en cache local.
Tape Gateway (VTL)Remplace les librairies de bandes physiques. Compatible avec les logiciels de sauvegarde existants (Veeam, Veritas). Stocke dans S3 Glacier.

Optimisation des coûts (D4 · 20%) — Compléments

Cycle de vie S3 & optimisation stockage

S3 Lifecycle PoliciesRègles automatiques pour déplacer ou supprimer des objets. Transitions : Standard → Standard-IA (min 30 jours) → Glacier Instant Retrieval (min 90 jours) → Glacier Deep Archive. Expirations : suppression automatique après N jours.
S3 Intelligent-TieringDéplace automatiquement les objets entre tiers selon les patterns d'accès. Pas de frais de retrieval. Adapté quand les patterns d'accès sont inconnus ou changeants. Frais de monitoring (~0,0025$/1000 objets/mois).
S3 Requester PaysPar défaut, le propriétaire du bucket paie le transfert. Avec Requester Pays activé, c'est celui qui télécharge qui paie le data transfer. Utile pour distribuer de gros datasets publics sans coût de bande passante.

EC2 — Optimisation coûts avancée

EC2 HibernationSauvegarde le contenu RAM sur EBS (racine chiffré obligatoire) et arrête l'instance. Au redémarrage, la RAM est restaurée — démarrage ultra-rapide. Limite : instance RAM max 150 GB, durée hibernation max 60 jours. Utile pour des workloads avec long temps de démarrage applicatif.
AWS OutpostsRack AWS déployé dans votre datacenter. Mêmes services AWS, même API, même console. Latence ultra-faible ou contraintes de résidence des données imposant le on-premises. Facturation : frais fixes du rack + usage. Cas d'usage : manufactures, hôpitaux, traders HF.
EC2 Instance Connect / Session ManagerAccès SSH sans ouvrir le port 22 (SSM Session Manager). Éliminer les bastions = économie et sécurité améliorée.

Anti-patterns & Pièges exam

NLB ne remplace pas ALB pour du HTTP avec routage. ALB ne donne pas d'IP statique.
Auto Scaling Simple Policy a un cooldown bloquant. Pour une réaction rapide → Target Tracking.
RDS Multi-AZ standby n'est PAS lisible. Pour la lecture → Read Replicas.
S3 One Zone-IA : données perdues si AZ tombe. Ne jamais utiliser pour données uniques critiques.
CloudFront ne cache pas par défaut les requêtes POST/PUT/DELETE. Seulement GET/HEAD.
SQS Visibility Timeout trop court = même message traité deux fois (at-least-once). Toujours > durée de traitement.
VPC Peering est non-transitif : A↔B et B↔C ne signifie pas A↔C. Pour transitivité → Transit Gateway.
Lambda dans un VPC privé a besoin d'un NAT Gateway pour accéder à Internet (y compris les API AWS publiques).
EFS ne supporte que Linux (protocole NFS v4). Pour Windows avec accès partagé → FSx for Windows.
Instance Store perdu à l'arrêt/terminate ET si l'hôte physique tombe. Jamais pour données persistantes.
Cognito User Pools ≠ Identity Pools. User Pools = annuaire d'utilisateurs (JWT). Identity Pools = credentials AWS temporaires pour accéder à S3/DynamoDB directement. On les chaîne souvent mais ce sont deux services distincts.
GuardDuty détecte les menaces existantes (ML sur logs). Macie détecte les données sensibles dans S3 (PII, credentials). Inspector analyse les vulnérabilités sur EC2/ECR. Ne pas les confondre à l'examen.
Control Tower crée des guardrails PRÉVENTIFS (SCP = bloque l'action) et DÉTECTIFS (Config Rules = alerte après). Les SCP ne donnent jamais de permissions — elles limitent seulement.
DataSync = transfert de données (migration). Storage Gateway = extension hybride permanente (accès continu au stockage cloud depuis on-premises). Question sur «migrer des fichiers vers S3» → DataSync. «Accéder à S3 comme un NAS» → File Gateway.
Athena = SQL serverless sur S3 (paiement par scan). Reduire les coûts Athena → convertir en Parquet + partitionner. EMR = cluster Big Data Spark/Hadoop. Glue = ETL serverless. Lake Formation = gouvernance du data lake.
EC2 Hibernation nécessite le volume racine EBS chiffré. L'instance RAM max est 150 GB. Durée max en hibernation : 60 jours. Ne pas confondre avec Stop (RAM perdue) ou Reboot (tout préservé, restart rapide).
ACM gère les certificats pour ALB, CloudFront, API Gateway — renouvellement automatique. Les certificats ACM ne peuvent PAS être exportés pour être installés directement sur EC2. Pour EC2 → importer son propre certificat ou utiliser Let's Encrypt.
NLB (Network Load Balancer) : seul LB avec IP statique / Elastic IP assignable. ALB et CLB ont des IPs dynamiques. Question sur «IP fixe pour whitelisting client» → NLB.
