🏢 AWS Organizations & IAM

AWS Organizations

  • Compte Management (racine) → Organizational Units → Comptes membres
  • SCP (Service Control Policy) : limite les permissions max d'un compte, même sur le root
  • Consolidated Billing : facturation centralisée + volume discounts
  • Control Tower : landing zone avec guardrails (SCP + Config)
  • RAM (Resource Access Manager) : partage de ressources entre comptes (VPC, Transit Gateway, subnets…)

IAM — Fondamentaux

  • Service global (non régional)
  • Identity-based policy (attachée à user/role) vs Resource-based policy (attachée à la ressource)
  • Permission boundaries : limite permanente max pour un user/role
  • Session policies : limite temporaire lors d'un AssumeRole
  • SCP : limite les comptes dans Organizations
  • Format ARN : arn:aws:SERVICE:REGION:ACCOUNT:RESOURCE

IAM Rôles & Fédération

  • Role : 3 étapes → AssumeRole → Trust Policy → STS tokens temporaires
  • Instance Profile : attribution d'un rôle à une instance EC2 (seulement ça)
  • SAML 2.0 : SSO fédéré → AssumeRoleWithSAML
  • OIDC : OAuth 2.0 → AssumeRoleWithWebIdentity
  • Identity Center : SSO centralisé multi-comptes (SAML 2.0)
  • IAM Roles Anywhere : machines hors AWS via certificat X.509
  • External ID : protéger l'accès cross-account lors d'audit

IAM — Outils d'audit

  • Credential reports : liste users + statut credentials (passwords, access keys, MFA) MAIS PAS les permissions
  • IAM Access Analyzer : ressources partagées avec l'extérieur, valide les policies, génère des policies minimales depuis CloudTrail
  • IAM Policy Simulator : teste et valide les permissions sans faire l'action réelle
  • Directory Services : AD Connector (passerelle) / Managed Microsoft AD (vrai AD) / Simple AD (clone léger)

🌐 Réseau — VPC & Connectivité

VPC & Sous-réseaux

  • VPC → région, Subnet → AZ
  • ACL : niveau subnet, stateless, tout ouvert par défaut
  • Security Groups : niveau instance/ENI, stateful, entrant bloqué par défaut
  • Internet Gateway → attachée au VPC ; NAT Gateway → dans subnet public, lié à une AZ, associée au subnet privé
  • Egress-Only IGW = NAT Gateway IPv6
  • Public subnet = IGW + Route table + IP publique

VPC Endpoints

  • Gateway Endpoint (S3, DynamoDB) : accès privé via route table, pas d'ENI
  • Interface Endpoint (PrivateLink) : ENI avec IP privée dans le subnet
  • GWLB Endpoint : inspection du trafic (IDS/IPS)
  • Endpoint policies : restreindre l'accès aux ressources
  • PrivateLink vs VPC Peering : PrivateLink expose un service spécifique ; Peering connecte deux VPC entiers

Connexions hybrides

  • VPN : Virtual Private Gateway + Customer Gateway (IPSEC)
  • Direct Connect : fibre optique dédiée (prend des mois à installer)
  • Transit Gateway : hub VPC transitif, supporte VPN + Direct Connect + hybride
  • VPC Peering : non transitif, fonctionne cross-account et cross-region

DNS & Réseau avancé

  • Route 53 Resolver : résolution DNS entre VPC et on-prem (inbound/outbound endpoints)
  • AWS Global Accelerator : IP anycast statique → routage réseau basse latence (≠ DNS, ≠ cache)
  • Managed Prefix List : Customer-managed (partageable) vs AWS-managed (non modifiable)
  • Network Firewall : deep packet inspection, domain filtering, centralized egress

💾 Stockage — EBS & S3

EBS (Elastic Block Store)

  • Volume bloc, attaché à une instance EC2 (même AZ)
  • Types : gp3/gp2 (généraliste), io2/io1 (IOPS provisionnées), st1 (throughput HDD), sc1 (cold HDD)
  • Chiffrement : avec KMS (managed ou customer key, PAS AWS owned)
  • Chiffré au repos ET en transit entre EBS et instance
  • Pour lancer EC2 avec EBS chiffré : permission kms:CreateGrant
  • DeleteOnTermination = false pour conserver après arrêt
  • Data Lifecycle Manager : automatisation des backups EBS et gestion du cycle de vie des snapshots

S3 — Fondamentaux

  • Serverless, buckets illimités, 5 To/objet max, 5 Go max par transfert (sinon multipart)
  • Pour multipart chiffré : permissions KMS (Encrypt, Decrypt, GenerateDataKey, DescribeKey, ReEncrypt)
  • Nom de bucket = chemin unique dans le monde
  • S3 Block Public Access : paramètre qui empêche l'accès public même si policy ou ACL le permettent → S3 EXPLICIT DENY
  • Bucket Policy : 20 kb max, peut créer des access points (jusqu'à 1000)
  • S3 Object Lock : retention (durée fixe) vs legal hold (sans durée) ; governance mode vs compliance mode
  • Vault Lock Policy = object lock pour tout un dossier Glacier (24h pour modifier)

S3 — Logs & Réplication

  • Server Access Logging : stocké dans S3 (pas CloudWatch) — ce ne sont PAS des management events CloudTrail
  • Object-level logging : API operations (get/put/delete) → stockés dans CloudTrail comme data events
  • S3 Replication : versioning requis sur les deux buckets ; IAM role avec s3:GetObjectVersionForReplication
  • Lifecycle Policy : uniquement vers le plus lent ; Intelligent Tiering peut remonter vers le plus fréquent
  • Pre-signed URL : accès temporaire sans credentials IAM
  • S3 Event Notification : SNS / SQS / Lambda
  • S3 Gateway Endpoint : même région obligatoire

🗄️ Bases de données

RDS

  • Base relationnelle managée au choix (MySQL, PostgreSQL, Oracle, SQL Server, MariaDB)
  • Chiffrement : avec KMS ou CloudHSM
  • RDS Event Subscriptions : notifications sur événements d'infrastructure (pas modifications de données)
  • RDS Enhanced Monitoring : monitoring des ressources (mémoire, threads, CPU)
  • SSL : rds.force_ssl=true côté serveur ; donner certificat RDS au client pour validation MITM
  • IAM database authentication : token IAM valable 15 min (MySQL et PostgreSQL uniquement)
  • ⚠️ SEUL SERVICE qui fait une backup automatique par défaut toutes les 24h

Aurora

  • Service managé AWS, MySQL ou PostgreSQL, optimisé AWS
  • Stockage distribué, auto-scaling, réplication 6 copies sur 3 AZ
  • Aurora Serverless : scaling automatique selon usage
  • Aurora Global Database : réplication cross-région (<1s lag)
  • Aurora Multi-Master : écriture depuis plusieurs instances
  • Read replicas cross-AZ (jusqu'à 15)

DynamoDB

  • NoSQL clé-valeur serverless et scalable
  • DynamoDB Streams : logs d'activité / events pour synchronisation
  • PITR (Point-in-time Recovery) : backup continu automatique (35 jours max)
  • DAX : cache en mémoire pour DynamoDB (microsecondes)
Multi-AZ RDS = HA (standby non accessible en lecture), Read Replicas = scalabilité lecture (peuvent être dans une autre région)

🔍 Monitoring & Logs

CloudWatch

  • Métriques pas en temps réel (5 min par défaut, 1 min avec detailed monitoring)
  • Logs stockés indéfiniment — 2 façons de gérer : retention policy (suppression après délai) ou subscription filter
  • CloudWatch Alarms : OK / ALARM / INSUFFICIENT_DATA
  • CloudWatch Events / EventBridge : réactions à des événements AWS
  • CloudWatch Container Insights : métriques pour ECS, EKS, Fargate
  • Services qui envoient vers CloudWatch : WAF, VPC Flow Logs, API Gateway, RDS, Route53 logs
  • Services qui envoient vers S3 : S3 access logs, ALB/ELB, CloudFront

CloudTrail

  • Audit trail des appels API AWS
  • Management events : activés par défaut (90 jours dans Event History)
  • Data events : opérations sur les données (S3 get/put, Lambda invocations) — à activer manuellement
  • Multi-region trail : un trail pour toutes les régions
  • Multi-account : organisation trail depuis le compte Management
  • CloudTrail Insights : détecte activité inhabituelle
  • Integrity Validation : hash SHA-256 pour détecter la modification des logs
  • CloudTrail Lake : stockage structuré requêtable SQL
EC2 logue en local. Lambda essaie d'envoyer vers CloudWatch mais il faut lui donner les permissions dans son execution role.

⚖️ Load Balancing & Auto Scaling

Load Balancers

  • ALB (Application LB) : couche 7 HTTP/HTTPS, routing par path/host/header
  • NLB (Network LB) : couche 4 TCP/UDP, très haute performance, IP statique par AZ
  • GWLB (Gateway LB) : couche 3, pour appliances réseau (IDS/IPS, firewalls)
  • CLB (Classic LB) : legacy, à éviter
  • ALB utilise SNI pour servir plusieurs domaines avec une seule IP
  • Connection Draining / Deregistration Delay : finir les requêtes en cours avant déréférencement
  • Sticky Sessions : affinité de session (ALB = target group cookie, CLB = LB cookie)

Auto Scaling

  • Launch Template : configuration d'instance (AMI, type, SG, IAM role…)
  • Policies : Target Tracking (maintenir une métrique) / Step Scaling (seuils à paliers) / Scheduled (prévu)
  • Warmup period : délai avant qu'une instance participe aux métriques
  • Cooldown period : délai entre deux actions de scaling
  • ASG peut utiliser des instances Spot pour optimiser les coûts
  • Lifecycle hooks : actions custom lors du launch/termination
  • Predictive scaling : prévision ML basée sur l'historique

🔧 IAC & Containers

CloudFormation

  • Templates YAML/JSON pour déployer l'infrastructure
  • Stack Policy : protège les ressources contre les mises à jour non désirées
  • Update behaviors : Update:Modify (en place) / Update:Replace (nouvelle ressource) / Update:Delete (suppression)
  • StackSets : déploiement multi-comptes et multi-régions depuis Organizations
  • Nested Stacks : stacks référencées par d'autres stacks (réutilisation)
  • Change Sets : prévisualiser les changements avant déploiement

Containers : ECS, EKS, Fargate

  • ECS : Elastic Container Service (orchestrateur AWS natif)
  • EKS : Elastic Kubernetes Service (Kubernetes managé)
  • Fargate : serverless pour ECS/EKS (pas de gestion de serveurs)
  • ECR : registre de container images AWS (scanning des vulnérabilités)
  • ECS Task = unité de déploiement ; Task Definition = blueprint avec IAM role
  • ECS Service = maintient N tasks en cours d'exécution + intégration LB
  • Service auto-scaling pour ECS

📨 Découplage & Lambda

Files de messages

  • SQS : file de messages, découplage, rétention 4j (max 14j), max 256 KB/msg
  • Standard vs FIFO : Standard = best-effort ordering + at-least-once ; FIFO = ordre strict + exactly-once (moins throughput)
  • Visibility Timeout : temps pendant lequel un message est invisible après lecture (évite double traitement)
  • Dead Letter Queue : messages qui échouent N fois sont envoyés en DLQ
  • SNS : pub/sub, fan-out vers SQS / Lambda / HTTP / email
  • SNS FIFO + SQS FIFO : livraison ordonnée garantie
  • EventBridge : événements AWS ou custom → targets

Lambda

  • Serverless, event-driven, max 15 min d'exécution, max 10 GB mémoire
  • PUSH model : S3, SNS, EventBridge poussent les events
  • PULL model : Lambda pollers SQS, Kinesis, DynamoDB Streams (Lambda poll, pas la source)
  • Lambda dans VPC : besoin d'une ENI dans le subnet → permission ec2:CreateNetworkInterface
  • Lambda@Edge : low-latency geoproximity compute à l'edge CloudFront
  • Provisioned Concurrency : éviter les cold starts
  • Layers : partager des librairies entre fonctions
  • Destinations : SQS/SNS/Lambda/EventBridge pour succès ou échec

🔐 Sécurité

Protection DDoS & WAF

  • Shield Standard : gratuit, automatique, protection DDoS L3/L4
  • Shield Advanced : payant, L7, support DDoS Response Team, remboursement coûts
  • WAF : Web Application Firewall L7 (SQL injection, XSS, rate limiting, geofencing) ; déployé sur ALB, CloudFront, API Gateway, AppSync
  • Firewall Manager : centralise WAF, Shield, Security Groups, Network Firewall
  • Network ACLs : stateless (niveau subnet)
  • Security Groups : stateful (niveau instance)

KMS

  • AWS KMS : gestion centralisée des clés de chiffrement
  • Types : AWS Managed / Customer Managed / AWS Owned
  • Rotation automatique : CMK uniquement (annuelle par défaut)
  • Envelope encryption : GenerateDataKey → chiffre données avec DEK → chiffre DEK avec CMK
  • Key policy : contrôle d'accès à la clé (obligatoire)
  • Grants : déléguer l'accès à la clé temporairement
  • Encryption Context : paire key/value pour audit et contrôle

Detection & Response

  • GuardDuty : détection de menaces ML (analyse CloudTrail, VPC Flow Logs, DNS logs). Suppression rules pour réduire les faux positifs
  • Inspector : scanning de vulnérabilités sur EC2, ECR, Lambda (CVE, network reachability)
  • Detective : investigation graphique après incident (alimenté par GuardDuty)
  • Security Hub : agrégation des findings de sécurité, score de conformité
  • Macie : ML pour détecter données sensibles (PII) dans S3
  • Config : audit des configurations et conformité dans le temps

Secrets & Certificats

  • Secrets Manager : rotation automatique des secrets (base de données, API keys)
  • Parameter Store : stockage de paramètres (moins cher, rotation manuelle)
  • ACM (Certificate Manager) : SSL/TLS publics et privés pour services AWS
  • ACM PCA : Private Certificate Authority pour entités internes
  • CloudHSM : HSM dédié dans le VPC (clés non accessibles par AWS)
SSM Session Manager = accès SSH sans port 22 ni clé SSH, via IAM. Audit dans CloudTrail.

🌍 Edge Location Services

Route 53

  • DNS public (ou privé via Private Hosted Zones) + routing avancé
  • Types de routing : latency, failover, geoproximity, geolocalisation, weighted, multivalue
  • Alias = record Route 53 → ressource AWS sans IP (ex: load balancer)
  • ⚠️ Pas de CNAME pour la zone apex (example.com) → utiliser A/AAAA Alias
  • Health Checks : surveillance des endpoints pour le failover
  • Route 53 ne collecte pas de logs par défaut → activer Route 53 Query Logging → CloudWatch (pas S3)

CloudFront

  • CDN (cache avec TTL) + protection bypass URL S3 (OAC)
  • OAC (Origin Access Control) : remplace OAI, protège S3 en autorisant uniquement CloudFront comme principal
  • Lambda@Edge : pour authentification des users avant accès (viewer request event)
  • ⚠️ CloudFront Function ≠ Lambda@Edge (CF Function = moins de capabilities)
  • Geo-restriction : bloquer des pays (aussi possible avec WAF)
  • Certificates HTTPS : sur us-east-1 (North Virginia) pour CloudFront

🚨 Disaster Recovery

  • RPO = Recovery Point Objective : temps d'interruption entre la dernière sauvegarde et le début de la panne (perte de données max)
  • RTO = Recovery Time Objective : délai entre le début de la panne et le retour à l'état fonctionnel
StratégieRTORPOCoûtPrincipe
Backup & RestoreHeuresHeures💰Backups réguliers, restore en cas de panne
Pilot LightMinutesMinutes💰💰Environnement dupliqué éteint, bascule via DNS
Warm StandbySecondesSecondes💰💰💰Environnement dupliqué allumé mais inutilisé
Multi-Site Active/ActiveQuasi zéroQuasi zéro💰💰💰💰Redondance totale, trafic distribué
  • Multi-AZ = HA (haute disponibilité, même région)
  • Cross-région = DR (disaster recovery)
  • AWS Backup : centralisation, automatisation, chiffrement, cross-account
  • AWS DRS (Disaster Recovery Service) : réplication bloc continue on-prem → AWS + recovery orchestration automatique
  • Fault Tolerance : continuité no matter what (≠ HA = reprise après incident)
  • Pas de single point of failure : régions multiples, Multi-AZ, réplication
  • Application Recovery Controller (ARC) : multi-region failover via Route 53
  • ⚠️ La région est un single point of failure si un seul AZ utilisé

📊 Data & Analytics

Données en mouvement

  • Kinesis Data Streams : streaming temps réel, gérer soi-même les consommateurs, 24h rétention (max 365j), replay possible
  • Kinesis Data Firehose : service managé de transport vers S3/Redshift/ES (pas de replay) ; TLS chiffrement en transit par défaut
  • Kinesis vs Firehose : Streams = traitement temps réel custom ; Firehose = ingestion managée vers destination
  • MSK (Managed Streaming for Kafka) : Kafka managé AWS

Données au repos

  • Athena : requêtes SQL directement sur S3 (serverless, TLS en transit par défaut)
  • Redshift : data warehouse colonne pour analytics à grande échelle
  • Glue : ETL managé + Data Catalog
  • EMR : Hadoop/Spark managé pour big data
  • Lake Formation : gouvernance du Data Lake, accès granulaire aux données

HPC (High Performance Computing)

  • Cluster Placement Group : instances très proches (même rack), latence ultra-basse
  • Enhanced Networking : SR-IOV, jusqu'à 100 Gbps
  • EFA (Elastic Fabric Adapter) : réseau HPC, bypass OS pour MPI/HPC workloads
  • FSx for Lustre : système de fichiers HPC haute performance, intégré S3
  • AWS Parallel Cluster : cluster HPC automatisé

Machine Learning

  • SageMaker : plateforme ML complète (formation, déploiement, monitoring)
  • Rekognition : reconnaissance d'image/vidéo
  • Textract : extraction de texte depuis documents
  • Comprehend : NLP, analyse de sentiment
  • Bedrock : accès aux modèles fondamentaux (FM) via API

🔀 Divers — À ne pas confondre

Pricing & Instances

  • On-Demand : prix à la seconde, flexible, sans engagement
  • Reserved Instances : engagement 1 ou 3 ans, jusqu'à 72% d'économie
  • Savings Plans : engagement en $/heure pendant 1 ou 3 ans (Compute ou EC2)
  • Spot Instances : jusqu'à 90% moins cher, peuvent être interrompues avec 2 min préavis
  • Dedicated Hosts : serveur physique dédié (compliance, licences par socket)
  • Dedicated Instances : instances sur matériel dédié (mais pas le serveur entier)
  • Capacity Reservations : réserver de la capacité dans une AZ spécifique

Stockage avancé

  • EFS : système de fichiers NFS managé, multi-AZ, élastique
  • FSx for Windows : partage SMB avec Active Directory
  • FSx for Lustre : HPC, intégré S3
  • Storage Gateway : hybride on-prem ↔ AWS (File/Volume/Tape)
  • S3 Transfer Acceleration : accélération upload via CloudFront Edge Locations
