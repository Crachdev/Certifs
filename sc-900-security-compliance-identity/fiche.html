Concepts de sécurité

Domaine 1 · 10–15%

Triade CIA

  • Confidentialité — seules les personnes autorisées accèdent aux données
  • Intégrité — données exactes et non altérées
  • Disponibilité — systèmes accessibles quand nécessaire

Modèles de sécurité

  • Zero Trust — ne jamais faire confiance, toujours vérifier
  • Défense en profondeur — couches de sécurité multiples
  • Moindre privilège — accès minimum nécessaire
Authentification (AuthN)
Prouver qui vous êtes — vérification d'identité
Autorisation (AuthZ)
Prouver ce que vous pouvez faire — vérification des droits
Chiffrement symétrique
Même clé pour chiffrer/déchiffrer — rapide (AES)
Chiffrement asymétrique
Clé publique/privée — sécurisé (RSA, TLS)
Hachage
Fonction unidirectionnelle — intégrité des données (SHA-256)

Zero Trust — Piliers

  • Vérifier explicitement (toujours)
  • Moindre privilège
  • Supposer une violation

Types de menaces

  • Phishing / Spear phishing
  • Ransomware / Malware
  • Attaque DDoS
  • Insider threat

SIEM / SOAR

  • SIEM = collecte + analyse logs
  • SOAR = automatisation réponse
  • XDR = détection étendue

Identité et gestion des accès

Domaine 2 · 25–30%
L'identité est le nouveau périmètre de sécurité dans le cloud. Avec le modèle Zero Trust, l'identité vérifiée remplace le périmètre réseau traditionnel.
Identité fédérée
SSO entre organisations — trust entre fournisseurs d'identité (ex : SAML, OIDC)
MFA (Authentification multifacteur)
Quelque chose que vous savez + avez + êtes
SSO (Single Sign-On)
Une seule connexion pour plusieurs applications
Passwordless
Windows Hello, FIDO2, Microsoft Authenticator (sans mot de passe)
Conditional Access
Politiques : si (user+device+location) alors (allow/block/MFA)
TypeDescriptionExemple
Facteur de connaissanceCe que vous savezMot de passe, PIN
Facteur de possessionCe que vous avezTéléphone, clé FIDO2
Facteur d'inhérenceCe que vous êtesEmpreinte, Face ID
03

Microsoft Entra ID

Domaine 2 · 25–30%

Microsoft Entra ID (anciennement Azure Active Directory) est le service cloud d'identité et d'accès de Microsoft.

Tenant (Locataire)
Instance dédiée Entra ID pour une organisation
Objets Entra
Users, Groupes, Devices, Applications, Service Principals
Editions
Free · P1 (Conditional Access) · P2 (PIM, Identity Protection)
Hybrid Identity
Entra Connect synchronise AD on-prem → Entra ID cloud
External Identities
B2B (partenaires) + B2C (clients) dans Entra
RBAC
Role-Based Access Control — rôles intégrés Azure (Owner, Contributor, Reader)

Active Directory (on-prem)

  • Domaine Windows local
  • Protocoles : Kerberos, LDAP
  • GPO, OU, Domain Controllers
  • Géré par l'entreprise

Entra ID (cloud)

  • Service cloud Microsoft
  • Protocoles : OAuth 2.0, OIDC, SAML
  • Conditional Access, PIM, MFA
  • Géré par Microsoft (SaaS)
04

Authentification Entra

Conditional Access

  • Signal : user, device, location, app, risk
  • Décision : allow, block, require MFA
  • Requiert Entra P1 minimum

Identity Protection

  • Risk policies (sign-in risk, user risk)
  • Détection d'anomalies automatique
  • Requiert Entra P2

PIM (Privileged Identity Management)

  • Accès privilégiés juste-à-temps (JIT)
  • Activation temporaire de rôles
  • Requiert Entra P2
SSPR (Self-Service Password Reset)
Réinitialisation autonome sans IT — inclut Entra P1/P2
Microsoft Authenticator
MFA push, TOTP, passwordless — app mobile Microsoft
FIDO2
Clés de sécurité physiques (YubiKey) — plus haut niveau de sécurité passwordless
Windows Hello for Business
Biométrie/PIN lié au device pour remplacer le mot de passe

Microsoft Sentinel — SIEM & SOAR

Domaine 3 · 35–40%

Microsoft Sentinel est un SIEM cloud-natif et une plateforme SOAR basée sur Azure Log Analytics.

Collecte de données

  • Connecteurs natifs Microsoft
  • Connecteurs partenaires (CEF/Syslog)
  • API REST custom
  • Azure Monitor / Log Analytics

Détection

  • Règles analytiques (KQL)
  • Threat Intelligence intégrée
  • Anomalies comportementales (UEBA)
  • Fusion ML pour incidents complexes

Réponse (SOAR)

  • Playbooks = Azure Logic Apps
  • Automatisation des réponses
  • Tickets, notifications, blocage IP
  • Orchestration multi-outils
Workbooks
Tableaux de bord visuels interactifs pour les données Sentinel
KQL (Kusto Query Language)
Langage de requête pour analyser les logs dans Sentinel / Log Analytics
UEBA
User Entity Behavioral Analytics — détecte comportements anormaux
Threat Intelligence
IOCs, feeds TAXII/STIX intégrés pour enrichir les alertes

Protection des données

Domaine 4 · 20–25%

Chiffrement au repos

  • Azure Storage Service Encryption
  • Transparent Data Encryption (SQL)
  • Disk Encryption (BitLocker/DM-Crypt)
  • Clés gérées Microsoft ou client (CMK)

Chiffrement en transit

  • TLS 1.2+ pour toutes les communications
  • HTTPS obligatoire
  • VPN / ExpressRoute
  • Perfect Forward Secrecy
Azure Key Vault
Stockage sécurisé de secrets, clés, certificats. HSM disponible.
Customer-Managed Keys (CMK)
L'organisation contrôle ses propres clés de chiffrement dans Key Vault
Double Key Encryption
Microsoft + client key → Microsoft ne peut jamais déchiffrer seul (M365)
Azure Confidential Computing
TEE (Trusted Execution Environment) — données chiffrées même pendant le traitement

Microsoft Purview

Domaine 4 · 20–25%

Microsoft Purview est la suite de conformité et gouvernance des données Microsoft (anciennement Microsoft 365 Compliance + Azure Purview).

Sensitivity Labels
Étiquettes de classification (Public, Confidential…) — chiffrement + marquage
DLP (Data Loss Prevention)
Empêche partage accidentel de données sensibles (email, Teams, SharePoint)
Information Protection
Classifie, étiquète et protège les données où qu'elles soient
Insider Risk Management
Détecte comportements à risque internes (fuites, fraude)
Communication Compliance
Surveille communications pour violations politiques (financier, harcèlement)
eDiscovery
Recherche légale et collecte de preuves numériques
Audit (Standard & Premium)
Journaux d'audit 90j (standard) ou 1 an (premium) pour investigation
Data Map / Catalog
Inventaire et classification automatique des données multi-cloud
Retention Labels vs Sensitivity Labels : Retention = contrôle durée de vie (garder/supprimer). Sensitivity = contrôle accès et protection (chiffrement, marquage).

12

Pièges fréquents à l'examen

Entra ID ≠ Active Directory on-prem : Entra ID = cloud, OAuth/OIDC/SAML. AD = local, Kerberos/LDAP. Entra Connect synchronise entre les deux mais ce sont des services distincts.
  • MFA requiert Entra Free, Conditional Access requiert Entra P1 ou P2
  • PIM (juste-à-temps) et Identity Protection requièrent Entra P2
  • Defender for Cloud ≠ Defender XDR — Cloud = posture Azure, XDR = investigation incidents
  • Sentinel = SIEM cloud-natif Microsoft basé sur Azure Log Analytics
  • Playbooks Sentinel = Azure Logic Apps (orchestration no-code)
  • Sensitivity Labels = protection contenu · Retention Labels = durée de vie
  • DLP empêche le partage non autorisé de données sensibles (pas un outil de chiffrement)
  • CASB = Cloud Access Security Broker = Defender for Cloud Apps
  • Zero Trust = "Never trust, always verify" + moindre privilège + supposer violation
  • AuthN = authentification (qui) · AuthZ = autorisation (quoi)
  • Key Vault stocke secrets, clés ET certificats
  • Compliance Manager = score conformité personnalisé · Service Trust Portal = preuves publiques Microsoft
    • Mnémotechnique CIA : Confidentialité · Intégrité · Disponibilité (Availability). Triade fondamentale de la sécurité de l'information.
