Guide officiel CLF-C02

☁️ CONCEPTS CLOUD (24 %)

  • 6 avantages du cloud (formulation AWS, à reconnaître mot pour mot) :

    • Remplacer les dépenses d'investissement (CapEx) par des dépenses variables (OpEx)

    • Profiter d'économies d'échelle massives (AWS achète en volume → prix plus bas pour tous)

    • Arrêter de deviner la capacité (plus de sur- ou sous-dimensionnement)

    • Gagner en vitesse et agilité (ressources en minutes, pas en semaines)

    • Arrêter de payer pour faire tourner des datacenters

    • Devenir mondial en quelques minutes

  • Vocabulaire :

    • Élasticité = s'ajuster automatiquement à la demande, à la hausse ET à la baisse (→ Auto Scaling)

    • Scalabilité = capacité à grandir (verticale : plus grosse machine / horizontale : plus de machines)

    • Haute disponibilité = le service reste accessible malgré une panne (→ plusieurs AZ)

    • Tolérance aux pannes = aucune interruption du tout, même pendant la panne

    • Agilité = expérimenter vite et pas cher

  • Modèles de déploiement : Cloud (100 % AWS) · Hybride (on-prem + AWS reliés) · On-premises / cloud privé

  • Modèles de service : IaaS = EC2 (tu gères l'OS) · PaaS = Elastic Beanstalk (tu gères le code) · SaaS = logiciel fini (tu l'utilises)

🏛 Well-Architected Framework (6 piliers)

Pilier

Mots-clés qui le trahissent dans une question

Excellence opérationnelle

automatiser, IaC, petites modifications fréquentes et réversibles, anticiper les échecs, runbooks

Sécurité

moindre privilège, traçabilité, chiffrement, sécuriser toutes les couches

Fiabilité

reprise automatique après panne, scaler horizontalement, tester la reprise, arrêter de deviner la capacité

Efficacité des performances

bon type de ressource, serverless, déploiement mondial, expérimenter souvent

Optimisation des coûts

payer à l'usage, mesurer, dimensionnement approprié, supprimer l'inutilisé

Durabilité

réduire l'impact environnemental, maximiser l'utilisation, instances efficaces (Graviton)

  • ⚠️ Fiabilité (se remettre d'une panne) ≠ Efficacité des performances (utiliser les ressources au mieux). Piège classique.

  • ⚠️ Durabilité est un pilier (environnement). Rien à voir avec la durabilité S3 (11 neuf = ne pas perdre les données).

  • ℹ️ AWS Well-Architected Tool : outil gratuit dans la console pour évaluer une charge de travail contre les 6 piliers.

🧭 Cloud Adoption Framework (AWS CAF)

  • 6 perspectives, en 2 groupes :

    • Côté métier : Business · People (personnes) · Governance

    • Côté technique : Platform · Security · Operations

  • 4 résultats métier attendus : réduire le risque métier · améliorer la performance ESG · augmenter les revenus · augmenter l'efficacité opérationnelle

  • ⚠️ Formation, culture, changement organisationnel = perspective People. Budget, risques, portefeuille de projets = Governance.

💶 Économie du cloud

  • Coûts fixes (on-prem : serveurs achetés d'avance) → coûts variables (cloud : payés à l'usage)

  • Coûts on-prem souvent oubliés (TCO) : électricité, refroidissement, locaux, sécurité physique, personnel, renouvellement du matériel

  • Licences : BYOL (Bring Your Own License = on réutilise ses licences existantes) vs licence incluse (payée dans le prix horaire)

  • Dimensionnement approprié (right-sizing) = choisir la plus petite ressource qui tient la charge

  • Automatisation = moins d'erreurs humaines, reproductible, plus rapide

  • ℹ️ Migration Evaluator : construit le business case (estimation du TCO) avant de migrer

🌍 INFRASTRUCTURE MONDIALE

  • Région = zone géographique (ex. eu-west-3 Paris) composée de plusieurs AZ (3 minimum pour les nouvelles régions)

    • Choisir une région selon 4 critères : conformité / souveraineté des données · latence (proximité des utilisateurs) · services disponibles · prix

    • ⚠️ Si la question parle de loi, de données qui ne doivent pas quitter un pays → c'est le critère conformité qui prime

  • Zone de disponibilité (AZ) = un ou plusieurs datacenters avec alimentation, réseau et refroidissement indépendants

    • Les AZ sont physiquement séparées (kilomètres) mais reliées par un réseau à très faible latence

    • ⚠️ Les AZ ne partagent aucun point de défaillance unique → répartir sur plusieurs AZ = haute disponibilité

  • Emplacements périphériques (edge locations / points de présence) = bien plus nombreux que les régions, près des utilisateurs

    • Servent à : CloudFront (cache), Route 53 (DNS), Global Accelerator, Shield / WAF, Lambda@Edge

    • ℹ️ Avantage : faible latence pour les utilisateurs finaux du monde entier

  • Local Zones = extension d'une région au plus près d'une grande ville → latence de quelques millisecondes

  • Wavelength Zones = infrastructure AWS dans les réseaux 5G des opérateurs télécoms

  • AWS Outposts = baies de serveurs AWS installées dans ton propre datacenter (hybride, latence locale, données sur site)

🤝 RESPONSABILITÉ PARTAGÉE

Le thème le plus tombé du domaine Sécurité : AWS sécurise le cloud, le client sécurise ce qu'il met dans le cloud.

  • AWS = sécurité DU cloud : datacenters (sécurité physique), matériel, réseau mondial, hyperviseur (virtualisation), et l'OS des services managés

  • Client = sécurité DANS le cloud : ses données, IAM (qui accède à quoi), OS invité d'EC2 et ses correctifs, applications, security groups, choix du chiffrement

  • Contrôles partagés : gestion des correctifs (AWS : infra / client : OS invité et applis) · gestion de configuration · sensibilisation et formation (chacun forme ses équipes)

  • Contrôles hérités : le client hérite des contrôles physiques et environnementaux d'AWS

Plus le service est managé, plus AWS en prend en charge :

  • ⚠️ Le chiffrement : AWS fournit l'outil, mais c'est le client qui décide de l'activer et de gérer ses clés

  • ⚠️ Les security groups et NACL sont toujours configurés par le client

  • ℹ️ Destruction sécurisée des disques en fin de vie = AWS

🪪 IAM &amp; IDENTITÉS

  • IAM = service global et gratuit : qui (authentification) peut faire quoi (autorisation)

  • Par défaut tout est refusé · un refus explicite (Deny) l'emporte toujours sur une autorisation (Allow)

  • Principe du moindre privilège = donner uniquement les droits nécessaires, rien de plus

👑 Utilisateur racine (root)

  • Créé avec l'e-mail du compte, accès total, impossible à restreindre par une policy IAM

  • Protéger le root : MFA activée · pas de clés d'accès · ne jamais l'utiliser au quotidien · créer un user admin à la place

  • Tâches réservées au root (à reconnaître) :

    • Modifier les paramètres du compte (e-mail, nom, mot de passe root)

    • Fermer le compte AWS

    • Changer ou annuler le plan AWS Support

    • Restaurer les droits d'un admin IAM qui s'est bloqué lui-même

    • S'inscrire comme vendeur sur la Reserved Instance Marketplace

    • Activer MFA Delete sur un bucket S3

🔐 Authentification

  • MFA = mot de passe + un 2e facteur (appli d'authentification, clé physique FIDO, token matériel)

  • Politique de mots de passe = longueur, complexité, rotation, réutilisation interdite

  • Clés d'accès (Access Key ID + Secret) = accès programmatique (CLI, SDK, API) · à faire tourner régulièrement

  • IAM Identity Center (ex-AWS SSO) = une seule connexion pour plusieurs comptes AWS et applis métier

  • Fédération = utiliser des identités existantes (Active Directory, Google, SAML 2.0) sans créer de users IAM

  • Rôle inter-comptes = un user du compte A endosse un rôle dans le compte B

🛡 SÉCURITÉ &amp; CONFORMITÉ

🧱 Protéger

  • Shield = protection DDoS

    • Standard : gratuit, automatique pour tous, couches réseau 3 et 4

    • Advanced : payant, couche applicative en plus, équipe de réponse DDoS 24/7, protection des coûts (remboursement des surcoûts dus à une attaque)

  • WAF = pare-feu applicatif web (couche 7) : bloque injection SQL, XSS, IP ou pays, limite le nombre de requêtes

    • Se branche sur CloudFront, Application Load Balancer, API Gateway, AppSync

  • Firewall Manager = gérer centralement les règles WAF, Shield et security groups sur tous les comptes d'une organisation

🔑 Chiffrer

  • Au repos (données stockées) : S3, EBS, RDS… via KMS

  • En transit (données qui circulent) : TLS/SSL, certificats via ACM

  • KMS = créer et gérer des clés de chiffrement, intégré à presque tous les services, matériel géré par AWS

  • CloudHSM = un module matériel dédié (HSM) : toi seul contrôles les clés, AWS n'y a pas accès

  • ACM (Certificate Manager) = certificats SSL/TLS publics gratuits avec renouvellement automatique

  • ⚠️ « Contrôle exclusif des clés » ou « matériel dédié » → CloudHSM. Sinon → KMS.

📜 Prouver la conformité

  • AWS Artifact = portail pour télécharger les rapports de conformité d'AWS (SOC, ISO, PCI DSS) et accepter des accords (ex. BAA pour HIPAA)

  • AWS Audit Manager = évalue ton usage d'AWS en continu et collecte les preuves pour tes audits

  • ⚠️ Artifact = la conformité d'AWS · Audit Manager = la conformité de ton usage · Config = l'état de tes ressources face à des règles

  • Les exigences varient selon le pays (RGPD) et le secteur (HIPAA santé, PCI DSS paiement) : tous les services ne sont pas couverts par chaque programme de conformité

🧰 Autres

  • AWS RAM (Resource Access Manager) = partager des ressources (sous-réseaux, Transit Gateway…) entre comptes

  • AWS Marketplace = on y trouve des produits de sécurité tiers (pare-feux, antivirus…)

  • Sources d'info sécurité : AWS Security Center, AWS Security Blog, AWS Knowledge Center, AWS re:Post

  • Trusted Advisor a aussi des contrôles de sécurité (MFA sur root, ports ouverts, buckets publics)

🏢 Gouvernance multi-comptes

  • AWS Organizations = regrouper plusieurs comptes AWS

    • Facturation consolidée : une seule facture + remises sur volume cumulées + partage des instances réservées

    • SCP (Service Control Policies) = limites maximales de ce qu'un compte peut faire (même le root du compte membre)

    • OU (Organizational Units) = dossiers de comptes (Prod, Dev…)

  • AWS Control Tower = mettre en place automatiquement un environnement multi-comptes sécurisé (« landing zone ») avec des garde-fous

  • AWS Service Catalog = catalogue de produits pré-approuvés que les équipes peuvent déployer elles-mêmes

  • AWS License Manager = suivre et limiter l'usage des licences logicielles (Microsoft, Oracle…)

  • Service Quotas = voir et demander l'augmentation des limites de service

  • AWS Health Dashboard = état des services AWS

    • Vue générale : santé de tous les services, toutes régions

    • Vue personnalisée : événements qui touchent tes ressources (maintenance planifiée, panne locale) + API AWS Health

💾 STOCKAGE

  • 3 types de stockage :

    • Objet = fichiers + métadonnées dans des « buckets », accès via HTTP → S3

    • Bloc = disque dur attaché à une machine → EBS, stockage d'instance

    • Fichier = dossier partagé réseau entre plusieurs machines → EFS, FSx

♾️ S3

  • Stockage objet illimité, objets jusqu'à 5 To, nom de bucket unique au monde, service régional

  • Durabilité 99,999999999 % (« 11 neuf ») = on ne perd quasiment jamais un objet · la disponibilité (accès), elle, varie selon la classe

  • Fonctions à connaître : versioning (garder les anciennes versions, protège des suppressions) · Block Public Access · hébergement de site web statique · réplication entre régions · Transfer Acceleration (envoi rapide via les edge locations)

  • AWS Elastic Disaster Recovery = réplication continue de serveurs vers AWS pour redémarrer en quelques minutes en cas de sinistre

🌎 Services de périphérie

  • Route 53 = DNS managé + achat de noms de domaine + health checks + routage intelligent :

    • Simple · Pondéré (weighted : 90 % / 10 %) · Latence (région la plus rapide) · Basculement (failover vers un site de secours) · Géolocalisation (selon le pays de l'utilisateur) · Géoproximité

  • CloudFront = CDN : met en cache le contenu (images, vidéos, site) dans les edge locations, proche des utilisateurs

  • API Gateway = créer, publier, sécuriser et limiter des API (souvent devant Lambda)
