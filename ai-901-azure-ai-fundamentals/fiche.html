IA Responsable — 6 principes Microsoft

Domaine 1 · ~15% de l'examen

Microsoft définit 6 principes pour concevoir et déployer une IA de confiance. Mémorise l'acronyme F·R·P·I·T·A.

PrincipeEn quoi ça consisteExemple concret
Fairness (Équité)Traiter tous les groupes sans discriminationModèle de crédit qui n'avantage pas un genre
Reliability & Safety (Fiabilité)Fonctionner de façon sûre même dans des cas inattendusVoiture autonome qui s'arrête correctement
Privacy & Security (Confidentialité)Protéger les données personnellesNe pas stocker des données médicales sans consentement
Inclusiveness (Inclusivité)Bénéficier à tous, y compris les personnes marginaliséesSous-titrage automatique pour les malentendants
Transparency (Transparence)Expliquer comment le système prend ses décisionsIndiquer qu'un chatbot est un robot
Accountability (Responsabilité)Des personnes sont responsables des décisions IAComité d'éthique IA dans une entreprise
Piège examen : Il y a exactement 6 principes — pas 5, pas 7. L'examen peut proposer des formulations proches ; repère bien les 6 noms exacts.
Azure AI Content Safety
Filtre automatique : violence, haine, autoagression, contenu sexuel — 4 catégories sur une échelle 0–7
Responsible AI Dashboard
Dans Azure ML : Fairness, erreurs du modèle, interpretabilité (SHAP values), analyse contrefactuelle
Differential Privacy
Ajoute du bruit statistique calculé pour protéger les données individuelles tout en conservant les tendances globales
Model Cards
Documentation standardisée d'un modèle : objectif, limites, biais connus, métriques de performance
Mnémotechnique : F·R·P·I·T·A → Fairness · Reliability · Privacy · Inclusiveness · Transparency · Accountability
02

Modèles IA — Composants & configurations

Domaine 1 · ~12% de l'examen

Comment fonctionnent les modèles génératifs (LLM)

Architecture Transformer

  • Mécanisme d'attention
  • Traitement parallèle des tokens
  • Encoder (comprendre) + Decoder (générer)
  • Base de GPT-4, Llama, Mistral…

Tokens

  • Unité minimale de traitement
  • ≈ ¾ d'un mot anglais
  • Limite contexte = window size
  • Coût API basé sur nb de tokens

Embeddings

  • Représentation vectorielle du texte
  • Capturent le sens sémantique
  • Permettent recherche par similarité
  • Modèle : text-embedding-3

Choisir le bon modèle

BesoinModèle recommandéNotes
Génération de texte avancéeGPT-4o, GPT-4.1Multimodal (texte + images)
Génération légère / rapideGPT-4o mini, Phi-4Coût réduit
Génération d'imagesDALL-E 3, gpt-image-1Prompt → image
Transcription vocaleWhisperSpeech-to-text open source
Embeddings vectorielstext-embedding-3-small/largePour RAG / recherche
Modèles open-sourceLlama 3, Mistral, PhiCatalog Foundry

Paramètres de déploiement clés

Temperature (0–2)
0 = déterministe/reproductible · 1+ = créatif/varié. Utilise 0 pour du code, 0.7–1 pour de la créativité.
Max tokens
Limite la longueur de la réponse générée (tokens de sortie).
Top-p (nucleus sampling)
Ne considère que les tokens dont la probabilité cumulée atteint p. Alternatif à temperature.
Frequency penalty
Réduit la répétition de tokens déjà fréquemment utilisés dans la réponse.
Presence penalty
Encourage l'introduction de nouveaux sujets / réduit les redites de concepts.
Stop sequences
Tokens qui déclenchent l'arrêt de la génération (ex : "\n\n", "###").
Fine-tuning vs RAG : Le fine-tuning modifie les poids du modèle (long, coûteux, permanent). Le RAG injecte des documents dans le contexte au moment de la requête (flexible, sans réentraînement).

Charges de travail IA

Domaine 1 · ~15% de l'examen
IA générative IA agentique Analyse de texte Reconnaissance vocale Vision par ordinateur Extraction d'informations

IA générative

  • Crée du nouveau contenu (texte, images, code)
  • Basée sur LLMs (GPT-4o, Llama…)
  • Réponse à des prompts en langage naturel
  • Résumé, traduction, génération de code

IA agentique

  • Agent = LLM + outils + mémoire + planification
  • Exécute des actions autonomes (appels API, recherche…)
  • Peut décomposer des tâches complexes
  • Multi-agents : agents spécialisés qui collaborent

Analyse de texte (NLP)

  • Extraction de mots-clés : termes importants
  • Détection d'entités (NER) : personnes, lieux, organisations
  • Analyse de sentiment : positif / négatif / neutre
  • Synthèse : résumé extractif ou abstractif

Reconnaissance vocale

  • Speech-to-Text (STT) : voix → texte
  • Text-to-Speech (TTS) : texte → voix synthétique
  • Traduction vocale : parole d'une langue → texte d'une autre
  • Speaker recognition : identifier qui parle

Vision par ordinateur

  • Classification d'images : que représente cette image ?
  • Détection d'objets : où sont les objets + bounding boxes
  • OCR : extraire du texte d'une image
  • Génération d'images : DALL-E 3, gpt-image-1
  • Modèles multimodaux : comprendre texte + image

Extraction d'informations

  • Depuis documents & formulaires (PDFs, factures)
  • Depuis images (photos, captures)
  • Depuis audio (réunions, appels)
  • Depuis vidéos (meetings, formations)
  • Outil Azure : Content Understanding

Microsoft Foundry — Le portail

Domaine 2 · cœur de l'examen (55–60%)
Azure AI Foundry (anciennement Azure AI Studio) est le hub unifié pour explorer, déployer et gérer les solutions IA sur Azure. L'examen AI-901 teste désormais principalement les compétences Foundry.
Catalogue de modèles
Bibliothèque de modèles : Azure OpenAI (GPT-4o, DALL-E…), modèles open-source (Llama 3, Mistral, Phi-4), modèles partenaires
Playground Chat
Interface pour tester des modèles en direct, ajuster les paramètres (temperature, max tokens…) et itérer sur les prompts système
Playground Images
Générer des images avec DALL-E 3 ou gpt-image-1 directement dans le portail
Foundry Tools
Suite d'outils intégrés : Azure Speech, Azure Vision, Content Understanding, Language — accessibles sans quitter Foundry
Agent Builder
Créer, configurer et tester des agents IA (single-agent) avec tools, instructions et évaluations
Évaluations
Mesurer la qualité des réponses d'un modèle ou d'un agent avec des métriques intégrées (pertinence, cohérence, fluidité…)
Fine-tuning
Adapter un modèle de base sur tes propres données JSONL, directement depuis le portail
Connexions
Connecter des ressources Azure (Azure AI Search, Storage, Cosmos DB…) au projet Foundry

Hiérarchie Foundry

Hub Foundry (niveau organisation) └── Projet Foundry (niveau équipe / application) ├── Déploiements de modèles (endpoints) ├── Connexions (Azure AI Search, Storage…) ├── Foundry Tools (Speech, Vision, Language…) └── Agents
Hub vs Projet : Le Hub est le conteneur racine partagé par plusieurs projets. Le Projet est l'espace de travail d'une équipe ou application. Les déploiements de modèles et les agents sont créés dans un Projet.
05

Apps & agents génératifs avec Foundry

Domaine 2 · ~20% de l'examen

Déployer un modèle dans Foundry

  1. Ouvrir le Catalogue de modèles dans le portail Foundry
  2. Sélectionner le modèle (ex : GPT-4o) et cliquer sur Deploy
  3. Choisir le type : Standard (serverless, pay-per-token) ou Provisioned (throughput garanti)
  4. Nommer le déploiement → il devient accessible via l'endpoint du projet
  5. Tester dans le Playground avant d'intégrer dans une app

Écrire des prompts efficaces

Prompt système

  • Définit le rôle et comportement de l'assistant
  • Invisible pour l'utilisateur final
  • Exemple : "Tu es un assistant juridique. Réponds toujours en français. Ne donne pas de conseils médicaux."
  • Doit être précis, sans ambiguïté

Prompt utilisateur

  • Message de l'utilisateur dans le tour de conversation
  • Peut contenir : contexte, exemples few-shot, données
  • Techniques : zero-shot, one-shot, few-shot, chain-of-thought
  • Grounding : inclure des faits ou documents pour ancrer la réponse

Créer un agent dans Foundry

Instructions (system prompt)
Définit le comportement, les limites, le ton et le rôle de l'agent
Tools (outils)
Fonctions que l'agent peut appeler : recherche web, exécution de code, appels d'API, Azure AI Search…
Mémoire / Thread
Chaque conversation (thread) garde l'historique des échanges pour maintenir le contexte
Évaluation
Tester les réponses de l'agent avec des jeux de données de test et des métriques automatisées
Agent = LLM + outils + mémoire. L'agent reçoit un objectif, planifie ses étapes, appelle ses outils (recherche, code, API), analyse les résultats et génère une réponse finale.

SDK Foundry — Applications Python légères

Domaine 2 · ~15% de l'examen

L'examen teste la capacité à créer des applications clientes légères avec le SDK Azure AI Foundry (package azure-ai-projects).

Structure d'une app de chat basique

from azure.ai.projects import AIProjectClient from azure.identity import DefaultAzureCredential # Connexion au projet Foundry client = AIProjectClient( endpoint="https://<hub>.services.ai.azure.com/api/projects/<project>", credential=DefaultAzureCredential() ) # Appel chat completion response = client.inference.chat_completions.create( model="gpt-4o", # nom du déploiement messages=[ {"role": "system", "content": "Tu es un assistant utile."}, {"role": "user", "content": "Explique le RAG en 3 lignes."} ], temperature=0.7, max_tokens=256 ) print(response.choices[0].message.content)

Client pour un agent

from azure.ai.projects.models import AgentThread, MessageRole # Créer un thread (conversation) thread = client.agents.create_thread() # Ajouter un message utilisateur client.agents.create_message( thread_id=thread.id, role=MessageRole.USER, content="Cherche les dernières nouvelles sur l'IA générative." ) # Lancer l'agent (run) run = client.agents.create_and_process_run( thread_id=thread.id, agent_id="asst_xxxx" # ID de l'agent créé dans Foundry ) # Lire la réponse messages = client.agents.list_messages(thread_id=thread.id) print(messages.data[0].content[0].text.value)
Authentification : L'examen attend DefaultAzureCredential (Entra ID) et non une API key hardcodée. En local : az login suffit. En production : identité managée de la ressource Azure.
AIProjectClient
Client principal — accès à inference, agents, tools, connections
client.inference
Chat completions, embeddings, image generation depuis le projet
client.agents
Créer/gérer des agents, threads, messages, runs
client.connections
Accéder aux connexions configurées (Azure AI Search, Storage…)

Texte & parole avec Foundry

Domaine 2 · ~10% de l'examen

Azure AI Language — Analyse de texte

Analyse de sentiment
Score positif / négatif / neutre par phrase et par document. Renvoie un score de confiance (0–1).
Extraction d'entités (NER)
Identifie : Personne, Organisation, Lieu, Date, Quantité, URL… dans le texte.
Extraction de mots-clés
Renvoie les termes les plus représentatifs du document.
Résumé (Summarization)
Extractif (phrases du document) ou Abstractif (reformulé) — disponible pour textes et conversations.
Détection de langue
Identifie la langue du texte avec un score de confiance.
Traduction (Translator)
Service séparé : traduction dans 100+ langues, translitération, dictionnaire bilingue.
Dans Foundry : Accéder à Language via Foundry Tools → Language. Tester directement dans le portail ou appeler l'API depuis le SDK avec client.language.

Azure AI Speech

Speech-to-Text (STT)

  • Transcription en temps réel ou par batch
  • Supporte 100+ langues et accents
  • Custom Speech : adapter à un vocabulaire spécifique
  • Résultats : texte brut + mots avec timestamps

Text-to-Speech (TTS)

  • Neural voices : voix naturelles et expressives
  • Custom Voice : créer une voix de marque
  • SSML : contrôler rythme, pauses, emphase
  • Format de sortie : WAV, MP3, OGG

Répondre à des invites vocales avec un modèle multimodal

import azure.cognitiveservices.speech as speechsdk # STT : microphone → texte speech_config = speechsdk.SpeechConfig(subscription=KEY, region=REGION) recognizer = speechsdk.SpeechRecognizer(speech_config=speech_config) result = recognizer.recognize_once() # texte reconnu user_text = result.text # → envoyer user_text à GPT-4o (via SDK Foundry) # → récupérer la réponse texte # TTS : texte → voix synthesizer = speechsdk.SpeechSynthesizer(speech_config=speech_config) synthesizer.speak_text_async(response_text)

Extraction d'informations — Content Understanding

Domaine 2 · ~10% de l'examen
Azure Content Understanding est le service Foundry qui extrait des informations structurées depuis des sources multimodales : documents, images, audio et vidéo. C'est l'évolution d'Azure Document Intelligence (Form Recognizer).
SourceCe qu'on extraitCas d'usage
Documents & formulairesChamps structurés (nom, montant, date), tableaux, signatures, cases cochéesFactures, contrats, formulaires fiscaux, bons de commande
ImagesTexte (OCR), objets, données visuelles, schémasCartes de visite, étiquettes produits, photos de terrain
AudioTranscription, identification des locuteurs, résumé, sujets clésRéunions, appels clients, interviews
VidéosTranscription, chapitrage automatique, détection d'événements visuelsFormations, webinaires, surveillance

Modèles prédéfinis vs modèles personnalisés

Modèles prédéfinis (prebuilt)

  • Prêts à l'emploi, sans entraînement
  • Facture, reçu, carte d'identité, carte de visite
  • Formulaire général (layout model)
  • Résultats immédiatement disponibles

Modèles personnalisés (custom)

  • Entraîner sur tes propres documents
  • Minimum 5 exemples labellisés
  • Champs spécifiques à ton métier
  • Compose plusieurs modèles ensemble
from azure.ai.documentintelligence import DocumentIntelligenceClient # Analyser une facture avec le modèle prédéfini client_di = DocumentIntelligenceClient(endpoint=ENDPOINT, credential=cred) poller = client_di.begin_analyze_document( model_id="prebuilt-invoice", body={"urlSource": "https://example.com/invoice.pdf"} ) result = poller.result() invoice = result.documents[0] print(invoice.fields["VendorName"].content) # Nom du fournisseur print(invoice.fields["TotalTax"].content) # Montant TVA

Prompt Engineering

TechniqueDescriptionQuand l'utiliser
Zero-shotAucun exemple dans le promptTâches simples, modèles très capables
One-shotUn seul exemple fourniQuand le format de réponse doit être précis
Few-shot2–10 exemples input → outputTâches complexes, format inhabituel
Chain-of-Thought"Réfléchis étape par étape"Raisonnement mathématique, logique complexe
System promptRôle et instructions permanentesToutes les apps — définir le comportement de base
GroundingInclure des faits/documents dans le promptRéduire les hallucinations, répondre sur une base factuelle
ReActRaisonnement + Action en boucleAgents qui utilisent des outils
Hallucination : Le modèle génère des informations fausses mais convaincantes. Solutions : RAG (ajouter des sources réelles), grounding, temperature basse, demander au modèle de citer ses sources.
Prompt injection : Un utilisateur malveillant insère des instructions dans son message pour détourner le comportement de l'assistant. Mitigation : valider les entrées, utiliser un système de modération, Content Safety.

RAG & Recherche vectorielle

RAG (Retrieval-Augmented Generation)
Combine recherche documentaire + LLM. Les documents pertinents sont injectés dans le prompt pour ancrer la réponse dans des faits réels.
Azure AI Search
Service de recherche hybride (texte classique + vecteurs). Indexe des documents et les rend accessibles au modèle LLM. Clé du RAG sur Azure.
Vecteurs (embeddings)
Chaque chunk de document est converti en vecteur numérique. La recherche trouve les N documents les plus proches (cosine similarity).
Semantic Ranker
Couche de reclassement dans Azure AI Search qui utilise un modèle de langage pour améliorer la pertinence des résultats.

Architecture RAG étape par étape

  1. Indexation : découper les documents en chunks → générer un embedding par chunk → stocker dans Azure AI Search
  2. Requête utilisateur : convertir la question en embedding avec le même modèle
  3. Recherche vectorielle : trouver les K chunks les plus similaires (similarité cosinus)
  4. Augmentation : injecter les chunks récupérés dans le prompt comme contexte
  5. Génération : le LLM génère une réponse fondée sur le contexte injecté
RAG vs Fine-tuning : RAG = ajouter de la connaissance au runtime (flexible, pas de réentraînement). Fine-tuning = modifier les poids (long, coûteux, pour des styles/formats, pas pour des faits récents).

⚠ Différence clé : L'examen AI-901 (avril 2026) n'est PAS AI-900. Les domaines ont complètement changé. 55–60% porte sur Microsoft Foundry — pas sur Azure ML classique.

  • Hallucination → corriger avec RAG + grounding + sources vérifiées.
  • Prompt injection → risque de sécurité, mitiger avec Content Safety.
  • Hub Foundry = niveau organisation. Projet Foundry = niveau app / équipe.
