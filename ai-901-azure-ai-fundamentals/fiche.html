Workloads et concepts IA

Domaine 1 · 15–20%

L'IA englobe des sous-disciplines complémentaires. Comprendre leurs différences est fondamental pour l'examen.

Intelligence Artificielle

  • Simuler l'intelligence humaine
  • Prendre des décisions automatiques
  • Englobe ML, vision, NLP

Machine Learning

  • Apprendre à partir de données
  • Amélioration continue avec l'expérience
  • Sous-ensemble de l'IA

Deep Learning

  • Réseaux de neurones profonds
  • Nécessite gros volumes de données
  • Excellents en vision/NLP
Types de workloads IA : Prédiction/Régression · Classification · Clustering · Détection d'anomalies · Computer Vision · NLP · IA générative
02

Machine Learning fondamental

Domaine 2 · 20–25%

Apprentissage supervisé

  • Données étiquetées
  • Classification (labels discrets)
  • Régression (valeurs continues)
  • Ex : spam filter, prédiction prix

Apprentissage non supervisé

  • Données non étiquetées
  • Clustering (regroupement)
  • Réduction de dimensionnalité
  • Ex : segmentation clients

Apprentissage par renforcement

  • Agent · Environnement · Récompense
  • Apprend par essai/erreur
  • Ex : jeux, robotique

Transfer Learning

  • Réutilise un modèle pré-entraîné
  • Fine-tuning sur nouvelles données
  • Réduit temps et coût d'entraînement

05

IA Générative

Domaine 4 · 35–40%

L'IA générative crée du nouveau contenu (texte, images, code, audio). Elle repose sur des Large Language Models (LLMs).

LLMs — Bases

  • Transformer architecture
  • Pré-entraînés sur vastes corpus
  • Prédiction du token suivant
  • Température = créativité

Types de contenu généré

  • Texte (GPT-4, GPT-4o)
  • Images (DALL-E 3)
  • Code (GPT-4, Codex)
  • Audio / Vidéo

Tokens

  • Unité de traitement LLM
  • ≈ ¾ d'un mot anglais
  • Limite de contexte = fenêtre tokens
  • Coût API basé sur tokens
Embeddings : Représentation vectorielle numérique du texte qui capture le sens sémantique. Permettent la recherche de similarité et le RAG.

Azure OpenAI Service

Domaine 4 · 35–40%

Modèles disponibles

  • GPT-4 / GPT-4o (texte)
  • GPT-4 Vision (images + texte)
  • DALL-E 3 (génération d'images)
  • text-embedding-ada-002
  • Whisper (transcription)

API Chat Completions

  • Messages : system / user / assistant
  • Temperature (0=déterministe)
  • Max tokens
  • Top-p, frequency/presence penalty

Fine-tuning

  • Adapte GPT à un style/domaine
  • Données : JSONL (prompt/completion)
  • Réduit le prompt engineering
  • Modèle déployé = endpoint privé
Déploiement : Azure OpenAI n'est pas automatiquement disponible — il faut demander l'accès. Les modèles sont déployés dans une ressource Azure OpenAI, pas directement via l'API OpenAI publique.
09

Responsible AI

Microsoft définit 6 principes pour une IA responsable :

  • Fairness (Équité) : Les systèmes IA doivent traiter tous les groupes équitablement, sans discrimination.
  • Reliability & Safety (Fiabilité) : Fonctionnement sûr et fiable dans toutes les conditions.
  • Privacy & Security (Confidentialité) : Protection des données personnelles et sécurité des systèmes.
  • Inclusiveness (Inclusivité) : L'IA doit bénéficier à tous et ne laisser personne de côté.
  • Transparency (Transparence) : Compréhension du fonctionnement des systèmes IA.
  • Accountability (Responsabilité) : Les personnes et organisations sont responsables des systèmes IA.
    • Biais IA : Les modèles peuvent hériter des biais présents dans les données d'entraînement. Tools Azure : Fairlearn, Responsible AI Dashboard, Azure AI Content Safety.
    Azure AI Content Safety
    Filtre contenu nuisible : violence, haine, autoagression, contenu sexuel
    Interpretability
    SHAP values, LIME → comprendre pourquoi un modèle fait une prédiction
    Differential Privacy
    Ajoute du bruit statistique pour protéger les données individuelles

    RAG et Copilots

    RAG (Retrieval-Augmented Generation)
    Combine recherche documentaire + LLM → réponses fondées sur des sources réelles
    Azure AI Search
    Indexation vectorielle + sémantique pour le RAG. Connecte documents → LLM
    Azure AI Foundry
    Hub pour créer des applications IA de bout en bout (anciennement Azure AI Studio)
    Microsoft Copilot Studio
    Créer des copilotes personnalisés sans code (ancien Power Virtual Agents)
    Semantic Kernel
    SDK open-source pour orchestration d'agents IA (C#, Python, Java)

    Architecture RAG

    • 1. Indexer documents → vecteurs
    • 2. Question utilisateur → embedding
    • 3. Recherche similarité (cosine)
    • 4. Top-K docs → contexte LLM
    • 5. LLM génère réponse grounded

    Copilot Extensions

    • Microsoft 365 Copilot
    • GitHub Copilot
    • Power Platform Copilot
    • Azure Copilot
    • Extensions plugins/connectors

    Pièges fréquents à l'examen

    Azure AI Foundry vs Azure ML Studio : AI Foundry = modèles génératifs, LLMs, Azure OpenAI. Azure ML Studio = ML classique, AutoML, Designer, entraînement de modèles custom.
  • CLU remplace LUIS pour la compréhension du langage conversationnel
  • Document Intelligence = Form Recognizer (renommé)
  • Custom Vision nécessite min. 15 images par classe
  • Responsible AI = 6 principes (pas 5, pas 7)
  • Temperature 0 = déterministe, temperature 1+ = créatif
  • Fine-tuning ≠ RAG : fine-tuning modifie les poids, RAG ajoute du contexte au runtime
  • Embeddings = vecteurs numériques de sens sémantique
  • Overfitting : bonne perf train, mauvaise perf test → régulariser
  • Underfitting : mauvaise perf partout → modèle trop simple
  • Azure OpenAI nécessite une approbation d'accès (pas ouvert par défaut)
    • Mnémotechnique Responsible AI : F-R-P-I-T-A → Fairness · Reliability · Privacy · Inclusiveness · Transparency · Accountability
