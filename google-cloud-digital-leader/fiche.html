Transformation digitale avec Google Cloud

☁️ Section 1 · ~18%

Concepts cloud fondamentaux

Cloud computingLivraison de ressources informatiques (calcul, stockage, réseau, IA) via Internet, à la demande, avec facturation à l'usage.
IA agentiqueAgents IA autonomes capables de planifier et exécuter des tâches complexes en plusieurs étapes. Différenciateur clé de Google Cloud 2025–2026.
Open source / open standardEngagement Google pour éviter le vendor lock-in : Kubernetes, TensorFlow, Apache Kafka, etc.

Architectures cloud

ArchitectureDescriptionUsage
Cloud privéInfrastructure dédiée à une organisationConformité réglementaire stricte
Cloud hybrideOn-premises + cloud public connectésMigration progressive, données sensibles
Multi-cloudPlusieurs fournisseurs cloudÉviter le vendor lock-in, résilience
Cloud publicInfrastructure Google partagéeScalabilité maximale, coût optimisé

Bénéfices du cloud Google

Business

  • Scalabilité élastique
  • Réduction des coûts (CapEx → OpEx)
  • Agilité et rapidité de mise sur le marché
  • Focus stratégique (vs. gestion IT)

Technique

  • Haute disponibilité mondiale
  • Sécurité intégrée (secure by design)
  • Réseau backbone mondial (edge locations)
  • Accès aux données en temps réel

Différenciateurs GCP

  • AI Hypercomputer (GPU/TPU)
  • Gemini (IA générative)
  • Ouverture : Kubernetes, Anthos
  • Réseau mondial Google (le plus rapide)

Rôle des données

Base de donnéesStockage structuré, transactions ACID, requêtes SQL. Ex : Cloud SQL, Spanner, AlloyDB.
Data warehouseDonnées historiques agrégées pour l'analytique et le reporting. Ex : BigQuery.

Moderniser l'infrastructure et les applications

🏗️ Section 4 · ~18%

Stratégies de migration — les 6 R

StratégieDescription
Rehost (Lift & Shift)Déplacer la VM telle quelle sur GCP. Rapide, sans modification.
ReplatformMigration + quelques optimisations cloud (ex : BDD managée). Sans réécriture.
RefactorRéécriture pour exploiter pleinement le cloud (microservices, conteneurs).
ReimagineRepenser complètement l'application avec une architecture cloud-native.
RetireSupprimer les applications obsolètes. Réduire les coûts.
RetainGarder on-premises pour l'instant (conformité, dépendances).

Options de calcul GCP

Compute Engine

  • VMs IaaS sur GCP
  • Contrôle total de l'OS
  • Spot VMs (préemptibles, -90% coût)
  • Autoscaling, load balancing

Google Kubernetes Engine

  • Kubernetes managé
  • Orchestration de conteneurs
  • Autopilot ou Standard
  • Multi-cloud avec Anthos/GKE Enterprise

Cloud Run

  • Conteneurs serverless
  • Scale-to-zero automatique
  • Pay-per-request
  • Idéal microservices HTTP

Cloud Run Functions

  • Fonctions serverless (event-driven)
  • Anciennement Cloud Functions
  • Déclencheurs : HTTP, Pub/Sub, Cloud Storage
💡 APIs avec Apigee Apigee API Management : gérer, sécuriser et monétiser des APIs publiques. Gateway entre clients et services backend. Idéal pour exposer des APIs à des partenaires ou au marché.

Confiance et Sécurité avec Google Cloud

🔒 Section 5 · ~18%

Menaces courantes

Menaces externes

  • DDoS (attaques volumétriques)
  • Ransomware (chiffrement + rançon)
  • Phishing (usurpation d'identité)
  • Malware / cryptomining

Menaces internes

  • Mauvaise configuration (misconfiguration)
  • Tiers non sécurisés (supply chain)
  • Attaques LLM (injection de prompt)
  • Dommages physiques

Principes de sécurité

Zero TrustNe jamais faire confiance, toujours vérifier. Chaque accès est authentifié et autorisé, même sur le réseau interne.
Moindre privilègeAccorder uniquement les droits minimum nécessaires (IAM sur GCP).
Chiffrement3 états : au repos (at rest), en transit (in transit), en utilisation (in use / Confidential Computing).
DLPData Loss Prevention : détecter et protéger les données sensibles. Sensitive Data Protection sur GCP.

Produits sécurité GCP

ServiceRôle
Security Command CenterTableau de bord centralisé de posture de sécurité GCP. Détecte les misconfigrations et menaces.
Google Threat IntelligenceRenseignement sur les menaces (Mandiant + VirusTotal). Contexte sur les attaquants.
Google Security Operations (SecOps)SIEM/SOAR pour détecter, investiguer et répondre aux incidents de sécurité.
Cloud ArmorProtection DDoS et WAF (Web Application Firewall).
IAMIdentity and Access Management. Contrôle qui peut faire quoi sur quelles ressources GCP.
Sensitive Data ProtectionDécouverte et masquage des données sensibles (ex-DLP API).
Cloud VPN / Cloud InterconnectConnexion sécurisée on-premises ↔ GCP. VPN via Internet, Interconnect via fibre dédiée.
Identity-Aware Proxy (IAP)Contrôle d'accès aux apps web sans VPN. Zero Trust pour les applications.

Opérations cloud & Gestion des coûts

⚙️ Section 6 · ~10%

Contrôle des coûts GCP

CapEx → OpExLe cloud remplace l'investissement initial (CapEx) par des dépenses opérationnelles à l'usage (OpEx). TCO = Total Cost of Ownership.
Hiérarchie ressourcesOrganisation → Dossiers → Projets → Ressources. Les budgets et politiques s'appliquent à chaque niveau.
Spot VMsVMs préemptibles jusqu'à 91% moins chères. Peuvent être arrêtées par Google à tout moment. Pour workloads tolérants aux interruptions.
Quota policiesLimites d'utilisation des ressources pour éviter les dépenses imprévues.
Budget alertsAlertes automatiques quand les dépenses approchent d'un seuil défini. Pas un hard cap par défaut.

Observabilité et fiabilité

Cloud Monitoring

  • Métriques en temps réel
  • Dashboards personnalisés
  • Alertes sur seuils

Cloud Logging

  • Centralisation des logs
  • Rétention configurable
  • Intégration avec Security Operations

SRE & DevOps

  • SLI : indicateur (ex : latence)
  • SLO : objectif (ex : 99,9%)
  • SLA : accord contractuel
  • Error budget : tolérance d'erreurs

Pièges classiques

  • BigQuery ≠ base de données : c'est un data warehouse analytique. Ne pas l'utiliser pour des transactions OLTP (utiliser Cloud SQL ou Spanner).
  • Cloud Storage classes : Standard = accès fréquent | Nearline = 1x/mois | Coldline = 1x/90 jours | Archive = 1x/an. Accès plus rare = stockage moins cher mais lecture plus chère.
  • Spot VMs peuvent être arrêtées à tout moment : ne pas utiliser pour des workloads critiques ou avec état non sauvegardé.
  • Cloud Run ≠ GKE : Cloud Run est serverless (containers HTTP), GKE est un cluster Kubernetes managé (plus de contrôle, plus complexe).
  • Interconnect vs VPN : Cloud Interconnect = fibre dédiée (haute performance, coûteux). Cloud VPN = chiffré via Internet (moins cher, moins fiable).
  • IAM ≠ Identity-Aware Proxy : IAM contrôle l'accès aux ressources GCP. IAP contrôle l'accès aux applications web via un proxy Zero Trust.
  • IA Générative ≠ ML classique : le ML classique prédit une valeur. L'IA générative CRÉE du contenu nouveau (texte, image, code).
  • Rehost ≠ Refactor : Rehost = déplacer sans modifier. Refactor = réécrire pour le cloud. L'examen distingue soigneusement les 6 R de migration.
  • SLO ≠ SLA : SLO = objectif interne. SLA = engagement contractuel avec le client (seuil plus bas que le SLO). Error budget = 100% - SLO.
